## 통합 과정에서 발견한 생성기 문제

[#1598](https://github.com/kimjooyoon/meta-ontology-go/pull/1598)의 원본 CI에서
`expectedBoundarySpecsForVersion`이 76줄이 되어 기존 75줄 한도를 넘었다.
버전별 기준값을 계속 하나의 `switch`에 추가하던 구조가 원인이었다.

등록 생성기는 이제 선언된 과거 버전·기준값 쌍을 읽고, 최대 24개씩 작은 함수로 나눈다.
현재 버전의 기본값과 과거 릴리스 조건은 유지한다. 중복 버전, 순환 연결, 잘못된 함수 서명,
주인 없는 보조 함수는 수정 후보를 만들기 전에 거부한다. 줄바꿈은 구문으로 읽는다.

현재 소스의 기준값 27개가 유지됐고, 기존 선언은 13줄, 가장 큰 분할 함수는 55줄이 됐다.
새 가상 추가 53단계에서 126개 기준값의 보존과 함수 크기를 관측했다.
현재 Gooo 등록 경로에서도 새 가상 사례 하나가 기존 9개 산출물 역할을 유지하는지 확인했다.
이 검사는 등록 후보 생성에 관한 관측이며, 기존 프로그램이나 모델을 다시 실행하지 않았다.

### 이전 통합 PR의 종료 결과

#1598의 원본 워크플로 51개는 모두 종료됐으며 47개가 성공하고 4개가 실패했다.
단위·동시성·의미 검사와 별도 투영·호환성 검사는 같은 선언 크기 문제를 보고했다.
동시성 검사의 최상위 실패도 해당 크기 검사 하나였으며 데이터 경합은 보고되지 않았다.

정책 작업에는 별개의 전송 실패가 있었다. GitHub의 산출물 생성 요청이
`ETIMEDOUT`으로 끝났고, 이후 provenance 산출물이 없어 결과 수집과 proof가 실패했다.
전송 실패를 소스 오류로 집계하거나 누락된 결과를 성공으로 대체하지 않는다.
후속 PR은 수정된 소스로 원래 검사를 거쳐야 한다.

[종료 관측](observations/pr-resolution/pr1598-terminal.json)에 실행·작업 번호와 실패 원인을 기록했다.
