# 문법 후보의 기원과 보관 범위

Gooo는 `source_fill` 안에서 빈자리마다 허용하는 식의 문법과 보관 수를 정한다.
작은 결정 모델이나 호출 프로그램은 그 소스가 만든 후보 ID를 읽고, 그중 하나의
기원을 조회할 수 있다. 조회 단계에서는 후보를 선택해 적용하지 않는다.

| 조회 | 보고서와 입력 | 기원의 위치 |
| --- | --- | --- |
| `--fill-candidates` | 후보 ID·선언 순서의 대입·계획 해시·문법 범위 | 소스가 보관한 후보 집합 |
| 직접 선언 후보의 `--fill-candidate` | 기존 v1·15개 원시 입력 필드 | 후보·식·빈자리 선언과 본문 사용 |
| 문법 후보의 `--fill-candidate` | 문법 기원 보고서·19개 원시 입력 필드 | 문법·빈자리 선언과 본문 사용 |

문법 후보의 보고서는 직접 선언된 식이나 후보의 위치를 만들지 않는다. 생성된
식은 보관 집합의 대입으로 남기고, `grammar_source`는 원본 파일의 문법 선언을
가리킨다. 한글·이스케이프가 포함된 파일에서도 원본 바이트와 디코딩한 본문
좌표를 나누어 보관한다. 모든 바이트 범위의 끝은 포함하지 않는다.

## 완전성을 읽는 기준

예제는 두 문법의 2개·3개 식을 조합한다. 조합 공간은 6개이며 소스의 상한에
따라 4개를 보관하고 2개를 생략한다. `candidate_generation`의 문법·조합 분모는
기존 소스 생성기가 계산한 값이다. 문법 공간의 보관 비율과 기능 사례의 정답률을
섞지 않는다. 기능 점수는 원래 생성·실행 기록에서 따로 읽는다.

조회 대상 ID는 보관된 집합에 있어야 한다. 집합 밖의 조회 실패는 그 후보의
기능 실패를 뜻하지 않는다. 빈자리의 실제 토큰이 없거나 반복되면 사용 좌표를
만들지 않고 `TEMPLATE_HOLE_NOT_UNIQUE`를 남긴다. 문법의 위치는 계속 보관한다.

## Gooo 소비자

[예제](../../examples/derived-candidate-origins/README.md)의 명령으로 원시 행을
전달하면 `inspect.gooo`가 `origin_kind`, 문법 범위와 사용 여부를 조건식으로
분류한다. 입력 전용 실행에는 기대값이 없으므로 `finite_total=0`이다. 위치 자료의
전달·분류 관찰은 후보의 기능 평가와 분모가 다르다.

CLI는 후보 목록을 출력할 때 명령을 섞지 않는다. 단일 ID 조회에서만 입력을
내보내며, 32KiB를 넘으면 생략하지 않고 오류를 낸다. 기존 `--field`와
`--include-control`은 일반 타입 기원 조회에 사용한다.
