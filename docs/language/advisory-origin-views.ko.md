# 출처를 보는 방식은 보조 힌트로 다루기

원본 출처 그래프는 하나로 두고 에이전트와 사람이 필요한 부분을 골라 읽습니다.
예를 들어 에이전트는 안정 ID와 바이트 위치를 받고, 사람은 자신이 자주 쓰는
입력 이름부터 볼 수 있습니다. 표시 선택은 프로그램의 의미를 바꾸는 권한을 갖지
않습니다.

이 문서는 개발 소스의 `body-view`, `view-lens` 입구를 설명합니다.
공개 릴리스에 포함됐는지는 해당 릴리스 안내에서 확인합니다.

## 도메인의 경계

| 기록 | 소유하는 내용 | 실패했을 때 |
| --- | --- | --- |
| 원래 Gooo 프로그램과 출처 보고서 | 계산·타입·안정 ID·소스 좌표 | 기존 소스 진단과 상태를 유지합니다. |
| 보기 힌트 | 보려는 추상화, 사용자 범위, 이전 선택 횟수 | 힌트를 무시하고 기본 보기를 사용합니다. |
| 선택 사건과 프로필 | 어떤 소스에서 어떤 보기를 골랐는지 | 저장 문제를 별도 결과로 반환합니다. |

컴파일·코드 생성·실행 명령은 보기 프로필을 자동으로 읽지 않습니다.
`body-view`는 원본 출처 보고서가 만들어진 뒤, 전달받은 작은 JSON 힌트로 보기를
고릅니다. 힌트 문법 오류·다른 사용자·미지원 보기에는 진단 코드가 붙습니다.
이 오류가 원본의 성공을 실패로 바꾸지 않습니다. Gooo 프로그램 자체의 문법 오류는
원래의 소스 오류로 남습니다.

내장 선택 규칙은 [policy.gooo](../../internal/meta/originlenspolicy/policy.gooo)의
`SelectLens`, `SelectionReason`, `LensAvailable` 세 활동에 있습니다.
이 파일은 컴파일러 개발 소스로 검사하고 Go 투영을 생성합니다. 사용자가 전달하는
힌트는 실행 가능한 Gooo 프로그램으로 해석하지 않습니다. 내장 라이브러리의 CI와
런타임 힌트의 비치명적 처리를 각각의 경계에서 다룹니다.

## 에이전트의 사용 순서

먼저 인터페이스를 읽습니다.

```sh
gooo body-view --capabilities
gooo body-view --activity Difference examples/named-inputs/main.gooo
```

기본 출력은 `gooo/body-view/v1` JSON입니다.

- `canonical`: 기존 타입 값 출처 보고서 전체.
- `projection.canonical_pointer`: `#/canonical`. 그래프를 다시 복사하지 않습니다.
- `projection.input_refs`: 이름 보기에서 `canonical.inputs`를 가리키는 정수 인덱스.
- `selection`: 보기 ID·선택 이유·정책 출처·힌트 진단.
- `next_operations`: 별도 저장 등에 쓸 명령 인수와 값의 JSON 포인터.

이 보고서는 소스의 가능한 의존 관계를 읽습니다. 실제 실행에서 어느 분기가
통과했는지는 실행 기록의 별도 범위입니다.

프로필이 필요하면 호스트가 표시 작업 밖에서 미리 읽습니다.

```sh
gooo view-lens load --actor kimjooyoon --audience person
```

반환된 `hint` 객체만 JSON 문자열로 직렬화해서 `body-view --hint`에 넘깁니다.
힌트 상한은 4,096바이트입니다. 표시 과정에서 설정 파일·저장 잠금·대기 큐·시계·
네트워크·모델을 사용하지 않습니다. 내장 정책 바이트의 해시 검사와 선택 계산,
보고서 직렬화 비용은 있습니다. 추가 CPU 비용이 0이라는 의미는 아닙니다.

사람에게 입력 이름부터 보여주고 싶다면 다음처럼 요청합니다.

```sh
gooo body-view --activity Difference --actor kimjooyoon --audience person \
  --prefer inputs --format text examples/named-inputs/main.gooo
```

JSON의 `record_event`는 저장할 수 있는 제안입니다. 자동 저장은 하지 않습니다.
호스트는 응답을 전달한 뒤 다음 작업으로 저장할 수 있습니다.

```sh
gooo view-lens record --event '<record_event 객체의 JSON>'
```

CLI 안에서 종료될 수 있는 백그라운드 쓰기를 시작하지 않습니다. 호스트가 별도
작업의 실행·재시도·보관을 맡습니다. 저장을 생략해도 프로그램은 동작합니다.

## 선택을 기억하는 범위

프로필은 보기 도메인 + `actor` + `audience`에 묶입니다.
각 사용자와 에이전트에 서로 다른 불투명한 actor 값을 주는 것은 호스트의 일입니다.
기본 actor `agent`를 모든 사람에게 공유하면 같은 프로필을 사용하게 됩니다.

1. 유효한 `--view`가 현재 요청을 정합니다.
2. `--prefer`로 고정한 보기가 있으면 사용합니다. `--prefer auto`는 고정을 해제합니다.
3. 고정이 없으면 더 많이 선택한 보기를 사용합니다.
4. 동률이면 에이전트는 전체 출처, 사람은 입력 이름을 기본으로 사용합니다.

선택 횟수는 저장된 요청의 횟수입니다. 사용자가 실제로 읽었는지, 만족했는지,
어떤 의도를 가졌는지에 대한 추론으로 사용하지 않습니다. 선택 기록은 대상 활동 ID,
원문 소스 해시, 선택 이유와 내장 정책의 소스·투영 해시를 갖습니다. 사용자 이름을
PROV Agent의 검증된 신원으로 승격하지 않습니다.

저장은 현재 프로필의 해시와 revision을 확인합니다. 낡은 힌트는
`PROFILE_SNAPSHOT_STALE`, 다른 쓰기가 잠금을 잡고 있으면 `PROFILE_BUSY`입니다.
잠금 재시도를 기다리지 않습니다. 마지막으로 수용한 사건의 재전송은
`ALREADY_RECORDED`이며 횟수를 늘리지 않습니다. 더 이전 사건의 재전송은 낡은
스냅샷으로 거부될 수 있습니다. 호스트가 이 결과를 보고 다음 작업을 정합니다.

## 원본을 잃지 않고 저장하기

저장 위치는 기본 사용자 설정의 `gooo/view-lenses`이며 `--state-dir`로 지정할 수
있습니다. 프로필은 횟수와 최근 32개 선택의 작은 요약입니다. 수용한 사건 전체와
프로필의 각 버전은 해시 이름의 별도 아카이브에 보관합니다. 최근 요약에서 빠진
기록도 아카이브에 남고, 이전 프로필 해시의 원래 바이트를 찾을 수 있습니다.

`originpack`은 원래 저장 바이트의 크기·SHA-256·인코딩을 고정 헤더에 담습니다.
gzip이 줄여 줄 때만 압축하며, 복원 크기 상한은 한 객체당 128KiB입니다.
원본 해시와 압축 파일 해시는 서로 다른 대상을 가리킵니다. JSON 정규화나 소스
재포맷을 바이트 비손실 압축이라고 부르지 않습니다. 사건의 원본은 저장 연산이
생성한 canonical JSON 바이트입니다. 호출자가 넘긴 JSON의 공백까지 보관한다는
계약은 아닙니다. Gooo 원문은 별도의 원문 해시로 연결합니다.

```sh
gooo view-lens read --kind event --digest sha256:...
gooo view-lens read --kind profile --digest sha256:...
```

`RESTORED` 결과의 `raw_bytes_base64`를 디코딩하면 저장했던 원래 바이트입니다.
`raw_digest`로 확인합니다. 이 읽기는 과거 정책이 담긴 바이트도 복원하며 실행
권한이나 현재 프로필 변경 권한을 주지 않습니다.

사건·프로필 아카이브를 먼저 만들고 현재 프로필을 원자적 이름 변경으로 교체합니다.
파일 동기화는 수행하지만 전원 장애까지 포함한 트랜잭션·디렉터리 내구성은
현재 보장하지 않습니다. 중간 실패로 참조되지 않는 아카이브가 남을 수 있으며,
이를 성공한 선택 횟수로 세지 않습니다. 기존 바이트와 충돌하면 덮어쓰지 않습니다.

## 현재 메모리 배치와 다음 과제

표시 경로에는 최근 기록 배열 전체를 전달하지 않고 작은 Snapshot만 줍니다.
입력 이름 보기는 선언 구조체를 복제하는 대신 정수 참조 배열과 16칸 중복 확인
배열을 사용합니다. 현재 본문 매개변수 범위를 벗어난 보고서는 전체 보기로
돌아가며 원본을 잘라내지 않습니다. 압축 헤더의 해시는 32바이트로 보관하고
외부 인터페이스에서 문자열로 표현합니다.

작은 파일은 압축돼도 디스크 할당량이 같을 수 있습니다. 실제 할당량을 줄이려면
불변 기록을 블록으로 묶고 인덱스로 찾는 후속 작업이 필요합니다.
[성능 지표와 마일스톤](../research/origin-performance-milestones-20261016.md),
[단계별 관찰](../observations/advisory-origin-views/observations.json)에 현재 확인 범위와
측정하지 않은 부분을 기록합니다.
