# 값을 갱신하는 표현과 출처

Gooo에서 초기화한 정수 지역 변수에 `+=`, `-=`, `*=`, `/=`를 사용할 수 있습니다. 조건 분기 안에서도 같은 규칙을 적용합니다. [실제 프로그램](../../examples/compound-updates/main.gooo)과 [입력 예제](../../examples/compound-updates/README.md)를 함께 제공합니다.

`amount += change`는 직전 `amount`와 `change`를 읽고 새 `amount`를 만드는 작업입니다. Gooo는 이 관계를 타입과 경로 레시피, 원래 소스 위치, 실행 시점의 지역 변수 기록에 연결합니다. 단축 표기에서도 값의 기원이 이어집니다.

코드 생성 단계에서는 네 연산자를 기존 이항 연산과 할당 경로로 정규화합니다. Go 출력에는 작성한 갱신 표기를 보존합니다. 실제 실행에서는 이전 값을 읽은 뒤 새 값을 쓰는 순서를 관찰합니다.

작성한 프로그램의 새 입력 네 사례는 모두 맞았습니다. 각 실행의 쓰기와 읽기를 합쳐 16회씩 기록했고, 직전 값과 최종 반환값의 출처를 확인했습니다. 모델 호출은 0회였습니다. 이 수치는 해당 네 사례의 결과입니다.

초기화된 정수 지역 변수에 더해, 지역 레코드의 정수 필드에도 네 연산자를 사용할 수 있습니다. 문자열 필드에는 `+=`를 사용할 수 있습니다. 입력을 바꾸려면 `let result = 기록`으로 지역 복사본을 만든 뒤 갱신합니다.

[관찰 기록과 등록 출처](../observations/compound-updates/README.md)에 원래 실패한 입력 봉투와 새 입력의 실행을 구분해 보관했습니다. 언어 등록은 Gooo의 기존 등록 계약으로 아홉 산출물 역할을 생성해 수행했고, 과거 분모 파일은 보존했습니다.

## 필드 하나를 바꾸어도 기원은 이어지기

`result.count += delta`는 직전 `count`와 `delta`를 함께 사용합니다. `delta`가 입력의 `step`에서 왔다면, Gooo로 작성한 출처 판독기가 그 연결도 따라갑니다. 값을 복사하는 관계와 식을 계산하는 관계를 나누어 보관해, 수정하지 않은 필드에 다른 필드의 기원을 붙이지 않습니다.

실행 기록은 갱신 전 읽기, 오른쪽 식의 읽기, 완료된 쓰기 순서를 남깁니다. 필드 나눗셈의 분모가 실행 중 0이 되면 원래 연산의 위치와 두 값을 남기고 그 쓰기는 미완료 상태로 보존합니다. 오른쪽 식 안에서 먼저 실패한 나눗셈도 바깥 갱신과 구분합니다.

이 연결을 실제 Gooo 판독기로 읽는 과정에서 한글 입력 이름 `기록`이 연결 포트에 잘못 쓰이던 오류를 찾았습니다. 이름은 사람이 읽는 표기로, `input0` 같은 포트는 선언 순서의 연결 정체성으로 각각 보관하도록 수정했습니다. 표시 이름을 PROV 역할 ID로 자동 해석하지 않습니다.

새 레코드 사례 4개에서 16회의 갱신을 관찰했고, 별도 나눗셈 사례 5개에서 정상 2건과 오류 3건을 구분했습니다. 출처 판독은 저장된 실행을 입력으로 받아 생산자를 다시 실행하지 않았습니다. [사례별 기록](../observations/record-field-updates/observations.json)에 실패한 초안과 수정본을 함께 남깁니다.

현재 필드 관찰 범위는 필수 단일 정수·불리언·문자열로 구성된 평평한 레코드입니다. 지역 변수의 동적 0 나눗셈 관찰과 컬렉션 필드 확장은 별도로 남아 있습니다.
