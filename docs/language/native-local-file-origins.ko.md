# 지역 변수의 원래 패키지·파일 기원

Gooo 워크스페이스는 여러 패키지의 함수와 레코드 이름을 하나의 실행 그래프로 바꾼다.
지역 변수의 선언·대입·사용을 설명할 때에는 바뀐 이름의 위치와 처음 받은 파일의
위치를 구분해야 한다. 개발 소스의 `local-input-locations` 입력이 이 연결을 제공한다.

[실행 예제](../../examples/workspace-local-origins/README.md)는 새 기록을 만들고
Gooo 프로그램으로 그 기록의 원래 파일 위치를 설명한다.

## 행이 가리키는 것

| 필드 | 의미 |
| --- | --- |
| `event_kind`, `event_index` | 사례 안의 실제 대입 또는 사용과 그 순번 |
| `assignment_index` | 대입 자체의 번호 또는 사용이 연결된 대입. 미확정이면 -1 |
| `frame` | 함수가 호출된 회차 |
| `activity_id`, `root_activity_id` | 실행 그래프의 활동과 진입 활동 |
| `original_activity_id` | 원래 패키지에서의 활동 ID |
| `package_path`, `filename`, `source_sha256` | 워크스페이스에 제공한 파일 이름과 내용의 해시 |
| `source_start`, `source_end` | 원래 파일의 UTF-8 바이트 구간 `[start, end)` |
| `category`, `mapping`, `reason` | 연결한 관계의 종류, 위치 유무와 미확정 이유 |

사례별로 대입, 사용 순서로 읽는다. 각 사건에는 선언 위치와 대입값 또는 사용 위치가
붙는다. 조립한 부분은 후보·문법·템플릿 행이 추가된다. 같은 코드 위치가 여러 사건에서
반복될 수 있다. 변수 이름이나 실행값이 같다는 이유로 기원을 합치지 않는다.

원래 파일의 리터럴이 한글 변수를 `\uAE30\uC900`처럼 저장했다면 위치는 그 이스케이프
텍스트의 바이트를 가리킨다. `expression`에는 풀어 읽은 이름이 남는다. Go 투영 위치,
선택된 합성 Gooo 위치, 원래 파일 위치는 각각 다른 좌표다.

## 이름 변경과 조립

컴파일러는 함수 호출과 레코드 이름을 바꾼 구간을 기록하고 역순으로 되돌려 원본 위치를
계산한다. 경계가 바뀐 이름의 중간에 걸리거나 본문이 달라졌으면 미확정 이유를 남긴다.
이름 변환을 되돌리기 전에는 선택된 표현이 실제 템플릿 구간과 일치하는지도 확인한다.

조립한 식 전체를 템플릿의 구멍 위치에 붙이지 않는다. 그대로 둔 변수 선언·사용은
템플릿으로 되돌리고, 채운 식은 `declared_candidate` 또는 `derived_grammar`로 연결한다.
파생 문법에는 원래 후보 식이 없으므로 문법 선언의 범위를 남긴다. 조립 문맥의 범위는
관계된 식 전체를 포함할 수 있으며, 개별 사용 토큰의 정확한 위치와 구분한다.

같은 활동·선택 본문에 다른 조립 입력이 충돌하면 `AMBIGUOUS_ASSEMBLY_INPUT`으로 남긴다.
임의의 첫 입력을 원본으로 고르지 않는다.

## 저장과 범위

원래 파일 정보는 `runtime.local_file_sources`의 정적 코드 위치별 표에 저장한다.
반복 대입과 사용은 기존 위치 번호를 참조한다. 페이지를 고를 때도 정수 인덱스 배열을
한 번 만들어 사례 사이에서 공유하며 파일 텍스트를 사건마다 복사하지 않는다.
기존 지역 변수 위치 ID와 관찰 집계는 그대로 두고 별도 설명을 추가한다.

기록을 읽을 때는 표의 소스 연결·위치 번호·구간·상태를 검사한다. 이 검사는 저장된
관계를 해석하기 위한 것이며, 원래 실행을 다시 수행하지 않는다. 파일 정보가 없는
예전 기록에는 `ORIGINAL_FILE_ANNOTATION_ABSENT`가 남는다. 현재 소스로 새 입력을
실행하면 새 실행의 파일 정보가 생기며 과거 기록을 수정하지 않는다.

페이지는 최대 128행·입력 JSON 32KiB다. `local-input-locations`의 offset은
0..2147483647이다. 원래 대입·사용·함수 회차의 기록 한도와 `PARTIAL`은 유지된다.
모든 값의 최소 원인이나 언어 전체의 완전성을 뜻하는 지표로 확대하지 않는다.

[원래 입력·선택 소스·별도 실행과 관찰](../observations/workspace-local-file-origins/README.md)을
함께 읽으면 각 위치가 어떤 범위에서 확인됐는지 볼 수 있다.
