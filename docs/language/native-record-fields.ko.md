# 실행 경로에서 레코드 필드의 기원 잇기

소스 분석은 가능한 분기를 함께 보여 줍니다. 실행 기록은 이번 입력이
실제로 읽은 쓰기를 알려 줍니다. Gooo는 두 관점을 별도 데이터로 남깁니다.

필드 기록의 정체성은 다음처럼 구성됩니다.

| 정체성 | 역할 |
| --- | --- |
| 레코드·필드의 안정적 ID | 선언한 개념 |
| 루트 활동·활동·지역 변수 순번 | 어느 소스 바인딩인가 |
| 케이스·함수 프레임 | 어느 실행 인스턴스인가 |
| 쓰기 번호 | 어떤 쓰기인가 |
| 완료 순서·읽기 시점 | 그 읽기 전에 어떤 쓰기가 완료됐는가 |

레코드의 각 필드는 별도의 마지막 쓰기 슬롯을 가집니다. 복사할 때 슬롯도
값으로 복사합니다. 고정된 헬퍼의 레코드 인자는 관측용 Go 호출에서 부모
슬롯을 함께 전달하고, 헬퍼의 입력 바인딩은 이를 부모 쓰기로 기록합니다.
헬퍼가 지역 레코드를 반환하면 해당 필드 슬롯을 호출자의 대입과 잇습니다.
원래 프로그램의 입력과 반환값은 그대로 계산합니다.

레코드 생성식은 필드별 평가 창을 기록합니다. 전체 레코드 대입의 기원
슬롯은 오른쪽 평가가 모두 끝난 뒤 갱신합니다. 따라서
`item=Pair{left:item.right,right:item.left}`에서 두 번째 읽기도 갱신 전
왼쪽 필드를 가리킵니다. 평가 중 실패하면 새 슬롯을 완료 처리하지 않습니다.

중첩 호출에서는 바깥 대입의 기록을 먼저 예약한 뒤 안쪽 쓰기가 완료될 수
있습니다. 기록 배열의 순서와 완료 순서는 다릅니다. 별도의 완료 번호와
읽기 시계를 유지하여 미래 쓰기나 다른 필드를 참조하는 기록을 구분합니다.

## 저장 형식

네이티브 보조 파일은 `gooo/native-field-observation/v1`입니다.
쓰기는 9개의 32비트 정수, 읽기는 5개의 32비트 정수로 저장합니다.
상한은 쓰기 4,096개·읽기 65,536개·프레임 65,536개·케이스 128개입니다.
선언·표현식·필드 이름은 정적 지점 표에 두고, 실행 행에는 참조만 보관합니다.
새 필드 기록은 실제 값이나 문자열 본문을 저장하지 않습니다.

실행 결과에는 다음 자료가 포함됩니다.

- `field_bindings`, `field_sites`, `field_use_sites`
- 관측 전 Go 코드 지점의 `field_projection_sha256`
- 케이스별 `field_writes`, `field_uses`와 프레임·누락 수
- `gooo/native-field-summary/v1` 요약

요약은 직접 부모 연결, 루트 입력 바인딩, 공유된 오른쪽 평가 창,
미해결 부모, 미완료 쓰기, 누락량을 각각 셉니다. 이들을 하나의 언어 정답률로
합치지 않습니다. `COMPLETE`는 현재 필드 기록 프로필의 행과 참조가 모두
남아 있는 상태입니다. 의존성 해석의 범위는 `dependency_mode`와 미해결
수치를 함께 봅니다.

`field-writes`와 `field-uses` 조회는 저장된 행을 32개 원시 필드의 Gooo 입력
레코드로 전달합니다. 조회 중 원래 프로그램과 모델의 호출 수는 `0`입니다.
필드 기록이 없는 과거 자료는 필드 기원을 새로 만들어 표시하지 않습니다.
기존 스칼라 지역 변수와 컬렉션 기록은 각자의 형식과 상한을 유지합니다.

## 현재 경계

필수 단일 스칼라 필드가 대상입니다. 단순 지역 레코드 인자와 지역 레코드
반환은 필드별 부모 연결을 가집니다. 다른 형태는 공유 평가 창이나 미해결
부모로 남습니다. 스칼라 지역 변수 경유, 활동 사이의 레코드 전달,
복잡한 인자·반환 식, 선택·반복 필드까지 잇는 작업이 남아 있습니다.

관측용 코드가 만든 내부 함수의 반환은 Gooo 활동의 반환과 구분합니다.
큰 반복 실험에서 이 구분이 빠져 컴파일이 실패한 원본 시도를 보존했고,
다른 소스·입력의 후속 실험으로 수정된 경로를 확인했습니다.
