# 계산과 실행 자원 정리

Gooo의 생성 프로그램은 계산을 마친 뒤 실행 파일과 임시 작업 폴더를 정리합니다.
Windows 원래 CI에서 계산 기록과 두 자식 실행이 완료된 다음, 실행 파일 삭제가
공유 위반으로 실패한 사례가 나왔습니다. 원래 실행은 실패로 보존합니다.
파일 핸들을 누가 보유했는지는 해당 기록으로 확인되지 않습니다.

실패 지점은 PR #1615의 원래 실행 `38856672790`, Windows 잡 `116829579217`입니다.
결과물 `12027641357`의 `windows-amd64-record-english-inputs.failed-output`에
완료된 JSON 기록과 뒤따르는 정리 오류가 남아 있습니다.

## 소유권과 종료 순서

실행기는 새 작업을 취소하고, 기존 자식 실행이 반환한 뒤 직렬화 게이트를 되찾아
자신이 만든 폴더를 제거합니다. 이 순서를 유지합니다. 저장소 파일이나 다른 실행기의
폴더를 대신 지우는 경로는 추가하지 않습니다.

Windows의 공유 위반 32와 잠금 위반 33만 같은 소유 폴더의 삭제를 다시 시도합니다.
문자열 비교로 오류를 분류하지 않습니다. 다른 운영체제의 같은 숫자와 권한 오류는
즉시 반환합니다.

한 번의 정리 호출에서 초기 삭제 이후 최대 여섯 번 기다립니다. 간격은 10·20·40·80·160·320ms이고,
최대 일곱 번 삭제를 시도합니다. 예약한 대기 시간의 합은 630ms입니다. 각 파일시스템
호출의 소요 시간은 이 합과 구분합니다. 영구 오류와 끝까지 남은 잠금은 반환하며,
소유한 실행 결과물 참조는 삭제 성공 후에만 해제합니다.

정리 재시도는 계산이나 모델 호출을 다시 실행하지 않습니다. Go 호스트가 운영체제
자원의 수명 주기를 처리하고, Gooo 선언과 생성된 계산의 의미를 유지합니다.
기존 임시 해제 콜백의 영구 오류 처리는 최선형 동작으로 남아 있습니다. 이번 실패가
발생한 소유 실행기의 `Close` 경로는 오류를 호출자에게 반환합니다.

## 확인 범위

새 로컬 사례 9개가 삭제 횟수·대기 예산·게이트 소유권과 비 Windows 오류 구분을
확인했습니다. Windows 전용 CI에는 오류 분류 6개와 실제 파일 핸들을 열어 삭제를
막았다가 해제하는 사례 1개를 연결했습니다. 실제 Windows 확인과 원래 플랫폼
출시 사례 전체는 새 소스의 원래 CI에서 확인할 단계입니다.

기존 실패 실행을 재시작하거나 검사 사례를 제거하지 않았습니다. CI 전체 제한 시간도
유지합니다. 기존 Gooo 원본과 생성 파일, 등록 정보는 이 변경에서 유지합니다.
