# 반환값과 조립 선택의 기원

Gooo는 계산을 만든 선언과 그 선언이 허용한 선택을 함께 남기려 합니다.
예를 들어 집계 결과가 예상과 다르면, 결과의 숫자에 더해 어느 필드가 어떤
대안에서 만들어졌는지 따라갈 수 있어야 합니다.

## 반환식도 기록의 주체

다음 두 형태가 필드 관찰에 참여합니다.

```gooo
return Summary{total:input.offset+count,bytes:bytes,complete:count<=8}
```

```gooo
if input<0 {return Make(input)}
```

컴파일러는 자료형을 확인한 반환 구문에 `BodyReturns`를 붙입니다. 원래 식,
반환 순번·전체 수, 활동·레코드 ID와 선택된 소스 좌표를 보존합니다. 실행 시
생성자와 도우미 반환에 필드 쓰기를 기록하고, 도우미의 실제 반환 쓰기를 부모로
연결합니다. 이미 이름이 있는 지역 레코드의 반환은 기존 주체를 사용합니다.

관찰용 변수를 따로 작성하지 않아도 됩니다. 내부 표시 이름 `<return:N>`은
화면 표기이며, 활동 ID·반환 순번·레코드 ID가 연결의 기준입니다. 기록은 반환식을
평가한 뒤 완료된 쓰기 번호를 잡습니다. 평가 전에 번호를 복사하면 도우미 반환의
부모 연결이 이전 쓰기를 가리킬 수 있기 때문입니다.

옛 기록에 `BodyReturns`가 없으면 새 반환 주체를 소급해서 만들지 않습니다.
기존 필드·지역 변수 저널과 32개 원시 열의 형식도 유지합니다.

## 선택된 식에서 원래 대안으로

`assembling`의 필드 선택에는 별도의 `ChoiceOrigins`가 붙습니다. 여기에는 선택
ID, 첫째·둘째 대안, 필드 ID, 선택된 본문의 해시와 식 범위가 있습니다. 작업공간은
이를 원본 파일의 `choice` 선언과 `alternative` 문자열 범위에 연결합니다.

선택된 식에 추가되는 괄호와 앞선 치환의 길이 변화도 좌표 계산에 반영합니다.
따옴표로 감싼 본문의 이스케이프는 원본 파일의 바이트 범위와 해석된 식을 따로
다룹니다. 하나의 완성된 식에 원본 템플릿 위치가 없으면 그 행은 미해결로 남기고,
원래 대안의 위치를 별도 행으로 보존합니다.

기존 `field-input-locations` 조회의 25개 원시 필드를 그대로 사용하며,
`category=record_choice` 행을 더합니다. 이 행을 IR 채움 후보로 간주하지 않으므로
`candidate_id`와 `hole_id`는 비어 있습니다. 상세 선택 ID는 정적
`field_file_sources.bindings[].choice`에서 확인합니다.

## 관찰한 범위

[집계 예제](../../examples/assembled-length-summary/README.md)는 세 필드 선택,
선택용 1/1, 보류 1/1과 별도 실제 입력 3/3을 기록했습니다. 모델 호출은 0입니다.
[조회 예제](../../examples/record-choice-origins/README.md)는 저장된 27행 중
아홉 행을 Gooo로 분류했습니다. 이전 생산자 실행과 모델 호출은 각각 0입니다.

새 기록 검사에서는 선택·자료형·소스 범위·반환 부모 관계가 모순되는 30가지를
거부했습니다. 관련 자체 해시는 다시 계산한 상태로 검사했습니다. 기록 내용
사이의 일관성을 확인하며, 원본 파일과 생산자의 진위는 별도 확인 범위입니다.
현재의 부모 연결은 명시적 필드 복사·도우미 반환 범위입니다. 조건,
스칼라 계산과 컬렉션 원소 전체의 인과 연결은 계속 구현할 부분입니다.
