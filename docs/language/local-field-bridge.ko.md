# 필드와 지역 변수의 실행 기원 연결

Gooo의 실행 관측에는 지역 변수 쓰기와 필드 쓰기가 따로 있었습니다.
이번 연결은 값이 이동한 두 기록을 읽기 참조로 이어 줍니다.

필드가 바뀌기 전에 값을 지역 변수에 저장하면, 그 변수는 이전 필드 쓰기를
계속 가리킵니다. 이후의 필드 대입은 지역 변수의 실제 마지막 완료 쓰기를
읽습니다. 같은 값이 반복돼도 이 참조는 서로 구분됩니다.

## 보관 형식

기존 `gooo/native-local-observation/v1`과
`gooo/native-field-observation/v1`을 유지합니다. 별도 파일
`gooo-native-field-local-bridge.json`의 스키마는
`gooo/native-field-local-bridge/v1`입니다.

교차 행은 32비트 정수 7개입니다.

| 열 | 의미 |
| --- | --- |
| case | 원래 케이스 |
| own assignment | 해당 기록 안의 쓰기 번호 |
| other start/end | 평가 중 다른 기록에서 읽은 구간 |
| other drops | 그 구간에서 빠진 읽기 수 |
| start clock | 평가 시작의 공통 시계 |
| completion | 두 종류 쓰기를 합친 완료 순서, 미완료는 -1 |

각 읽기에는 공통 시계의 정수 하나를 붙입니다. 네이티브 보관에는 추가 값이나
문자열 본문을 복사하지 않습니다. 지역 변수·필드의 저장 상한을 그대로
사용하므로 교차 쓰기는 합계 8,192개 이하입니다. 완료 시계는 케이스별입니다.

레코드 생성식은 각 필드 평가의 교차 구간을 따로 남깁니다. 전체 오른쪽
평가가 끝난 뒤 필드 슬롯을 갱신하는 기존 순서를 유지합니다.
평가 중 실패한 쓰기는 완료 번호를 받지 않습니다.

## Gooo 탐색기

`--origin-shape field-local-columns`는 기본으로 필드 읽기 하나를 고릅니다.
`--origin-limit`으로 최대 128개를 고르면 각각 독립된 입력으로 전달합니다.
각 입력은 해당 케이스의 두 쓰기·읽기 집단을 32개 열로 받습니다.
전체 입력 페이지에는 32KiB 제한을 적용합니다. 스칼라 지역 변수의 실제 선언
순번·이름·타입을 담고, 레코드·필드 ID는 비워 둡니다. Go 전송기는 조상
집합을 계산하지 않습니다.

`trace.gooo`는 공통 완료 순서를 거꾸로 따라갑니다. 필드 복사와 알려진
레코드 반환은 직접 부모 연결을 먼저 사용합니다. 다른 쓰기는 자신의 읽기
구간과 교차 읽기 구간을 함께 봅니다. 두 읽기 배열의 내부 순서는 각각
검사하므로 서로 다른 기록의 번호를 한 순서로 오인하지 않습니다.

단순 상수는 보관한 타입 표현식의 구문으로 구분합니다. 관측된 읽기가 없는
다른 식은 미해결로 남깁니다. 컬렉션 읽기가 포함되면 그 부분을 미해결로
세면서 확인된 필드·지역 변수 기원은 유지합니다.

`recording_complete`는 선택된 케이스 안의 보관 상태입니다. 전체 실행의
요약이 일부 중단을 포함해도 다른 케이스의 기록은 별도로 판단합니다.
`SCOPED_FIELD_LOCAL_ORIGINS`는 이 기록 프로필 안의 탐색 결과입니다.
분기 제어와 사용하지 않은 헬퍼 인자의 정밀 구분 등은 남아 있습니다.

이전 필드 기록만 있는 자료에서는 새 교차 기록을 만들지 않습니다.
기존 행 조회는 그대로 사용하고 새 열 형식은 기록이 없다는 오류를 냅니다.
저장 자료 조회 중 원래 프로그램과 모델은 호출하지 않습니다.
