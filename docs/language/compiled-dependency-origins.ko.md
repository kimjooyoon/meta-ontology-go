# 의존성 타입의 출처

분석기가 같은 의존성을 여러 단계에서 다시 검사하면 함수 본문을 반복해서 읽는 비용이 커집니다. 의존성 본문을 컴파일한 출처와 지금 분석하는 본문을 구분해 처리합니다.

1. 현재 빌드 조건의 의존성 목록과 입력 파일을 읽습니다.
2. 같은 도구와 모듈, 환경으로 Go 컴파일 출처를 얻습니다.
3. 컴파일 전후의 입력 집합과 파일 내용, 실행 문맥을 확인합니다.
4. 출처가 확인된 의존성의 선언을 읽고, 지금 분석하는 본문은 전체 타입 검사 경로로 처리합니다.

새 단계에서는 프로젝트 AST와 타입 객체를 새로 만듭니다. 표준 라이브러리의 타입 동일성은 한 분해 작업의 문맥 안에서 유지합니다. 잘못된 의존성 본문은 선언 전용 읽기에 들어가지 않습니다.

새 소비자로 수행한 실제 프로젝트 관찰은 60개 의존성의 타입을 약 2.49초에 읽었습니다. 조회는 두 번이었고 과거 테스트는 실행하지 않았습니다. 이 결과는 해당 소비자의 관찰입니다. 전체 CI 시간은 별도 확인이 필요합니다.
