# 미해결 연산의 출처

등록되지 않은 연산이 들어왔을 때도 요청한 ID와 출처를 남기는 작업을 진행하고
있습니다. `internal/meta/metricprogram/unresolvedpolicy/policy.gooo`의 세 활동이
해상도, 이유, 다음 단계의 이름을 정합니다. Go는 받은 요청과 원본 스냅샷을 담아
전달합니다.

| 등록 여부 | 출처 기록 | 해상도 | 다음 단계 |
| --- | --- | --- | --- |
| 등록됨 | 있음 | `exact_operation` | `CONTINUE_SOURCE_OPERATION` |
| 미등록 | 있음 | `invariant_only` | `DECLARE_SOURCE_OPERATION` |
| 등록됨 | 빠짐 | `invariant_only` | `CAPTURE_OPERATION_ORIGIN` |
| 미등록 | 빠짐 | `invariant_only` | `CAPTURE_OPERATION_ORIGIN` |

출처 기록은 저장한 문맥의 존재를 뜻합니다. 실제 원본과의 일치는 독립적인 소비
단계에서 확인할 사항입니다. 반환되는 거부 기록은 요청한 연산과 지표 ID, 저장소와
커밋, 레지스트리 원본·투영의 경로와 다이제스트, 판단 규칙의 원본을 함께 담습니다.
준비도 점수나 저장소 쓰기·승격 권한은 부여하지 않습니다.

## 현재 구현 범위

규칙 세 개를 Gooo에서 Go로 생성했고, 원본과 생성 묶음의 연결을 검증합니다.
새 로컬 검사 7개는 네 입력 조합, 생성 코드의 원본 일치, 오류를 감싸고 JSON으로
옮긴 뒤에도 요청과 권한 경계가 유지되는지를 확인했습니다. 분류는 정해진 분기로
실행하며 외부 모델을 호출하지 않습니다.

현재는 독립된 분류·전송 모듈입니다. 실제 컴파일러의 미등록 연산 거부 지점과
독립 소비자 연결, 새 원본의 문법 등록, 원래 CI의 상위 입력 사례는 후속 작업입니다.
기존 컴파일러의 등록 제약과 16개 반례 집합은 유지합니다. 이 단계로 이슈 #791을
완료 처리하지 않습니다.
