# 일반 계산의 필드별 기원

`gooo body-origins --activity <이름> <파일.gooo>`는 소스의 가능한 값 의존성을
`gooo/typed-value-origins/v1`로 조회합니다. 조립 후보나 모델 없이 일반
`computes`에서도 사용할 수 있습니다.

주요 필드는 다음과 같습니다.

| 필드 | 의미 |
| --- | --- |
| `source_sha256`, `filename` | 조회한 파일 내용과 이름 |
| `flow.nodes` | 형식이 확인된 값 정의, 읽기, 필드 쓰기, 호출, 합류 |
| `outputs` | 스칼라 반환 또는 반환 레코드의 각 필드 ID와 루트 |
| `inputs` | 입력 노드와 포트, 필드 ID |
| `node_sources` | 노드 순서대로 원래 리터럴의 바이트 범위 또는 매핑 불가 이유 |
| `status`, `reason` | 분석 완료 여부와 지원 범위 밖인 이유 |

반환값을 레코드 전체와 연결하는 대신 개별 필드의 정의를 유지합니다.
지역 레코드를 복사하면 필드의 정의도 복사되고, 필드 대입은 그 필드만
갱신합니다. 같은 파일의 순수 헬퍼는 실제 인자 정의와 연결합니다.
조건이 상수가 아니면 각 반환·필드 대입의 가능한 정의를 합류시킵니다.

기본 데이터 간선은 `parents`입니다. `guard`와 `condition`은 제어 의존성을
나타냅니다. 상수로 도달 불가인 반환은 결과 루트에 들어가지 않습니다.
분석에 실행 입력이 없으므로 어떤 경로가 실제로 실행됐는지는 판단하지
않습니다. 모든 프로그램의 최소 의존성을 보장하는 분석도 아닙니다.

`--inputs-for <패키지:활동>`는 그래프를 기존 입력 전용 스키마인
`gooo/body-composition-inputs/v1`로 바꿉니다. `--field <필드 ID>`는 반환
레코드의 필드를 고릅니다. `--include-control`은 동봉한 Gooo 탐색기에서
제어 간선도 따라가도록 지정합니다. 이 변환은 기원 결론을 계산하지
않으며, 예제 Gooo 프로그램이 연결을 따라가 결론을 반환합니다.

조회 상한은 512노드·64개 동시 바인딩·분기/호출 깊이 16입니다.
필수 단일 스칼라 필드의 평평한 레코드가 현재 대상입니다. 반복문,
선택/반복 필드 등 지원 범위 밖인 분석은 이유와 함께 `UNRESOLVED`가 됩니다.
Gooo 탐색기의 입력은 60노드·32KiB까지이며 초과 시 거절합니다.

`--inputs-shape source-control-columns`는 보관된 활동 그래프의 분기 방향,
상수 진리값, 노드 활동 ID를 함께 전달합니다. 기본 내보내기는 기존
`ancestry-columns` 형식을 유지합니다. 새 형식에서는 `--field`로 그래프를
자르지 않습니다. [Gooo 조건 분기 판독기](../../examples/source-control-reader/README.md)는
이 사실을 받아 참·거짓·알 수 없음과 그 분모를 직접 구성합니다.

기존 `gooo/body-value-origins/v1` 및 조립용
`gooo/record-value-flow/v1`의 생성 결과와 저장된 기록은 유지합니다.
새 조회는 기존 형식 기반 분석기를 사용하고 자신의 반환 루트와
원본 위치를 덧붙입니다. 소스 검사는 정수 지역 변수의 내부 형식 정규화
전에 수행하여, 원래 작성한 `let count=0`을 내부 형식 선언으로 오해하지
않도록 합니다.

[실행 예제](../../examples/typed-value-origins/README.md)에서 레코드 복사와
필드 수정의 실행 결과, Gooo가 고르는 입력 기원을 함께 볼 수 있습니다.
