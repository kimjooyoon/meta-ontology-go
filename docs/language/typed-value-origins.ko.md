# 일반 계산의 필드별 기원

`gooo body-origins --activity <이름> <파일.gooo>`는 소스의 가능한 값 의존성을
평평한 스칼라 그래프는 `gooo/typed-value-origins/v1`, 중첩 레코드 그래프는
`gooo/typed-value-origins/v2`로 조회합니다. 조립 후보나 모델 없이 일반
`computes`에서도 사용할 수 있습니다.

주요 필드는 다음과 같습니다.

| 필드 | 의미 |
| --- | --- |
| `source_sha256`, `filename` | 조회한 파일 내용과 이름 |
| `flow.nodes` | 형식이 확인된 값 정의, 읽기, 필드 쓰기, 호출, 합류 |
| `flow.record_layouts` | 중첩 레코드 버전에서 쓰는 타입 ID와 순서 있는 필드 ID·타입 ID |
| `flow.record_values` | 레이아웃과 정확한 필드 기원 노드 배열 |
| `flow.record_versions` | 소스 사건 노드와 필드 기원 배열의 연결 |
| `outputs` | 스칼라 반환 또는 반환 레코드의 각 필드 ID와 루트 |
| `inputs` | 입력 노드와 포트, 필드 ID 및 원래 시그니처의 `declaration` |
| `node_sources` | 노드 순서대로 원래 리터럴의 바이트 범위 또는 매핑 불가 이유 |
| `status`, `reason` | 분석 완료 여부와 지원 범위 밖인 이유 |

반환값을 레코드 전체와 연결하는 대신 개별 필드의 정의를 유지합니다.
지역 레코드를 복사하면 필드의 정의도 복사되고, 필드 대입은 그 필드만
갱신합니다. 같은 파일의 순수 헬퍼는 실제 인자 정의와 연결합니다.
조건이 상수가 아니면 각 반환·필드 대입의 가능한 정의를 합류시킵니다.

기본 데이터 간선은 `parents`입니다. `guard`와 `condition`은 제어 의존성을
나타냅니다. 상수로 도달 불가인 반환은 결과 루트에 들어가지 않습니다.
중첩 레코드의 `record_version`은 복사·반환 같은 레코드 이력으로 연결됩니다.
다른 필드를 수정한 사건을 선택한 필드의 데이터 의존성으로 섞지 않습니다.
분석에 실행 입력이 없으므로 어떤 경로가 실제로 실행됐는지는 판단하지
않습니다. 모든 프로그램의 최소 의존성을 보장하는 분석도 아닙니다.

`--inputs-for <패키지:활동>`는 그래프를 기존 입력 전용 스키마인
`gooo/body-composition-inputs/v1`로 바꿉니다. `--field <필드 ID>`는 반환
레코드의 필드를 고릅니다. `--include-control`은 동봉한 Gooo 탐색기에서
제어 간선도 따라가도록 지정합니다. 이 변환은 기원 결론을 계산하지
않으며, 예제 Gooo 프로그램이 연결을 따라가 결론을 반환합니다.

조회 상한은 512노드·64개 동시 바인딩·분기/호출 깊이 16입니다.
필수 단일 스칼라 필드와 중첩 레코드 필드를 다룹니다. 반복문,
선택/반복 필드 등 지원 범위 밖인 분석은 이유와 함께 `UNRESOLVED`가 됩니다.
Gooo 탐색기의 입력은 60노드·32KiB까지이며 초과 시 거절합니다.
기존 배열 형식의 `ancestry-columns`와 `source-control-columns`는 중첩 레코드의
버전 표를 전달하지 못하므로 이 경우 내보내기를 거절합니다. JSON과 텍스트
조회에서 전체 출처 기록을 확인할 수 있습니다.

중첩 레코드는 복사·호출·반환 사건을 각각 보존하면서 같은 필드 기원 배열을
공유합니다. 배열의 각 항목은 값 자체가 아닌 기원 노드의 번호입니다.
같은 값을 가졌더라도 원래 입력 경로가 다르면 서로 다른 기원을 유지합니다.
`record_values[].layout`과 `record_versions[].value`는 각각 표에서 1부터 시작하는
번호이고, `fields`는 해당 레이아웃의 필드 순서를 따릅니다. `record_versions[].node`는
`flow.nodes`의 사건 번호입니다. 이 필드 연결은 레코드 구성 정보이며, 데이터·제어
간선을 임의로 양방향 순회하라는 의미가 아닙니다.

파생된 출력 필드 루트는 원문 표현식의 바이트 범위를 새로 만들어내지 않습니다.
`node_sources`에는 `DERIVED_RECORD_FIELD_PROJECTION`을 남기고, `record_version`으로
연결한 실제 반환·복사 사건에서 원문 위치를 확인합니다.

`--inputs-shape source-control-columns`는 보관된 활동 그래프의 분기 방향,
상수 진리값, 노드 활동 ID를 함께 전달합니다. 기본 내보내기는 기존
`ancestry-columns` 형식을 유지합니다. 새 형식에서는 `--field`로 그래프를
자르지 않습니다. [Gooo 조건 분기 판독기](../../examples/source-control-reader/README.md)는
이 사실을 받아 참·거짓·알 수 없음과 그 분모를 직접 구성합니다.

`inputs[].declaration`은 활동 ID, 원본 파일 해시, 입력 순서, 타입 이름과
타입 ID, 원래 타입 참조의 바이트 범위를 보관합니다. 같은 타입을 여러 번
사용해도 선언 위치가 유지됩니다. 레코드의 각 입력 필드는 같은 선언을
가리키면서 자신의 필드 ID를 유지합니다. 텍스트 출력에서는 시그니처의
행·열을 보여 줍니다. 기존 기록에 선언 정보가 없으면 해당 줄을 생략합니다.

`--inputs-shape input-declaration-columns`로 이 사실을 Gooo에 전달할 수
있습니다. 내보내기는 입력 1~16개, 32KiB 범위이며 각 시그니처 위치마다
행 하나를 구성합니다. `--field`, `--include-control`은 이 형식에 적용되지
않습니다. [입력 선언 예제](../../examples/source-control-reader/README.md#같은-타입의-입력을-선언-위치로-구분하기)에서
Gooo가 같은 타입의 입력 쌍을 판독하는 과정을 볼 수 있습니다.

기존 `gooo/body-value-origins/v1` 및 평평한 스칼라 레코드의
`gooo/record-value-flow/v1` 생성 결과와 저장된 기록은 유지합니다.
중첩 레코드는 `gooo/record-value-flow/v2`에 위 레코드 버전 표를 함께 보관합니다.
기존 모델의 특징 계약에는 이 버전 정보가 없으므로 모델 인코딩을 거절하고,
기존 결정론적 선택 경로를 유지합니다.
새 조회는 기존 형식 기반 분석기를 사용하고 자신의 반환 루트와
원본 위치를 덧붙입니다. 소스 검사는 정수 지역 변수의 내부 형식 정규화
전에 수행하여, 원래 작성한 `let count=0`을 내부 형식 선언으로 오해하지
않도록 합니다.

[실행 예제](../../examples/typed-value-origins/README.md)에서 레코드 복사와
필드 수정의 실행 결과, Gooo가 고르는 입력 기원을 함께 볼 수 있습니다.

## Gooo에서 전체 레코드 그래프 조회

[레코드 출처 탐색기](../../examples/record-origin-reader/README.md)는 v2·v3 보고서를
페이지로 받아 Gooo가 데이터·조건·레코드 이력 간선을 선택한다. Gooo 원문이
단계별 처리량과 전체 단계 수를 정하고 질의 정체성을 확인한다. 준비된 순수
프로그램은 입력 바인딩을 호출마다 새로 만들며 같은 형식 정보와 투영을 재사용한다.
실제 446개 노드의 18개 질의, 별도 필수 레코드의 4개 질의와
511·512노드의 3개 경계 질의를 독립 기대값으로 해석·네이티브 양쪽에서 확인한다. 전체 질의의 구체적인 출처와 남은 범위는 예제에 구분하여 기록한다.

필수 배열의 `for … in …`은 v3에서 상징적 원소와 반복 전달 관계를 보존한다.
초기 값과 다음 반복의 값을 분리해, 서로 이전 값을 교환하는 변수도 추적한다.
Gooo가 소유한 방문 집합과 재탐색 상한으로 순환 관계를 읽는다.
[반복 값 예제](../../examples/loop-carried-values/README.md)는 값의 실행 9개와
출처 질의 4개를 별도로 검사한다. 정적 가능 관계와 실제 실행의 PROV-O 기록은
각각의 원본 소스·활동·노드 정체성으로 구별한다.

`items[offset + 1]`처럼 인덱스로 읽는 경로도 v3에서 목록과 인덱스식의 부모를
함께 보존한다. [인덱스 예제](../../examples/indexed-record-values/README.md)는
지역 별칭과 한글 변수명을 거친 원문 위치를 유지하며, 읽지 않는 필드를 결과에서
구별한다. 노드의 `source_index`는 작성한 식을 나타낸다. 입력값에서 실제로 계산한
배열 위치와 실행 성공 여부는 실행 기록과 범위 검사에서 별도로 확인한다.

직접 만든 `[]Item{first, second}`의 출처도 v3에서 다룬다.
[배열 구성 예제](../../examples/constructed-record-values/README.md)는 배열 전체의
값과 선택할 때 필요한 형태 정보를 구별한다. 필드 하나를 읽을 때 다른 필드의
기원이 섞이지 않으며, 상수 인덱스는 해당 항목의 원래 필드까지 따라간다.
복사·레코드 필드 저장·조건 분기 이후에도 같은 관계를 보존한다. 반복 메타데이터의
`collection`은 원소와 진입 여부가 참조하는 동일한 형태 루트다. 실제 원소 값의
기원은 선택한 필드의 부모로 별도 연결한다. 배열 자체의 반복 전달은 미해결로
남기고, 원소를 읽으며 스칼라·레코드 값을 누적하는 기존 반복 전달과 구별한다.
