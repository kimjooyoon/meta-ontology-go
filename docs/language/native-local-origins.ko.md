# 지역 변수에서 이어지는 기원

```gooo
let original = input.values[0]
let copy = original
original = input.values[1]
return Batch{values: []int64{copy, original}}
```

두 입력의 숫자가 같아도 `copy`와 마지막 `original`은 다른 대입에서 온다.
Gooo는 지역 변수의 선언, 실제 대입 순서, 함수가 호출된 회차를 함께 기록한다.
새 배열의 첫 원소는 복사 전 대입으로, 둘째 원소는 재할당으로 이어진다.

이 기능을 포함한 개발 소스에서 새로 실행한 기록에 적용된다. 과거 실행 기록에
없던 관계를 다시 계산해 채우지는 않는다.

워크스페이스의 원래 파일까지 이어지는 위치는 별도의 `local-input-locations` 입력으로
읽는다. [원래 패키지·파일 기원](native-local-file-origins.ko.md)과
[실행 예제](../../examples/workspace-local-origins/README.md)에 명령과 좌표의 차이를 적었다.

## Gooo가 기록을 읽는 경로

```sh
go run ./cmd/gooo package execute --json \
  --origin-receipt examples/native-origin-reader/local10773-runtime.json \
  --origin-kind local-uses --origin-offset 0 --origin-limit 2 \
  examples/native-origin-reader/locals/locals.workspace.json
```

예제의 JSON은 지역 변수 관찰이 포함된 저장 기록이다.
[원래 프로그램과 기록의 출처](../observations/native-local-origins/README.md)도 함께 보관한다.
[읽기 프로그램](../../examples/native-origin-reader/locals/locals.gooo)은
`let`과 조건문으로 연결된 대입, 기록 한도, 원본 선언 위치를 구분한다.
분류 규칙은 이 Gooo 파일에 있다. 페이지를 읽을 때 원래 프로그램과 모델의
호출 횟수는 0이며, 새 읽기 프로그램만 실행한다.

| 입력 종류 | 한 행이 나타내는 것 |
| --- | --- |
| `local-writes` | 사례 안의 대입 번호, 함수 실행 회차, 변수, 완료 여부와 평가 범위 |
| `local-uses` | 실제 사용 위치와 마지막으로 완료된 대입의 연결 |
| `local-elements` | 생성한 배열 원소를 평가하면서 관찰한 지역 변수 사용 범위 |

대입 번호는 사례 안에서 해석한다. 함수 실행 회차는 같은 함수를 여러 번 불러도
각 호출의 변수가 섞이지 않도록 구분한다. 값의 같고 다름으로 기원을 찾지 않는다.

`local-uses`의 `projection_start/end`는 생성된 Go의 위치다.
`declaration_start/end`는 선택된 Gooo 소스 안의 원래 선언 위치다.
각 위치에는 해당 소스의 해시가 붙는다. `source_start/end`와 `source_sha256`는
선택된 Gooo 소스 안에서 실제 사용 표현을 가리킨다. `source_mapping`이 `MAPPED`인
행에 적용된다. 선언과 사용의 위치를 따로 기록하므로 같은 변수를 여러 번 쓴 곳도 구분한다.
이 정보가 없는 예전 기록은 `UNMAPPED`와 `declaration-only`로 남는다.

## 관찰 범위와 한도

정수·불리언·문자열 지역 변수의 초기화, 재할당, 반복문 변수와 실제 사용을 기록한다.
조건식에서 실행되지 않은 오른쪽 항이나 건너뛴 분기는 사용 기록을 만들지 않는다.
대입 중 오류가 발생하면 완료되지 않은 대입과 그때까지의 평가 범위를 남긴다.

한 실행 묶음에서 대입 4,096개, 사용 65,536개, 함수 실행 회차 65,536개까지
기록한다. 기록 저장에는 고정 폭 정수 행을 사용하며 변수의 실제 값은 복사하지 않는다.
배열 원소의 사용 범위는 기존 생성 관찰의 65,536개 원소 한도를 따른다.
한도를 넘으면 계산을 계속하고 누락 수와 `PARTIAL`을 남긴다.

`recorded_local_observation`에는 대입·사용·배열 원소 범위의 수, 중단과 누락 수가
들어간다. 완전성은 이 관찰 범위와 한도 안에서 읽어야 한다. 호출한 함수 안에서
평가된 사용도 범위에 포함되므로, 결과에 꼭 필요한 최소 의존성까지 보장하는 지표로
해석하지 않는다.

`gooo package execute`의 일반 텍스트 출력은 유한 사례 결과와 지역 변수 기원
상태를 별도 줄로 표시한다. `local origin: PARTIAL`에는 보관한 대입·사용 수와
누락·연결 미확정 수가 함께 나온다. 이 줄은 실행 후 이미 계산된 기록을 보여주는
힌트이며, 유한 사례의 `PASS` 판정이나 생성된 프로그램의 동작을 바꾸지 않는다.
지역 변수 관찰 지점이 없는 프로그램에는 이 줄을 표시하지 않는다.

읽기 프로그램의 입력 레코드는 22개 필드를 가진다. 처음 18필드 읽기 프로그램을 표현하기 위해 순수 본문
레코드의 필드 한도를 32개로 맞췄다. 타입 검사, 인터프리터 값 배열, 기호적 필드
배열, JSON 입력 해석이 같은 한도를 사용한다. 레코드 종류는 최대 16개다.

## 이번 로컬 관찰

| 새 실험 | 결과 |
| --- | --- |
| 재할당·반복·같은 값·헬퍼 반복 호출 | 4/4 결과 일치, 대입 46회, 사용 42회 |
| 컬렉션 없는 정수 프로그램 | 2/2 결과 일치, 대입 6회, 사용 8회 |
| 조건 건너뛰기와 0으로 나누기 | 3/4 결과 일치, 의도한 오류 1건과 미완료 대입 1건 기록 |
| 기록 한도 | 2/2 결과 일치, 대입 4,096회 보관, 4,102회 누락, 사용 6,149회 연결 미확정 |
| 새 기록을 읽는 Gooo 프로그램 | 생산 프로그램 2/2, 읽기 프로그램 3/3 결과 일치 |
| 32개 필드 | 2/2 결과 일치, 33개 필드의 선언과 인터프리터 배열 거부 |
| 사용 기록 한도 | 14/14 결과 일치, 사용 65,536회 보관, 6,172회 누락; 마지막 페이지에서도 PARTIAL 유지 |
| 함수 회차 한도 | 관찰기 Go 백엔드에서 65,537회 계산 유지, 회차 65,536회 보관·1회 누락 |
| 기록 간 모순 | 시간 순서·함수 회차·선언·평가 범위의 모순 18종 거부 |

함수 회차 한도는 관찰기 백엔드를 직접 실행한 결과다. Gooo 프로그램에서 같은 수의
함수 호출을 실행한 결과는 아니다. 언어의 별도 호출 예산은 그대로 적용된다.

CLI로 별도의 두 행을 읽은 결과는 `OBSERVED`였다. 기대값을 입력하지 않은 실행의
정답률로 환산하지 않는다. 앞선 개발 시도에서 플랫폼 전용 파일명 때문에 빌드가
한 번 실패했고, 16개 필드 한도 때문에 첫 읽기 프로그램 생성도 실패했다.
이 실패 기록을 보존했고, 후속 확인은 새로운 프로그램·입력 조합으로 수행했다.
정확한 소스 스냅샷, 로그, 분모는 [관찰 기록](../observations/native-local-origins/README.md)에 있다.

## 사용 표현까지 연결한 후속 관찰

새 프로그램에서 이스케이프로 저장된 한글 변수, 같은 이름의 분기별 변수,
반복 헬퍼 호출을 포함한 3/3 결과가 일치했다. 다른 프로그램은 CLI 첫 실행 3/3,
저장 기록으로 다른 입력을 실행한 결과 3/3이 일치했다. 반복문과 정수·문자열·불리언
사용 표현에 선택된 Gooo 소스 위치가 붙었다.

Gooo 읽기 프로그램은 새 기록의 두 행을 `assignment`, 원래 사용 위치가 없는 예전
기록의 다른 두 행을 `declaration-only`로 분류했다. 원래 생산 프로그램 실행과 모델
호출은 0회다. [소스 위치 관찰](../observations/local-use-source/README.md)에 범위를 적었다.
