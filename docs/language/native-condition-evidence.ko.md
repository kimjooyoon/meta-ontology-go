# Gooo 결과에 실제 조건 경로를 붙이기

승인 여부와 이유를 반환하는 프로그램을 읽을 때, 설명 문구와 실행 조건을 함께 확인하고 싶다.
Gooo는 소스가 허용한 후보를 구성하고 활동·필드 ID와 입출력을 기록해 왔다.
이번 개발본은 기존 실행 결과에 실제 `if` 조건의 참·거짓을 함께 남긴다.

참고한 원리는 [Mangle의 provenance 안내](https://mangle.readthedocs.io/en/latest/provenance.html)다.
Mangle은 유도한 사실을 규칙·변수 값·원래 사실과 연결하고 그 근거를 질의할 수 있게 한다.
Gooo에서는 결과를 소스가 선언한 조건·후보·활동 ID와 연결하는 작은 부분부터 구현했다.

## 어떤 내용이 새로 보이는가

[수량 판단 예제](../../examples/native-condition-evidence/README.md)의 입력은 수량,
처리 가능 수량과 요청 번호다. 소스는 수량이 2보다 작은지, 처리 가능 수량을 넘는지 확인한다.
두 조건을 통과한 반환값에는 승인 여부와 그 이유를 함께 채우는 후보 두 개가 있다.
이유가 다른 후보는 유한 선택 사례로 구별한다.

실제 생성 프로그램을 실행하면 다음 자료가 함께 남는다.

- `condition_sites`: 조건의 활동 ID, 호출의 루트 활동 ID, 순수 투영의 해시와 바이트 위치
- 각 입력의 `conditions`: 위치 번호와 그때 실제로 얻은 참·거짓, 평가 순서
- `deliveries`: 실제 입력과 결과, 레코드 필드의 ID, 제공한 기대값과의 일치 여부
- 원래 Gooo 소스·선택된 소스·타입 계획·관찰용 투영의 해시

관찰용 함수는 조건 값을 받아 기록하고 같은 값을 돌려준다. 조건 표현식은 한 번 평가한다.
Go의 단락 평가와 보조 활동 호출 순서를 유지한다. 호출을 건너뛰면 그 호출의 조건 기록도 없다.
조건을 계산하다 실패하면 그 조건에 임의의 거짓 값을 채우지 않는다.
그전에 완료한 조건 기록과 실제 산술 실패를 각각 읽을 수 있다.

저장한 순수 투영과 Gooo 소스는 그대로 두고 별도의 관찰용 투영을 만든다.
후보를 고르는 생성 과정과 실제 실행 관찰의 역할을 유지한다.
중복 이벤트는 순서를 가진 배열에 보관하고 조건의 긴 식·ID는 위치 표에서 참조한다.
전체 실행 묶음에서 이벤트 65,536건, 조건 위치 4,096개로 제한한다.
한도를 넘으면 완료된 관찰로 제출하지 않는다.

## 분모를 나눠서 읽기

| 관찰 | 실제 범위 | 해석 |
| --- | --- | --- |
| 새 레코드 CLI | 입력 6개, 기대값 12/12, 조건 평가 10건 | 이 입력에서 두 활동의 결과와 실제 조건 경로를 확인했다. |
| 같은 CLI의 위치·값 쌍 | 위치 2개 × 참·거짓, 4/4 관측 | 각 조건의 참·거짓을 관측했다. 여러 조건을 함께 거친 전체 경로의 분모는 별도다. |
| 별도 레코드 소스 | 레코드 4/4, 필드 값 8/8, 조건 평가 7건 | 필드 값은 네 레코드 안의 분모다. 실행 수에 더하지 않는다. |
| 별도 중첩 호출 소스 | 기대값 4/5, 산술 실패 1건, 조건 평가 9건 | 실패한 입력을 유지했다. 위치별 참·거짓 쌍은 5/6 관측했다. |
| CLI 후보 선택과 별도 평가 | 각각 1/1 | 실제 실행 12/12와 독립된 분모로 기록한다. |

위 자료의 모델·외부 제공자 호출은 0회다. 원래 관찰은 공개 커밋 이전의
컴파일러 소스와 임시 변경 해시에 연결돼 있다. 공개 커밋의 CI 증거는 그 소스에서 별도로 얻는다.
현재 다른 언어 엔진을 실행한 비교 자료는 없으므로 속도나 완전성의 순위를 매기지 않는다.

## Gooo의 다음 보완

현재 위치는 순수 Go 투영을 가리킨다. 한국어 별칭을 포함한 원래 Gooo 본문으로
위치를 대응시키는 기능이 필요하다. 조건의 필드 접근을 직접 필드 ID와 연결하고,
사용자가 이유 문구를 작성한 반환 위치도 같은 경로에서 읽도록 이어간다.
지역 값·반복 종료 조건·조건 안의 개별 피연산자는 별도 관찰 범위로 정한다.

모델 점수와 실제 참·거짓은 각자의 의미로 해석한다. 소형 결정 모델이 순서를 제안하는
지원 프로필에 이 기록을 연결할 때도, 소스가 허용한 선택과 실제 일치·실패는 남겨야 한다.
관찰값을 작은 typed record로 바꿔 Gooo 활동이 다시 분류하는 것이 후속 메타프로그래밍 과제다.
그 과정에서 여러 입력을 관계로 질의하거나 재귀 규칙을 유도하는 표현도 별도로 검토한다.
