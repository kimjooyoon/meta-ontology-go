# 실행된 필드에서 원래 Gooo 구문으로

필드의 고유 ID는 이름이 바뀌어도 유지됩니다. 이번 기능은 여기에 원본 파일의
위치를 연결합니다. 값이 같다는 이유로 출처를 합치지 않습니다.

## 연결 순서

컴파일러는 Go로 이름을 바꾸기 전에 필드 대입, 생성자의 필드 값, 필드 선택
읽기의 실제 구문 노드를 보관합니다. 타입 검사에서 레코드·필드의 고유 ID를
붙이고, 변환 뒤의 구문 순번과 집단 크기를 기록합니다.

실행 관측기는 구문 종류·순번·집단 크기와 타입 ID가 맞을 때만 좌표를 연결합니다.
매칭이 다르면 `UNMAPPED`입니다. 문자열 검색이나 값 비교로 빈 연결을 채우지 않습니다.

`field_sources`는 선택된 Gooo 소스 위치를, `field_file_sources`는 실제
워크스페이스 입력 파일의 위치를 담습니다. 기존 지역 변수 위치 변환을 공유해
패키지 이름 변환과 문자열 이스케이프를 되돌립니다. 위치는 UTF-8 바이트 범위입니다.

좌표는 정적 사이트별로 한 번 저장합니다. 반복 실행된 행은 사이트 번호를
참조합니다. 기존 필드·지역 변수 네이티브 기록과 32개 필드 사실의 모양은 유지합니다.

## Gooo에서 읽기

`package execute --origin-receipt ... --origin-kind field-input-locations`는
실제로 관측된 필드 쓰기·읽기에 대응하는 원본 위치 행을 전달합니다.

| 항목 | 의미 |
| --- | --- |
| `event_kind`, `event_index` | 관측된 쓰기 또는 읽기와 그 번호 |
| `assignment_index` | 기록 안에서 연결된 쓰기 번호, 미연결은 음수 |
| `record_id`, `field_id` | 소스가 선언한 고유 의미 ID |
| `category=target/value` | 대상 구문과 값 구문의 구분 |
| `mapping`, `reason` | 원본 위치 연결 상태와 미해결 이유 |
| 파일·해시·시작·끝 | 원래 입력 파일과 바이트 범위 |
| 후보·구멍·문법 | 조립 경로가 있는 경우 그 선언의 기원 |

`origin_input`에는 선택 소스 표와 원본 파일 표의 해시도 남습니다.
페이지는 최대 128행이며 전체 소비자 입력은 32KiB 이하입니다.

[조회 프로그램](../../examples/field-source-map/inspect.gooo)은 위치를 해석하는
규칙을 Gooo로 작성합니다. Go 전송기는 사실을 옮기고, Gooo가 출력 상태와
기원 종류를 구성합니다.

## 조립식과 범위

후보가 들어간 식이 여러 원본 조각에 걸치면 전체 식에 단일 좌표를 부여하지
않습니다. 템플릿·선언 후보·유도 문법의 조각별 원래 위치는 함께 전달합니다.
관계 이름은 `field_expression`입니다.

현재 원본 필드 구문을 보존하는 세 종류 밖의 사이트는 미해결입니다.
레코드 전체 복사·파라미터·전체 레코드 읽기의 정밀한 필드 위치와 선언 연결은
남아 있습니다. 파일이 없는 오래된 기록에도 새 좌표를 만들지 않습니다.

위치 연결률과 계산의 정확성은 별도로 봅니다. 이 기능은 분기 제어, 사용하지
않은 인자, 컬렉션 원소까지 포함한 완전한 인과 관계를 주장하지 않습니다.
[관찰 기록](../observations/field-source-locations/README.md)에 분모를 나누었습니다.
