# 여러 실행의 관계를 Gooo로 판단하기

요금이 입력에 따라 증가하는지, 변환한 값을 되돌리면 원래 값이 나오는지는 실행 결과를
함께 봐야 알 수 있습니다. Gooo에서는 이 비교를 일반 활동으로 작성하고, 해당 활동의
결과를 호출자 조립의 조건으로 사용할 수 있습니다.

```gooo
activity Nondecreasing(Integer) -> Boolean
 computes "let first=Fee(input); let second=Fee(input+1); return first <= second"

activity RoundTrip(Integer) -> Boolean
 computes "return Decode(Encode(input)) == input"
```

`Fee`, `Encode`, `Decode`의 바디에는 소스가 허용하는 선택지를 선언합니다. 각 활동의
지역 조건도 함께 유지합니다. 호출자 조립은 위 비교 결과가 참이 되는 후보를 찾되,
지역 조건을 어기는 후보를 전체 완료로 처리하지 않습니다.

## 확인한 동작

[실행 가능한 예제](../examples/source-relational-callers/README.md)에는 다섯 개의 Gooo
프로그램과 실제 선택된 소스, 입력, 결과 기록이 있습니다.

- 증가 관계: 첫 후보는 지역 조건만 통과했습니다. 다음 후보는 지역 조건과 호출자 조건을
  함께 통과했고, 별도 입력의 관계 검사도 1/1을 통과했습니다.
- 역변환 관계: 처음에는 두 함수가 모두 7을 더했습니다. 한 함수가 7을 빼도록 선택된 뒤
  왕복 결과가 원래 입력과 같아졌고, 별도 입력에서도 1/1을 통과했습니다.
- 선택지 부족: 올바른 동작을 만들 수 없는 두 프로그램은 각각 모든 2개·4개 조합을
  시도한 뒤 부분 완료로 남았습니다. 별도 실행도 각각 0/1입니다.
- 조건 충돌: 지역 조건은 두 결과를 7과 6으로 요구하고, 호출자는 첫 결과가 두 번째보다
  크지 않기를 요구합니다. 한 후보는 지역 2/2·호출자 0/1, 다른 후보는 지역 0/2·호출자
  1/1로 남았습니다. 컴파일러가 어느 요구를 지워서 완료로 만들지는 않습니다.

모델 호출은 모두 0회입니다. Gooo가 판단할 조건과 선택 범위를 소유하고, 현재의 결정론적
조립 경로가 그 안을 탐색했습니다. 이 관측은 주어진 입력의 관계를 확인한 결과입니다.
정수 경계값에서의 오버플로와 더 넓은 입력 범위는 별도로 다뤄야 합니다.

## 원래 요구와 실행 소스의 역할

원본 `.gooo.fixture`에는 조건과 허용한 선택지가 들어 있습니다. 선택된
`.selected.gooo.fixture`는 `assembling` 선언을 고정된 함수 바디로 바꾼 실행용 소스입니다.
읽기용 실행 소스는 줄 끝 공백을 정리했으며, 결과 JSON에는 당시 원문과 두 다이제스트를
함께 남겼습니다. 활동 식별자·입출력 타입·판단 함수는 유지됩니다. 선택을 이어가거나 결과를 설명할 때는
원본과 조립 결과 기록을 함께 사용합니다. 기록에는 원래 조건의 다이제스트, 시도한 선택과
관측 결과가 연결되어 있습니다. 실행용 파일만으로는 조립 선언을 복원할 수 없습니다.

## 언어와 모델의 다음 과제

이 비교 로직은 현재 Gooo 활동으로 구현할 수 있었습니다. 앞으로 같은 배선을 반복해서
작성해야 하는 사례가 쌓이면 관계 선언을 별도 문법으로 승격할 근거가 됩니다. 지금은
실행 가능한 소스와 선택 과정을 통해 표현력을 확인합니다.

결정 모델에는 어떤 지역 조건이 남았는지와 어떤 호출자 관계가 실패했는지를 함께 전달할
필요가 있습니다. 호출자 점수 하나만 올리는 선택은 지역 조건을 깨뜨릴 수 있습니다.
또한 왕복 예제에서는 4개 중 2개 조합만 확인했습니다. 확인하지 않은 조합에 실패 라벨을
붙이면 관측보다 강한 학습 정답을 만들게 됩니다. 모델 개선에서는 이 차이를 보존해야 합니다.

여러 실행의 관계로 결과를 판단하는 아이디어는
[Chen·Cheung·Yiu의 metamorphic testing 연구](https://arxiv.org/abs/2002.12543)와 연결됩니다.
[Fu 등의 적절성 연구](https://arxiv.org/abs/2412.20692)는 관계와 입력의 품질을 함께 살핍니다.
Gooo에서는 그 관계를 실행 가능한 활동으로 쓰고, 구현 선택·지역 조건·관측 결과와 연결하는
경험을 발전시키고 있습니다.
