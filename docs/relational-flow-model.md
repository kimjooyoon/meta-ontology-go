# 작은 결정 모델을 실제 Gooo 조립에 연결하기

개발 소스는 SDK 0.2.35의 관계 입력과 음수 신호를 보존하는 모델을 읽습니다.
Gooo 소스에 선택할 수 있는 비교식·분기와 검사할 사례를 적으면, 모델이 후보 순서를
정하고 컴파일러가 선택한 본문을 조립합니다. 현재 설치된 공개 컴파일러 0.6.25에는
이 연결이 아직 포함되지 않습니다.

## 사용 흐름

SDK의 `model-leaky_v6.json`을 로컬에 저장한 뒤 개발 컴파일러에서 실행합니다.

```sh
gooo body-context --activity Choose --model model-leaky_v6.json \
  examples/body-codegen/source-semantic-flow-copy.gooo.fixture

gooo body-codegen --json --activity Choose --path-model model-leaky_v6.json \
  --path-step-attempts 1 --path-feedback-rounds 3 \
  examples/body-codegen/source-semantic-flow-copy.gooo.fixture
```

첫 명령은 모델의 입력과 소스 연결을 보여 줍니다. 판단과 후보 검사는 0회입니다.
모델 파일에서 입력 버전을 읽으므로 긴 버전 이름을 매번 입력할 필요가 없습니다.
`--feature-version source_intent_condition_output_relational_flow_v6`로 명시한 경우에는
파일의 버전과 같아야 합니다. 두 번째 명령은 선택 직후 본문을 만들고 선언된 출력·조건
사례를 검사합니다. 실패한 후보의 결과는 다음 판단에 전달되며 검사한 후보를 중복 실행하지 않습니다.

`--path-model`을 생략하면 고정 순서로 조립합니다. `body-construct`로 저장한 프로그램은
이후 모델 파일 없이도 다시 실행할 수 있습니다. 모델과 별개로 Gooo의 원래 의도,
선택 범위, 사례 및 정확한 정수 값이 유지됩니다.

## 컴파일러가 확인하는 연결

- `body-context`의 384칸 배열과 실제 첫 판단의 배열 해시가 같습니다.
- 직접 반환·대입 뒤 복사처럼 같은 값 흐름의 표현은 같은 입력을 사용합니다.
- 비교값과 반환값의 관계는 정수 그대로 비교하며, 전체 정수를 부동소수로 바꾸지 않습니다.
- 중첩 분기처럼 현재 정규화 범위 밖의 구조는 원래 입력을 유지합니다.
- 새 계산은 `gooo/flow-candidate-decision/v2`와 `leaky_relu_0.01_v1`로 식별합니다.
  형식과 계산 방식이 맞지 않는 파일은 읽지 않습니다. 기존 ReLU 모델도 원래 방식으로 읽습니다.
- 모델은 한 번 읽은 가중치를 보유하며, 동시 조립은 각각의 작업 공간을 사용합니다.

## 지금 측정한 성과와 남은 부분

SDK의 한 번의 고정 실험에서 첫 선택이 모든 선언 사례를 만족한 소스는 82/162에서
141/162로 늘었습니다. 80개가 개선되고 **21개는 악화**됐습니다. 작은 값 반환 20개와
중첩 분기 1개에서 후퇴했습니다. 두 탐색 방식의 최종 선언 사례 통과는 162/162였고,
후보 시도는 각각 242회에서 183회로 줄었습니다.

이 수치는 서로 관련된 작은 과제 집합의 결과입니다. 새로운 자연어 요청 전반의
정확도나 모든 입력에 대한 프로그램의 정확성을 보장하는 수치는 아닙니다.
첫 선택 성공, 선언된 사례의 완전성, 추가 시도 수를 함께 기록합니다.

모델 학습은 로컬 CPU에서 약 133ms, 진단 복사를 포함한 판단 중앙값은 약 14.5µs였습니다.
이는 SDK 실험의 시간입니다. 파일 읽기·소스 분석·Go 실행을 포함한 컴파일러 전체 시간은
별도로 측정해야 합니다. 형식·입력·재실행 검사는 제어된 가중치로 확인했습니다.
이후 공개 학습 가중치로 [실제 CLI 30개 명령](research/leaky-flow-cli-20261010/README.md)을
실행했습니다. 의도적으로 고른 성공·회귀 사례 다섯 개에서 첫 선택은 2/5였으며,
유한 탐색 후 네이티브 사례 40/40개와 모델 없는 저장 재실행 40/40개를 통과했습니다.
모델 조립은 약 3.1–3.7ms로, 약 0.7–1.0ms의 고정 순서보다 길었습니다.
