# 분기와 변수에 모델을 붙이기 전에 확인하기

`body-context --model`로 내 Gooo 소스가 작은 모델의 입력에 맞는지 확인할 수 있습니다.
분기·변수·피연산자의 선택지를 보고, 모델을 쓰는 경로와 고정 순서로 진행하는 이유를 읽습니다.
이 명령은 후보를 고르거나 실행하지 않습니다. 실제 결과는 이후 조립에서 확인합니다.

이 문서는 새 개발 소스의 기능을 설명합니다. 공개 0.6.23/source2b의 `--model` 사전 확인은
레코드 조립을 지원합니다. 실행 파일의 `gooo version --build --json`으로 소스를 확인하세요.

## 작은 예제부터

컴파일러 소스 폴더에서 실행합니다.

```sh
go run ./cmd/gooo body-context --activity Choose --include-plan \
  --model examples/scalar-identity/model/model.json \
  examples/caller-typed-paths/unary.gooo.fixture
```

소스에는 `if input < 0`의 두 분기 중 하나를 고르는 선택이 있습니다.
동봉한 자체 모델은 세 레코드 필드용입니다. 이 예제에서는 선택 하나라
`DECLINED_TO_DETERMINISTIC`과 `THREE_DECISION_COUNT_UNSUPPORTED`가 나옵니다.
사전 확인 명령은 정상 종료하고, 조립은 고정 순서로 이어갈 수 있습니다.
현재 모델을 쓰기 위해 무의미한 선택 둘을 추가할 필요는 없습니다.

외부 계획을 쓰는 기존 경로는 `--plan plan.json`을 함께 넘깁니다.
소스와 그 계획의 기본 본문이 맞는지 먼저 검사합니다. 모델을 생략하면
기존 `--feature-version` 입력 내보내기가 동작합니다.

## 결과에서 볼 부분

| 필드 | 읽는 방법 |
| --- | --- |
| `model_compatibility.status` | `READY_FOR_RANKING`이면 이 모델의 입력으로 표현할 수 있습니다. |
| `model_compatibility.reason` | 입력을 만들었는지, 선택 수·본문 종류·표현 길이가 맞지 않는지 보여 줍니다. |
| `model_compatibility.model` | 실제 읽은 모델과 가중치 지문, 입력 규격, 상주 텐서 크기입니다. |
| `source_binding` | 안정 ID와 정규화한 원래 본문을 검사한 기록입니다. |
| `inputs` | 실제 경로 선택 때 쓰는 각 입력의 원문·길이·지문입니다. |
| `complete_model_input` | 두 개·세 개를 한 번에 판단하는 모델이 받는 전체 입력입니다. |
| `expanded_plan` | `--include-plan`에서만 추가되는 선택 ID·종류·후보·기본값과 별도 유한 사례입니다. |

`READY_FOR_RANKING`에는 정답률이나 고른 후보가 포함되지 않습니다.
`model_predictions`, `candidate_tests`, `repository_writes`는 0이고 `selected_emission`은 false입니다.
입력을 만드는 동안 소스와 타입을 검사하는 비용은 있습니다. 모델의 초기화 시간과 텐서 크기는
그 과정 전체의 시간·메모리와 따로 기록합니다.
typed 모델 사전 확인의 `timing.model_load_ms`는 실제 로드 구간이며 `total_ms`에 포함됩니다.
모델을 읽은 것과 예측한 것을 단계 이름으로 구분합니다.

거절된 입력은 `inputs: []`이고 전체 모델 입력도 내보내지 않습니다. 긴 문장 일부를 잘라서
입력 가능한 것으로 표시하지 않습니다. 원래 선언의 지문과 거절 이유는 남습니다.
읽을 수 없는 파일, 잘못된 모델, 소스 불일치는 실패로 종료합니다.

## 현재 지원 범위

- 경로별 판단 모델: 원래 선언문, 위치를 보존한 문장, 컴파일러의 분리 문맥·의도,
  정규화한 의미 특징·의도를 사용하는 기존 입력 계약.
- 전체 두 선택 및 세 선택 모델: 실제 생성과 같은 입력 구성 및 전체 framing.
- 세 선택 공유 모델: FP32와 압축 QAT, 버전이 구분된 bag 특징.
- 레코드 필드 모델을 일반 분기에 지정하면 실제 생성과 같은 이유로 고정 순서 진행을 표시합니다.

소스 IR 탐색과 전체 후보 판단 모델의 사전 확인은 후속 구현 범위입니다.
그 모델을 이 명령에서 호환 가능하다고 표시하지 않습니다. 명시한 `--feature-version`은
불러온 모델과 같아야 합니다. 로컬 파일을 읽으며 원격 서비스에 연결하지 않습니다.

## 어떻게 확인했는가

한글·영어 분기 예제의 네 경로별 계약과 다섯 joint/shared 계약에서 사전 확인의 입력 지문을
실제 네이티브 생성이 소비한 입력과 비교합니다. 기록된 표현 거절은 예측 0회인 실제 생성과
같은 이유를 가져야 합니다. 별도 사례의 기대값을 `9007199254740993`으로 바꾸거나 seed를
지정해도 입력은 같습니다. 취소, 없는 모델, 다른 특징 버전, 소스 불일치도 검사합니다.
일부 테스트는 입력 계약용 인공 가중치를 사용합니다. 이 검사는 학습 품질의 평가가 아닙니다.
