# 공개 관계 모델로 Gooo 본문 조립하기

소스·관찰 계획을 공개한 `24281f3751c8bdc6b1ee70573ac85a486ca7b271`에서
공개 HF 관계 모델을 한 번 사용했습니다. Gooo 소스에 적힌 두 선택을 모델이 먼저 정렬하고,
컴파일러가 후보를 검사한 뒤 실제 Go로 실행했습니다. 저장한 결과는 모델 없이 재실행했습니다.
이번 한 예제에서는 모델과 고정 순서가 같은 후보2개를 확인했습니다.

[고정 계획](protocol.md), [입력과 호출 대조](audit.json), [원래 자원 관찰](resources.json),
[전체 원본·생성 코드·검사 도구](https://huggingface.co/asketeddy/gooo-canonical-decision-tiny-v1/tree/0c1687667c7fc8dc51bd05759d9a5398132d0cba/research/source-relative-native-20261011)를
함께 공개합니다. 원본 학습·예측·후보 실행은 반복하지 않았습니다.

## 무엇을 조립했나

작은 배치 함수의 의도는 대기 수가8보다 작으면3을 더하고, 나머지는2배를 반환하는 것입니다.
소스에는 변수 대입, 비교식, 두 계산식, 네 출력과 세 중간 Boolean 요구가 있습니다.
비교 순서와 분기 배치가 각각 두 선택이므로, 허용한 본문은 네 가지입니다.

| 항목 | 고정 순서 | 관계 모델 |
| --- | ---: | ---: |
| 첫 후보의 출력 검사 | 1/4 | 1/4 |
| 첫 후보의 중간 조건 검사 | 3/3 | 3/3 |
| 확인한 후보 | 2 | 2 |
| 최종 출력 검사 | 4/4 | 4/4 |
| 최종 중간 조건 검사 | 3/3 | 3/3 |
| 외부 조립 사례 | 1/1 | 1/1 |
| 나중의 네이티브 출력 검사 | 4/4 | 4/4 |
| 모델 판단 | 0회 | 후보 검사 전1회 |

첫 후보는 입력0,8,13에서 실패했습니다. 입력3에서는 우연히 기대값과 같았습니다.
모델도 처음에는 이 후보를 추천했습니다. 다음 후보에서 분기 안의 계산을 바꾸자 주어진
검사를 통과했습니다. 중간 조건의 일치와 최종 계산의 일치를 따로 읽어야 하는 사례입니다.
나머지 두 후보는 검사하지 않고 남았습니다.

모델 세션의 진행 기록은 후보 검사0개·1개·2개이며, 각각의 후속 판단 횟수는0회입니다.
조회한 두528개 입력 배열의 실제 FP32 바이트와 순위 기록의 식별값이 일치했습니다.
출력·Boolean 입력, 계획, 모델 및 선택/출력 본문 식별값도 대조했습니다.
저장 재실행은 `generated_now:false`, `construction_replayed:true`, 새 모델 호출0회로
같은 나중의 네 사례를 통과했습니다. 재실행에 포함된 원래 판단 시간은 과거 기록입니다.

## 비용

Apple M4·논리 CPU10개·16GiB에서 `GOMAXPROCS=1`, 일반 Go 빌드 캐시를 사용했습니다.
판단 자체는0.106833ms, 가중치 준비는7.822ms, FP32 가중치 배열은76,136바이트입니다.

| 원래 관찰 | 고정 순서 | 관계 모델 | 저장 재실행 |
| --- | ---: | ---: | ---: |
| 전체 명령 시간 | 0.81초 | 0.64초 | 0.34초 |
| 사용자+시스템 CPU 시간 | 0.53초 | 0.52초 | 0.30초 |
| 최대 RSS | 82.375MiB | 81.578MiB | 83.016MiB |
| 본문 준비·검사·출력 | 1.619ms | 2.333ms | 과거 기록 |

고정 순서로 한 번 실행한 값이며 빌드 캐시와 다른 프로세스의 영향이 있습니다.
전체 시간에는 생성 Go의 빌드·실행과 결과 처리가 포함됩니다. 이 차이로 모델의 속도 향상을
추정할 수는 없습니다. 전체 CPU 시간으로 순간적인 PC 사용률 증가를 계산하지 않았습니다.
가중치 준비는 본문 처리 시간과 별도로 기록하며, 요청의 `model_load_ms:0`은 보유한
모델을 재사용했다는 뜻입니다.

## 범위와 남은 점

소스 출력은0,3,8,13, 조립 입력은9, 나중의 입력은1,7,10,21입니다. 원본에서 이 입력 집합은
구분되지만, 실행기의 내부 함수 입력 분리 지표는 `UNKNOWN/UNCLASSIFIED_INPUTS`입니다.
같은 네 평가 사례를 두 방식과 저장 재실행에 반복 사용했습니다. 독립적인 성공 사례 수나
일반화 성적으로 합산하지 않습니다. 모델의 학습 노출 여부와 임의 입력의 정확성은 미측정입니다.

가중치는 이전 HF `be6d9574`의 파일 그대로이며, SHA256은
`cae32bdad17ab818498c6099066918cd9c9c591eb118afe1bc6a7ef82dc83cc4`입니다.
Go1.27.2·SDK0.2.41을 쓴 깨끗한 개발 소스에서 실행했습니다. 공개 설치판0.6.28은
앞선 정규화 모델을 지원하며, 이번 관계 모델 연결은 별도 릴리스를 기다립니다.

첫 읽기 전용 감사는 Boolean 입력의 버전·행 수 접두사를 해시에 빠뜨려 중단했습니다.
공개 SDK 형식대로 감사 코드를 고친 뒤 원본 바이트만 다시 대조해 통과했습니다.
원본 CI의 의존성 정리 단계에서는 이전 SDK0.2.40의 불필요한 합계 두 줄이 발견됐습니다.
이 두 줄을 제거했고, 실험 원본은 기존 커밋에 연결한 채 유지합니다.

다음 연구 질문은 반환할 계산과 기대 출력의 관계를 작은 입력으로 전달할 수 있는지입니다.
동일한 정보를 쓰는 규칙과 함께 비교해야 모델이 추가 비용만큼 도움을 주는 영역을 찾을 수 있습니다.
