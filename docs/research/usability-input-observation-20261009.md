# 입력부터 실행해 보는 조립 경로

Gooo에서 만든 프로그램에 입력을 넣고 실제 값을 볼 수 있게 `body-compose
--inputs`를 연결합니다. 정답을 준비하기 전에도 시작할 수 있습니다. 결과에는
원래 입력, 중간 결과, 다음 활동이 실제로 받은 값이 남습니다. 같은 생성물을
저장해 두었다가 기대값을 제공하면 다시 생성하지 않고 검사할 수 있습니다.

## 이번에 참고한 흐름

2026-10-09에 [Hacker News](https://news.ycombinator.com/),
[GeekNews](https://news.hada.io/), [GitHub Trending](https://github.com/trending)을
읽고 원문에서 아래 내용을 골랐습니다. 글의 작성일과 오늘 소개된 날짜는 다릅니다.

- HN에 소개된 Carson Gross의 [Yes, and…](https://htmx.org/essays/yes-and/)
  (2026-02-27)는 생성한 코드를 이해하고 복잡도를 관리하는 능력을 강조합니다.
  Gooo에 적용할 부분은 원래 의도와 실제 데이터 흐름을 함께 읽는 경험입니다.
  활동 사이의 값을 숨기지 않고 입력·결과·출처를 남기는 기존 실행기에 연결합니다.
- 긱뉴스에 소개된 Michael Lynch의
  [개발 글쓰기의 안티패턴](https://refactoringenglish.com/blog/anti-patterns-software-blogging/)
  (2026-10-07)은 독자가 얻을 것을 먼저 보여주고 낯선 용어를 짧게 풀도록 권합니다.
  이번 가이드는 실행 명령으로 시작하고, 실제 결과와 정답 확인의 차이를 바로 설명합니다.
- Trending의 [Matt Pocock skills](https://github.com/mattpocock/skills)는 함께
  쓰기 쉬운 작은 작업과 테스트 흐름을 보여줍니다. 입력 실행, 저장 재생, 기대값
  검사를 이미 있는 조립 명령에서 연결합니다. 추가 패키지나 모델 설치는 없습니다.

위 자료에서 내린 Gooo 적용 판단입니다. 자료가 Gooo의 품질을 검증한 것은 아닙니다.

## 줄이는 절차와 남기는 기준

호출할 때마다 정답 파일부터 작성해야 하는 절차를 줄입니다. 기존 입력 전용
스키마와 타입 검사를 명령줄에서 사용할 수 있게 합니다. `inputs.json`에는
원본 바이트가 남고 `input_schema`는 실행 모드를 명시합니다.

기대값을 제공하지 않은 실행은 통과 수와 전체 수가 모두 0입니다. 정확도는
미측정으로 표시합니다. 소스에 선언한 조립용 사례의 점수는 별도로 남습니다.
나중에 제공한 기대값으로 저장한 그래프를 검사할 때부터 호출 점수를 셉니다.

모델을 생략하면 결정론적인 순서를 사용합니다. 모델은 선언한 후보 순서를
제안하고, 실행과 저장 재생은 새 추론을 하지 않습니다. 관측된 결과를 자동으로
정답으로 저장하는 기능은 추가하지 않습니다. 잘못된 그래프도 실행에 성공할 수
있기 때문에 실제 결과와 정답의 구분이 필요합니다.

여러 활동의 저장 조립을 작업장의 반례 루프에 연결하는 일은 별도 범위로 남습니다.
이번에는 원래 입력과 중간 입력을 보존하는 native 실행 경로의 사용성을 높입니다.
