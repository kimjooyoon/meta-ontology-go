# 익숙한 음수 표현을 Gooo 본문 조립에 연결하기

2026-10-10 KST. 앞선 typed-path 실험에서 `-input`이 일반 본문에서는 동작하지만
레시피 확장에서는 거절됐습니다. 당시 예제는 `0 - input`으로 작성했고 실패 로그를
그대로 보관했습니다. 이번 변경은 변수·괄호 안의 식·중첩 음수를 기존 정수 조립에 연결합니다.

## 적용한 구조

- 음수 정수 상수는 기존 IR 번호와 표현을 그대로 유지합니다. 최소 int64와 `-0`도 포함합니다.
- 다른 정수 음수 표현은 기존 subtract 연산의 `0 - expression`으로 정규화합니다.
- 새 subtraction은 원래 소스 위치의 operand-order 선택점입니다. 중첩 식에서는 바깥쪽이 먼저입니다.
- 산술 정규화와 조건 정규화를 각각 기록하고, 둘을 함께 적용한 바인딩도 별도 이름으로 표시합니다.
- 기존 후보 팔레트, 타입, 노드·중첩 한도, 안정 ID와 저장 재생을 함께 유지합니다.

모델 입력 범위나 가중치는 확장하지 않습니다. 예제의 분기 선택은 소스의 정해진 후보 순서로 진행합니다.
README에는 현재 소스를 별도 이름의 개발 실행 파일로 빌드하는 명령을 넣었습니다.

자동 분할을 미리 검사하는 과정에서 기존 receiver 메서드의 안전한 분할을 확인하지
못한 결과도 보관합니다. 식·문장의 배열 저장과 else 시퀀스를 작은 함수로 분리한 뒤
같은 검사기가 네 논리 파일에서 15개 파일을 생성했고, 생성 Go의 race 검사도 통과했습니다.
기존 배열 번호·할당 순서는 회귀 검사로 확인합니다. 검사 한도와 정책은 유지했습니다.

## 검사 범위

다섯 본문에서 각각 일곱 입력을 사용합니다: 변수 음수, 괄호 식, 중첩 음수,
지역 변수 재할당, 조건과 음수의 조합입니다. 입력에는 최소·최대 int64,
양수·음수 `9007199254740993`, -1, 0, 1이 있습니다.
이 35개는 해당 본문의 유한한 지역 평가입니다.

별도 native 호출의 생성·저장 재생은 네 입력으로 확인합니다: 정확한 큰 정수,
-5, 최소·최대 int64. CLI에서는 기존 세 평가 입력을 생성과 재생에 같은 뜻으로 넘깁니다.
같은 입력을 재생했다고 새로운 평가 사례로 더하지 않습니다. 전체 문서 JSON의 왕복,
체크포인트의 원래 선택 범위, 정수 음수와 boolean 타입 구분도 확인합니다.
이 검사는 모델 학습의 일반화나 성공 확률 보정의 관측으로 사용하지 않습니다.

## 자료에서 가져온 것과 보류한 것

[Microsoft의 10월 9일 Decision-1 발표](https://commandline.microsoft.com/microsoft-decision-1-model-foundry/)는
선택지 점수와 입력 표현 변화에 대한 안정성을 설명합니다. Gooo에서는 소스 표기와
정규화된 조립 표현 사이의 의미 보존을 확인하는 기준으로 참고합니다.
모델 확률은 별도 보정 자료가 쌓였을 때 읽습니다. 발표의 속도·정답률을 Gooo 지표로 옮기지 않습니다.

긱뉴스에서 본 [pg-jev](https://github.com/realZachi/pg-jev)는 자연어 판단을 SQL의
기존 필터·분류에 연결하고 배치·위치 표현의 제약도 설명합니다. Gooo에서는 작은
선택을 이미 있는 조건·할당 구조와 연결하는 방향을 참고합니다. 큰 배치를 통한
자동 판단이나 외부 판단 API를 이번 변경에 추가하지 않습니다.

GitHub 주간 목록에서 확인한 [RAD Debugger](https://github.com/EpicGames/raddebugger)는
디버그 정보와 변환 도구를 제공합니다. Gooo의 계획·선택 기록을 다른 도구가 읽을 수
있게 유지하는 방향으로 참고하고, 새 GUI 구축은 보류합니다.
