# 조건 관측을 돌려주는 Gooo CLI 실험

2026-10-10, Apple Silicon macOS. 자체 모델의 공개 가중치를 실제 `body-codegen`에
연결하고, 조립된 본문을 Go 실행 파일로 실행했다. 사전에 적은 [실험 절차](protocol.txt)를
한 번 수행한 기록이다. 가중치를 새로 학습하거나 결과를 보고 의도를 고치지 않았다.

## 무엇을 해봤나

[Gooo 예제](../../../examples/body-codegen/source-condition-model.gooo.fixture)에
비교 방향과 분기 배치를 선택할 두 자리를 선언했다. 실험에서 소비한 원본 바이트는
`result/source.gooo.gz`에 보관했다.
조합은 네 개다. 최종 출력은 절댓값이고, 중간 비교는 **입력이 양수인지** 확인해야 한다.
두 비교 방향 모두 분기를 맞춰 바꾸면 절댓값을 만들 수 있으므로, 출력만으로는 이 의도를
구분할 수 없다. 소스에 출력 사례 9개와 중간 조건 사례 3개를 따로 적었다.

모델은 두 선택지의 점수를 계산한다. Gooo가 본문을 구성하고 선언된 사례를 실행한다.
조건이 틀리면 그 실제 관측을 특징 배열에 넣어 남은 경로를 다시 정렬한다. 이것이 이번에
연결한 피드백이다. 모델이 소스 문장이나 토큰을 출력하는 단계는 없다.

| 관측 | 기본 탐색 | 조건 모델 + 피드백 |
| --- | ---: | ---: |
| 시도한 경로 | 4 | 2 |
| 모델 호출 | 0 | 2 |
| 선택한 본문의 출력 사례 | 9/9 | 9/9 |
| 선택한 본문의 중간 조건 | 3/3 | 3/3 |
| 조립 단계 총시간 | 1.153ms | 3.344ms |
| 모델 파일 로딩 | 0 | 1.869ms |

첫 모델 제안은 mask 0이었다. 출력은 9/9였지만 중간 조건은 1/3이었다.
`-9007199254740995`에서 조건이 `false`여야 하는데 `true`였다는 관측을 전달했고,
다음 제안 mask 3이 출력과 조건을 모두 통과했다. 시도한 경로는 중복되지 않았다.
초기 판단은 10,708ns, 피드백 판단은 10,625ns였다. 호출 수가 적어서 분포나 일반적인
지연시간으로 해석할 수는 없다. 이 작은 문제의 전체 조립은 기본 탐색이 더 빨랐다.

그 뒤 실험용 모델 사본을 삭제하고, 저장된 조립 결과로 `body-execute`를 실행했다.
실제 실행 파일을 두 번 실행해 별도로 선언한 10개 사례를 모두 통과했다. 이 중 입력
4개는 소스의 출력 사례에 없던 값이다. `9007199254740993`과
`±9007199254740995`, `18014398509481990`은 int64 그대로 확인했다.

## 메모리와 실행 비용

모델은 6,218개 FP32 매개변수, 가중치 값 24,872바이트, JSON 파일 72,482바이트다.
전체 프로세스의 최대 RSS에는 모델 외에 파서·컴파일러·Go 빌드 비용도 포함된다.

| 명령 | 전체 wall | user + system | 최대 RSS |
| --- | ---: | ---: | ---: |
| 입력 살펴보기 | 0.01s | 0.00s + 0.00s | 21,381,120B |
| 기본 조립 | 0.00s | 0.00s + 0.00s | 19,808,256B |
| 조건 모델 조립 | 0.01s | 0.00s + 0.00s | 21,970,944B |
| 저장 결과의 빌드·실행 | 0.90s | 0.15s + 0.14s | 86,589,440B |

위 표는 `/usr/bin/time -l`의 반올림된 원본 값이다. 0.00s는 시간이 들지 않았다는 뜻이
아니다. 네이티브 빌드 자체의 관측은 wall 498.313ms, user 127.915ms, system 118.034ms다.
호스트 전체 CPU 사용률의 증가는 측정하지 않았다. 캐시와 실행 순서를 통제한 성능 비교도
아니다. 원본 `.time` 파일을 함께 둔다.

## 원본과 읽기 전용 재집계

- 컴파일러: `35851648ee237837841905bb4c35c35db3298f00`, 수정 없는 소스에서 빌드.
- 런타임: 공개 `v0.2.30-experimental`, Go `1.27.2`, 로컬 대체 모듈 없음.
- 모델: [v0.2.29 공개 파일](https://github.com/kimjooyoon/gooo-decision-runtime/releases/tag/v0.2.29-experimental).
  SHA256 `a16696ed44c668f38cc2e7ee1dc6ff3f4716649d57e59df7c9490d1c670edc48`.
- `preflight.json.gz`, `deterministic.json.gz`, `condition.json.gz`는 `gzip -n`으로 압축했고,
  풀어낸 바이트를 최초 관측과 비교했다. 초기 입력의 256개 FP32 특징은 실제 모델이 받은
  특징 해시와 같다. 초기 조건 관측 구간은 비어 있다.
- `source.gooo.gz`도 같은 방식으로 원본 바이트와 비교했다. 보관용 스냅샷을 압축해
  현재 언어 코퍼스에 별도 실행 단위로 중복 등록되지 않게 한다. 직접 실행할 예제와
  집중 CLI 검사는 `examples/body-codegen/source-condition-model.gooo.fixture`를 사용한다.
- `native-observation.json`은 원본에서 뽑은 관측이다. 로컬 Go 경로와 부모·완전성 페이로드를
  제외했다. 생략한 필드와 원본 전체 파일의 해시를 명시했다. 전체 원본 영수증을 대신하는
  재검증 자료로 취급하지 않는다. 공개된 조립 원본과 이 관측으로 수치와 출처를 재집계한다.

저장소 루트에서 다음 명령은 저장된 파일만 읽는다. 모델 호출·학습·네이티브 실행을 하지 않는다.

```sh
GOWORK=off GOTOOLCHAIN=go1.27.2 go run \
  ./docs/research/condition-model-cli-20261010/audit \
  docs/research/condition-model-cli-20261010/result
```

`result/SHA256SUMS`는 공개 파일 바이트를 식별한다. 재집계는 소스/모델/생산자 식별,
입력 특징의 실제 바이트, 모델 호출 및 경로 수, 실제 실패 조건, 정확한 int64 출력,
독립 입력 수와 실행 완료 기록을 확인한다. 최초 생성·실행을 다시 수행하지 않는다.

## 현재 범위와 다음 문제

학습과 이전 연구에서 다룬 절댓값 계열의 문제다. 출력 9/9, 조건 3/3, 실행 10/10은
각각 선언한 유한 사례에 대한 관측이다. 모든 자연어 의도나 모든 입력에 대한 완전성을
뜻하지 않는다. 영수증의 기존 `TRAINING_COMPLETE` 이름은 여기서는 선택용 사례를
충족했다는 검색 상태이며, 이번 실행의 모델 학습 횟수는 0이다.

이번 연결로 Gooo가 소스의 의도와 관측을 바탕으로 자체 모델을 사용할 수 있게 됐다.
다음 언어 작업은 지역 변수의 범위, 중첩 조건, 여러 활동 사이의 선택을 명확히 표현하는
것이다. 해당 표현을 확장한 뒤 서로 다른 기능의 문제와 한영 의도로 학습·평가를 나눠야 한다.
출력 실패와 CI 결과를 모델 입력으로 표현하는 채널도 아직 남아 있다.
