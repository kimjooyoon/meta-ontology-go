# 같은 실패 과제의 두 표현을 실제 컴파일러로 조립

2026-10-10. 공개 SDK0.2.34의 v5 모델을 그대로 읽어 Gooo 본문을 조립했습니다.
깨끗한 생산자 `449b45c103e23903e5839f38f2ba42e945d8f993`, Go1.27.2,
공개 모듈 SDK0.2.34를 사용했습니다. 가중치 변경이나 재학습은 없습니다.

## 다르게 적은 같은 코드

SDK 학습 비교에서 이미 관측한 `max-k11-r1-w1` 과제를 가져왔습니다. 직접 반환 형태와
분기 뒤 값을 복사하고 원래 변수를 덮어쓴 뒤 복사본을 반환하는 형태입니다.
두 소스에 같은 `Main → Choose` 연결을 붙였습니다. 이 과제는 새 모델의 실패를
살펴보려고 선택했으며 새로운 문제의 정확도로 해석하지 않습니다.

두 Gooo 파일의 소스 해시는 다릅니다. 비교·분기 선택의384칸 v5 입력은 두 형태에서
각각 완전히 같았고, 사전 조회의 배열 해시가 실제 첫 판단의 배열 해시와 일치했습니다.
사전 조회는 판단이나 후보 사례 검사를 수행하지 않았습니다.

## 모델을 썼을 때 더 많은 시도가 필요했다

| 관측 | 직접 반환 | 분기 뒤 복사 |
| --- | ---: | ---: |
| 모델 없는 후보 시도 |1|1|
| 모델의 첫 판단을 쓴 후보 시도 |2|2|
| 실패를 다시 전달한 후보 시도 |2|2|
| 첫 모델 판단 |15.083µs|14.208µs|
| 모델 없는 전체 코드 조립 |0.665ms|1.004ms|
| 모델 읽기를 포함한 코드 조립 |3.174ms|3.646ms|
| 피드백 포함 코드 조립 |3.224ms|3.600ms|

원래 후보0이 사례를 통과했습니다. 모델은 후보2를 먼저 골랐고, 틀린 출력이 나온 뒤
다음 후보0으로 완성했습니다. 실패를 다시 주어도 모델의 최고 후보는2였습니다.
탐색기는 이미 검사한 후보를 재실행하지 않았습니다. 추가 판단은 각각13.916µs와
14.042µs였으며 시도 수를 줄이지 못했습니다. 단일 명령씩의 관측입니다.

각 최종 본문은 소스의 출력8개·조건3개 사례를 모두 충족했습니다. 큰 정수는
`9007199254740993`, `±9007199254740995`, `18014398509481990`를 정확하게 유지합니다.
표현을 일관되게 읽는 것과 좋은 첫 선택을 하는 것은 따로 확인할 항목입니다.

## 저장 후 모델 없이 실행

각 형태를 실제 Go 프로그램으로 조립해 별도8개 사례를 실행했습니다. 그 뒤 소유한
모델 사본을 지우고 저장 구성을 다시 실행했습니다. 두 형태 모두 조립·재실행 각각8/8을
통과했고, 재실행의 새 모델 호출은0회였습니다. 재실행은 저장된 실행 파일을 재사용했습니다.
