# Gooo의 다음 기원 조회: 좁은 비교와 구현 후보

2026-10-14. 공식 자료의 동작과 Gooo 개발 소스의 현재 동작을 구분한 조사다.
성능·사용자 수·언어 성숙도 순위는 측정하지 않았다. 첫 번째 ID 조회는 이번 개발 소스에서 구현하고, 두 번째·세 번째 항목은 후속 설계로 둔다.

## 공식 자료에서 확인한 세 가지

| 자료 | 확인한 동작 | Gooo에 적용할 후보 |
| --- | --- | --- |
| [TypeQL cardinality](https://typedb.com/docs/core-concepts/typeql/constraining-data/) | 관계 역할과 소유 관계의 수를 스키마에 선언한다. 상속한 제약과 직접 선언한 제약을 함께 만족해야 한다. | 기원 연결의 역할·수가 무엇을 뜻하는지 명시하고, 같은 모양의 값도 활동·필드 ID로 구별한다. |
| [CUE validation](https://cuelang.org/docs/concept/how-cue-enables-data-validation/) | 서로 충돌하는 데이터와 제약의 파일 위치를 오류에 함께 보여 준다. | 거절된 조립 후보에서 필드·선택 선언과 실패한 소스 사례의 위치를 함께 보여 준다. |
| [Soufflé provenance](https://souffle-lang.github.io/provenance) | 요청 시 설명 트리를 구성하며, 깊이를 제한한 부분과 나중에 펼칠 부분을 표시한다. | 특정 주체부터 기원을 조회하고, 깊이·페이지·기록 한계를 별도 상태로 유지한다. |

TypeQL은 관계 데이터의 제약, CUE는 데이터와 제약의 통합, Soufflé는 Datalog
튜플의 도출 설명을 다룬다. Gooo는 작성한 계산·허용된 조립 선택·생성 결과를
이어 보는 실행 언어를 개발하고 있다. 위 표는 가져올 원리에 관한 해석이다.
세 언어의 전체 실행 모델을 도입한다는 계획은 아니다.

## 현재 Gooo 소스와 맞닿는 부분

기준은 PR1560의 고정 소스 `792848f600e9229e70a9954262e1fa40ce130371`이다.

- `internal/bodyexecution/native_origin_input.go`: 저장 기록 검증 뒤 종류·행 범위로 조회한다.
- `internal/bodyexecution/native_field_file_facts.go`: 원래 파일의 필드 대상·값·조립 대안 행을 만든다.
- `internal/bodycodegen/record_choice_origin.go`: 선택된 필드 식의 선택 ID와 본문 범위를 보존한다.
- `examples/record-choice-origins/inspect.gooo`: 전달받은 위치를 Gooo 조건식으로 분류한다.
- `examples/native-field-lineage`와 `examples/local-field-bridge`: Gooo가 기록된 부모 연결을 순회한다.

실제 동작 범위는 소스 설명과 저장 관찰로 읽는다. 필드 기원과 원본 위치가
남아 있는 비율, 후보 사례의 결과 일치율, 원래 생산자의 정확도는 별개의 질문이다.

## 다음으로 구현할 작은 단위

### 1. 필드 ID에서 조회 시작하기

앞선 조회는 행 번호를 알아야 원하는 기원에 접근하기 쉬웠다. 이번 개발 소스는
필드·활동·진입 활동의 고유 ID를 받아 페이지 선택 전에 해당 주체를 고른다.

Go는 정확한 ID로 기록을 고르고, Gooo는 받은 행을 해석한다. 조회 결과는 필터
전 전체 수와 선택한 주체의 행 수, 반환 행 수를 구분해야 한다. 다른 종류의
기록에 맞지 않는 필터는 진단하고, 원래 생산 프로그램·모델은 실행하지 않는다.
이름 변경과 같은 값의 다른 필드, 빈 결과, 부분 페이지가 필요한 새 사례다.

### 2. 거절된 선택의 두 위치 연결하기

현재 선택된 대안은 원래 선언 위치로 돌아갈 수 있다. 다음에는 실패한 필드에
대해 원래 대안과 실패한 `value_case`의 위치를 함께 보이는 것을 검토한다.
기존 인터프리터 결과를 읽는 조회와 새 후보 평가를 구분한다.

새 지표는 거절된 필드 중 두 위치가 모두 연결된 수 / 해당 거절 필드 수다.
분모가 없으면 미측정으로 둔다. 이 값은 후보의 기능 정확도와 합치지 않는다.
처음에는 한 활동·명시적인 필드 선택·값 사례에 한정하고, 한글·영문 표기와
이스케이프·파일 분리·표시 이름 변경 후에도 ID와 위치가 유지되는지 살핀다.

### 3. 필요한 부모 연결만 펼치기

선택한 쓰기 주체와 최대 깊이를 받아 부모 연결을 따라간다. 아직 펼치지 않은
부분, 기록되지 않은 부모, 실제 입력에 닿은 부분을 다른 상태로 남긴다.
순환·단절·같은 값의 다른 주체를 새 입력으로 확인해야 한다.

Gooo의 순차 실행 기록은 튜플의 논리 도출과 의미가 다르다. 여기서는 기록된
필드 복사·도우미 반환 연결을 펼치는 범위로 시작한다. 완전한 인과 설명은
구현 범위와 관찰이 추가될 때마다 따로 명시한다.

## 모델과 학습

첫 구현은 ID 조회와 선언된 Gooo 규칙으로 진행한다. 이후 작은 결정 모델이
여러 조회 행동의 시도 순서를 제안하도록 실험할 수 있다. 허용한 행동·실제
선택·연결된 원본을 기록하고, 모델이 없으면 고정 순서를 따른다. 자연어 생성이나
대규모 학습은 위 세 작업의 선행 조건이 아니다. 이번 조사는 모델을 실행하거나
학습하지 않았다.
