# 학습한 작은 모델을 Gooo CLI에 직접 넣은 기록

SDK 0.2.35의 공개 가중치를 그대로 읽고, 실제 컴파일러로 30개 명령을 실행했습니다.
큰 값 선택의 성공 사례, 작은 값 선택의 회귀 사례, 중첩 분기 회귀를 미리 골랐습니다.
앞의 두 과제는 직접 반환과 분기 뒤 복사라는 두 표현을 각각 사용했습니다.
모델의 새 일반 정확도를 재는 표본이 아니라 연결과 실패 후 진행을 확인하는 사례입니다.

## 선택과 완성

| 사례 | 고정 순서 후보 수 | 모델 후보 수 | 피드백 사용 후보 수 | 모델 첫 선택 |
| --- | ---: | ---: | ---: | --- |
| 큰 값, 직접 반환 | 1 | 1 | 1 | 통과 |
| 큰 값, 분기 뒤 복사 | 1 | 1 | 1 | 통과 |
| 작은 값, 직접 반환 | 1 | 2 | 2 | 실패 |
| 작은 값, 분기 뒤 복사 | 1 | 2 | 2 | 실패 |
| 중첩 분기 | 3 | 2 | 2 | 실패 |
| 합계 | 7 | 8 | 8 | 2/5 |

작은 값을 골라야 하는 두 사례에서는 큰 값을 반환하는 후보를 먼저 선택했습니다.
실패를 받은 뒤에도 같은 후보가 가장 높은 점수를 받았습니다. 탐색기가 이미 검사한
후보를 제외하고 다음 후보로 진행해 완성했습니다. 중첩 분기도 첫 선택은 틀렸지만
고정 순서보다 후보 하나를 덜 검사했습니다. 피드백은 총 3번의 호출을 더 만들었고
이번 사례의 후보 수를 줄이지 못했습니다.

세 조립 방식은 각각 다섯 소스의 출력 40/40개와 조건 15/15개를 통과했습니다.
그 뒤 `Main → Choose`를 실제 Go 프로그램으로 만들어 별도 사례 **40/40개**를 통과했습니다.
각 모델 복사본을 삭제한 뒤 저장된 구성을 실행해 다시 **40/40개**를 통과했습니다.
저장 재실행의 새 모델 호출은 0회였고, 이미 빌드한 실행 파일을 재사용했습니다.
정확한 정수 `-9007199254740995`, `9007199254740993`, `9007199254740995`,
`18014398509481990`을 원본과 검산에 유지했습니다.

## 입력이 실제 판단까지 이어졌는가

`body-context --model`은 파일의 v6 입력 버전을 자동으로 읽었습니다. 사전 확인의
모델 판단·후보 검사는 0회였습니다. 내보낸 배열은 실제 첫 판단의 해시와 같았고,
모든 첫 입력·선택·출력·조건 결과가 앞서 저장한 SDK 관찰과 일치했습니다.
이 비교에서 이전 SDK 판단을 다시 실행하지 않았습니다.

직접 반환과 복사 표현은 두 과제 모두 같은 입력 배열을 사용했습니다. 중첩 분기는
정규화 범위 밖이라는 표시와 원래 입력을 유지했습니다. 초기 입력의 관찰 칸은
비어 있었고, 아직 실행하지 않은 후보의 실패를 미리 전달하지 않았습니다.
새 계산 형식과 가중치의 식별값은 사전 확인·조립·저장된 구성에서 유지됐습니다.

## 이번 실행의 시간과 메모리

| 사례 | 고정 순서 조립 | 모델 조립 | 모델의 첫 판단 |
| --- | ---: | ---: | ---: |
| 큰 값, 직접 반환 | 0.676ms | 3.146ms | 16.500µs |
| 큰 값, 복사 | 1.018ms | 3.618ms | 16.375µs |
| 작은 값, 직접 반환 | 0.722ms | 3.457ms | 16.416µs |
| 작은 값, 복사 | 1.019ms | 3.685ms | 16.708µs |
| 중첩 분기 | 0.998ms | 3.557ms | 16.583µs |

조립 시간에는 파일 읽기·모델 읽기·소스 분석·후보 확인이 포함됩니다. 작은 예제에서는
고정 순서가 더 빨랐습니다. 각 명령을 한 번만 실행한 관찰이며 반복 성능 비교는 아닙니다.
네이티브 빌드와 재실행까지 포함한 30개 명령의 관측 시간을 합하면 실제 시간 6.67초,
사용자 CPU 2.20초, 시스템 CPU 1.66초입니다. 반올림된 값으로 평균 약 0.58개 CPU 코어
사용에 해당합니다. 명령들 중 최대 RSS는 87,867,392바이트(약 83.8MiB)였습니다.
PC 전체 이용률 상승분이나 모델만의 메모리를 측정한 값은 아닙니다.

모델 호출은 총 18회, 네이티브 실행 프로세스는 20개였습니다. 학습과 가중치 수정은 0회입니다.
