# 호출자 결과로 조건·분기를 다시 조립한 관측

2026-10-10 KST. 실제 컴파일러 생산자는 깨끗한 개발 소스
`ce430158302b9b472057582d1a83ab66760446fc`, Go1.27.2, SDK0.2.26입니다.
버전 표시는 0.6.23-dev이며 immutable 공개0.6.23의 소스2b와 구분합니다.
공개 파일에 같은 새 예제를 넣은 원본 실행은 typed-path 계약을 받지 못해 실패했습니다.
새 실행·저장 재생은 위 개발 생산자로 수행했습니다.

| 예제 | 프로그램 시도 | 선택 본문의 지역 사례 | 조립용 호출 | 별도 평가 입력 | 초기 모델 호출 | 재생의 새 호출 |
| --- | --- | --- | --- | --- | --- | --- |
| 분기 하나, 모델 생략 | 2 / 후보2 | 1/1 | 1/1 | 3/3 | 0 | 0 |
| 분기 + 레코드, 자체 QAT | 15 / 후보16 | 2/2 | 1/1 | 3/3 | 1 | 0 |

두 초기 프로그램의 조립용 호출은 0/1이었습니다. 첫 예제는 함수 자체의
`0 -> 0` 사례로 두 분기를 구분할 수 없어서 호출자 `3 -> 6` 기대값으로 다시 골랐습니다.
혼합 예제는 분기를 다시 고르면서 레코드 필드 선택도 조합합니다. 지역 점수2/2는
두 함수에 적힌 사례의 수입니다. 필드 수나 반복 실행 수를 더해 만든 평가 점수가 아닙니다.

혼합 예제의 기존 자체 모델은 세 레코드 선택을 판단했습니다. 한 결정만 있는 분기
본문에는 `THREE_DECISION_COUNT_UNSUPPORTED`를 기록하고 결정론적으로 진행했습니다.
그 뒤 15개의 프로그램 후보를 실행하는 동안 새 모델을 호출하지 않았습니다.
모델 metadata/weights SHA와 실제 `model_calls: 1`이 원본 초기 기록에 있습니다.
이 자료는 모델이 분기 의미를 학습했다는 근거로 사용하지 않습니다.

## 시간과 리소스 관측

모델을 생략한 전체 조립·최종 평가 CLI는 wall1.63초,
혼합 모델 CLI는 wall8.20초였습니다. 후자는 후보15개를 구성·컴파일·실행한 시간입니다.
그 안의 레코드 모델 예측 타이머는 12,834ns, 보존 텐서는2,096bytes였습니다.
time-l 원본의 max RSS는 각각87,670,784bytes와88,408,064bytes입니다.
이 메모리 값은 CLI 리소스 관측이고, 텐서 크기와 다른 범위입니다.
공유 호스트의 한 실행이며 시스템 전체 CPU 이용률과 별도 추론 벤치마크는 측정하지 않았습니다.

별도 평가의 루트 입력은7, -5, `9007199254740993`이며 조립용3과 겹치지 않습니다.
모델 학습 노출은 확인하지 않았습니다. 알려진 후보와 이 입력의 유한한 동작을 관측합니다.
