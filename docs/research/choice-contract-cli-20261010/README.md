# 선택별 사례 모델을 컴파일러에서 사용하기

공개 SDK0.2.37의 `model-choice-v1.json`을 Gooo 개발 컴파일러에 연결했습니다.
이 모델은 각 선택 지점의 소스를 반영해 작성 사례를 읽고, 먼저 시도할 경로를 고릅니다.
모델의 제안 뒤에는 컴파일러가 모든 출력과 조건 사례를 검사합니다.

SDK 실험에 이미 공개한 세 예제로 입력 확인, 고정 순서 구성, 모델 구성, 네이티브 구성,
저장 재실행을 각각 한 번씩 진행했습니다. 두 경계값 예제는 같은 본문에 서로 다른 목표를
선언합니다. 곱셈 예제는 앞선 SDK 실험에서 선택별 모델이 퇴보했던 경우입니다.
세 예제 모두 앞선 학습 32개에는 포함되지 않았지만, 기존 실험에서 이미 결과를 본 사례입니다.
이번 관측의 범위는 실제 컴파일러 연결입니다.

## 결과

| 공개 예제 | 고정 순서 시도 | 모델 시도 | 고정 순서 구성 | 모델 구성 |
| --- | ---: | ---: | ---: | ---: |
| fresh-bound-k9-r1-w0-alias-g0 | 3 | 1 | 1.562ms | 5.199ms |
| fresh-bound-k9-r1-w0-alias-g1 | 1 | 1 | 1.031ms | 4.472ms |
| fresh-scale-k9-r1-w0-direct-g1 | 1 | 2 | 0.861ms | 4.255ms |

후보 시도는 합계 5→4회, 첫 선택에서 모든 사례를 만족한 예제는 양쪽 모두 2/3이었습니다.
경계값 목표 하나는 개선됐고 곱셈 목표는 한 번 더 시도했습니다. 최종 소스 출력은
각각 24/24개, 조건은 각각 9/9개를 통과했습니다. 별도 네이티브 구성의 평가와 저장
재실행 평가도 각각 24/24개 출력 사례를 통과했습니다.

모델은 소스에 작성된 출력 사례 8개를 모두 입력으로 받습니다. 네이티브 평가도 같은
8개로 실행해 실제 프로그램과 소스 요구의 일치를 확인합니다. 네이티브 구성을 위한
호출자 사례에는 그중 두 번째 사례 한 개를 사용했습니다.

모델 판단은 45.000~64.375µs, 세 값의 중앙값은 46.250µs였습니다. 모델을 읽는 데
3.090~3.605ms가 걸려 전체 구성은 고정 순서보다 길었습니다. 위 구성 시간에는 소스
연결, 파일 읽기, 후보 검사와 최종 출력이 포함됩니다. 작은 세 사례의 단회 관측입니다.

15개 명령의 전체 과정은 wall 4.08초, user 1.50초, system 1.11초였습니다.
최대 RSS는 88,326,144바이트(84.23MiB), swap은 0회였습니다. 네이티브 Go 도구 실행을
포함한 수치이며, 모델의 FP32 가중치 배열은 51,272바이트입니다. 평균 약 0.64개 CPU
코어 사용에 해당합니다. PC 전체 이용률의 증가분은 이 관측에서 측정하지 않았습니다.

## 호출과 검증

- 사전 입력 확인에서는 모델 판단과 후보 실행 모두 0회였습니다.
- 모델 코드 구성과 네이티브 구성은 각각 예제당 초기 판단 1회, 합계 6회였습니다.
- 후보가 실패한 뒤의 탐색에는 추가 판단이 없었습니다. 매 시도에서 출력 8개와 조건
  3개를 모두 검사했습니다.
- 각 네이티브 구성이 끝나면 해당 예제의 모델 복사본을 삭제했습니다. 저장된 구성은
  모델 호출 0회로 다시 실행됐고, 저장 내용과 실제 정수 출력이 일치했습니다.
- `9007199254740995`, `-9007199254740995`, `18014398509481990`을 포함한 큰 정수를
  원래 선언, 모델 입력 특징, 후보 결과, 네이티브 출력에서 정확히 비교했습니다.

## 재검산 자료

[프로토콜](protocol.txt)과 [실행기](producer/main.go)는 실행 전 커밋
`5aef77867df5d9568621b83fcd548d5771744059`에 고정했습니다. 깨끗한 같은 소스에서
Go1.27.2로 컴파일러를 빌드했고, 공개 모듈 `v0.2.37-experimental`을 사용했습니다.
모델 SHA256은 `aa81790884cd21ac9dd435fe5cf14b604cdd658f514f6460a526fc858ae07ab1`입니다.
32개 학습과 388개 문서 실험을 재실행하거나 가중치를 바꾸지 않았습니다.

[결과](result/audit.json), [체크섬](result/SHA256SUMS), 원래 명령과 종료 상태,
stdout, 자원 기록, 저장된 구성 파일을 보관합니다. 압축은 `gzip -n`으로 만들고
압축 해제한 바이트가 원본과 같은지 확인했습니다.
[검산기](audit/main.go)는 이 파일만 읽으며 모델 판단과 프로그램 실행을 새로 하지 않습니다.
입력 배열, 정확한 정수 값, 매 후보의 출력·조건 결과, 진행 연결과 저장 재실행을 확인합니다.
정수 1 차이, 기대값 동시 변경, 특징 배열, 판단 연결, 후보 결과, 조건 결과, 모델 형식을
변형했을 때 거부하는 테스트를 포함합니다.

연결 구현의 집중 검사와 425개 패키지 전체 순차 race 검사, 정적 검사, billing 예제는
통과했습니다. 처음 전체 검사를 병렬 실행했을 때는 네이티브 실행을 포함한 네 패키지가
기존 2초 제한에 걸렸습니다. 그 [실패 기록](result/choice-compiler-full-race.txt.gz)과
[순차 검사 기록](result/choice-compiler-serial-race.txt.gz)을 함께 남깁니다. 시간 제한과
검증 조건은 바꾸지 않았습니다. 새 기록 검산기는 별도로 race 검사를 통과했습니다.

실행 방법과 지원 형식은 [사례 판단 모델 사용법](../../declared-contract-model.md)에 있습니다.
설치된 공개 컴파일러 0.6.25는 그대로이며, 이 문서는 개발 소스의 연결 관측을 설명합니다.
