# Typed paths in caller-guided construction

2026-10-10 KST. This extension follows public Gooo 0.6.23 and the accepted
workbench concise construction output. Keep the public release's original
producer identity; these new observations describe a later development source.

## Problem and design

`body-compose` can choose conditions, local references, assignment targets,
branch layout and statement order. Previously `body-construct` rejected those
bodies when a caller wanted to reconsider a locally satisfactory helper.
Extend the existing native joint constructor with source-owned typed masks.
Source cases remain obligations; caller examples become explicit construction
feedback; later evaluation inputs are scored separately.

The initial selected body is first. Subsequent typed masks use fallback distance
and numeric order within the source budget. That declared continuation policy
keeps the historical initial model judgment intact, including encoded context,
and requires no new inference. Combined edits still typecheck as one program.
Each complete source combination is immediately executed with the caller suite.
Rejected local combinations consume attempts and have no caller observation.

v7 receipts record candidate palettes, local actuals, source/plan identities and
rejected combinations. Replay reconstructs every bounded mask and its results,
including native integer faults, before evaluating the saved selected program.
v1..v6 behavior remains unchanged. A finite score retains its measured inputs.

## Checks and limits

- Begin with a failing regression against the previous typed-body preflight.
- Reopen an ambiguous branch using an actual caller expectation.
- Observe source/program limits and conflicting source/caller expectations.
- Reproduce rejection of interacting declaration order and local-reference edits.
- Mix record choices and typed branches in one search.
- Retain native caller zero-divisor outcomes under v7 and replay them.
- Reject altered masks, source identities, local results, palette bounds and schema.
- Preserve exact input `9007199254740993` in CLI and saved replay.
- Exercise optional model use with existing own small weights, without downloading
  a larger model. Record which body receives inference and representation declines.

The branch fixture uses `0 - input`: unary variable negation is supported by
ordinary Gooo but recipe expansion currently accepts only negative literals.
Extending that spelling requires preserving source binding and existing arena
indices; it is a separate follow-up. Typed-path helpers currently remain pure
Integer -> Integer bodies within the existing 16-decision/128-node bounds.

[Original observations](typed-path-caller-20261010/README.md) record the clean
development producer, fixed and mixed own-model executions, separate input
scores, model representation decline and saved replay. The local fixtures passed
their finite checks; the current public0.6.23 tag keeps its earlier producer.

## External ideas and decisions

Recent Hacker News and GeekNews reading led to these source checks. These are
design decisions for Gooo, rather than measured superiority over those projects.

| Source | Applied or deferred |
| --- | --- |
| [Meadows](https://github.com/lorezzed/meadows) | Keep compiler graph data available to other tools. Extend native candidate receipts, preserving the compiler's source authority. |
| [Once](https://github.com/alex0ptr/once) | Continue using an earlier command result. Saved programs are rebound and replayed for new inputs; a time-based successful-output cache is deferred. |
| [Carson Gross, Yes, and…](https://htmx.org/essays/yes-and/) · 2026-02-27 | Readability and controlling complexity inform small, inspectable construction choices. The compiler emits selected Gooo and generated Go alongside the observations. |
| [Michael Lynch, Anti-Patterns in Software Blogging](https://refactoringenglish.com/blog/anti-patterns-software-blogging/) · 2026-10-07 | Start with a short runnable example and explain which result the reader can obtain. The accepted workbench already separates short output from full JSON. |

Large general-purpose model training, another desktop framework and new
efficiency dashboards are deferred. Current work extends what the language can
express and what callers can construct with its existing small model profiles.
