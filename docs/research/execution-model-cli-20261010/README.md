# Gooo 전용 출력 피드백 모델을 CLI에서 사용한 기록

2026-10-10 macOS arm64에서 실제로 실행했습니다. 생산자는 깨끗한 소스
`9c7d5bc76735eb33db032646082240eb16a1cefc`, Go1.27.2, 공개 SDK0.2.32입니다.
이 커밋은 기존 컴파일러 PR1441 위에서 작업한 후속 개발 소스입니다.
공개0.6.25 설치본의 측정값으로 읽으면 안 됩니다.

사용한 가중치는 [SDK PR24의 원본 모델](https://github.com/kimjooyoon/gooo-decision-runtime/blob/5a2b2d55fa5e05e1cf4f06e855f4e27ec25a3da4/studies/execution-feedback-learning-20261010/result/model-v3_output_on.json)입니다.
JSON90,501바이트, 가중치 값31,016바이트이며 파일 SHA256은
`7827d36a64ce72ee9d880f7e6bdb9b29f3cfba34d02d435781df4bf034dd789c`입니다.
다시 학습하거나 가중치를 변경하지 않았습니다.

## 어떤 작업에 썼나

`max(input, 10)`을 만들도록 한영 의도와 선택지 두 개를 Gooo에 적었습니다.
입력과10의 비교 순서, 두 분기의 배치를 고르는 문제입니다.
소스에 출력 사례6개와 조건 사례3개, 시도 예산4개를 선언했습니다.
큰 정수 `9007199254740993`, `±9007199254740995`, `18014398509481990`도 포함합니다.
[실행 가능한 예제](../../../examples/body-codegen/source-output-feedback.gooo.fixture)를 함께 두었습니다.

모델 학습에는 상수가7·13인 관련 최대·최소 형태가 들어 있습니다. 이 기록의 목적은
공개 가중치를 실제 컴파일러에서 사용하는 것입니다. 새로운 분야의 정확도 평가로
삼지는 않습니다. 명령6개를 아래 순서대로 한 번씩 실행했고 실패 결과도 보존하도록
[실행 전 계획](result/protocol.txt)을 고정했습니다.

## 조립 결과

| 방식 | 시도한 본문 | 모델 호출 | 추가 피드백 호출 | CLI 내부 전체 조립 시간 |
| --- | ---: | ---: | ---: | ---: |
| 모델 없음 | 3 | 0 | 0 | 0.705916ms |
| 첫 판단만 사용 | 1 | 1 | 0 | 2.820542ms |
| 출력 피드백 허용 | 1 | 1 | 0 | 2.712000ms |

모두 소스의 출력6개와 조건3개를 만족했습니다. 두 모델 실행 모두 첫 판단에서 맞는
조합을 선택했으므로 추가 피드백을 호출하지 않았습니다. 이번 기록만으로 출력
피드백의 효과를 주장할 수는 없습니다. 출력만 틀린 경우의 실제 연결은 별도의
배선 검사에서 확인했고, 학습한 모델의 반복 피드백 성적은 SDK128개 소스 실험에 있습니다.

첫 판단 시간은 각각12.125µs,10.708µs였습니다. 모델 읽기는1.874292ms,1.799000ms로,
이번처럼 작은 본문에서는 읽기 비용이 경로 두 개를 덜 검사한 이득보다 컸습니다.
각 행은 한 번의 관측입니다. 반복 평균이나 백분위수가 아닙니다.

`body-context`는 판단·후보 검사0회로 입력을 내보냈습니다.320개 FP32 값의
1,280바이트 해시가 실제 판단 기록과 같았고, 첫 입력의 출력 관측 구간은 모두0입니다.
판단 전에 정답 출력이나 아직 실행하지 않은 후보의 실패를 넣지 않았습니다.

## 조립한 프로그램 실행과 저장 재실행

`Main`은 조립된 `Choose`를 호출합니다. 호출자 조립 사례는11 한 개이며, 별도 실행
사례8개에는 -11,9,10,11과 큰 정수들을 넣었습니다. 일부 입력은 소스 사례 또는 호출자
사례와 겹치므로8개 모두를 미관측 사례라고 세지 않습니다.

`body-construct`의 일반 초기 모델 선택으로 구성하고8/8개 실행 사례를 통과했습니다.
로컬에 복사한 모델 파일을 지운 뒤 저장된 구성을 다시 실행해8/8개를 통과했고,
새 모델 호출은0회였습니다. 각 최종 실행 관측에는 종료 코드0인 실제 프로세스2개가
남아 있습니다. 저장 재실행은 실행 파일 캐시를 재사용해 빌드 프로세스를 새로 만들지
않았으며, 이를 새 빌드로 세지 않습니다.

| 명령 | 외부 벽시계 | 사용자 CPU | 시스템 CPU | 최대 RSS |
| --- | ---: | ---: | ---: | ---: |
| 처음 구성·실행 | 0.86초 | 0.27초 | 0.21초 | 87,818,240바이트 |
| 저장 구성 재실행 | 0.33초 | 0.16초 | 0.11초 | 86,769,664바이트 |

이 명령들은 Go 빌드·프로그램 실행을 포함합니다. RSS를 모델만의 메모리로 읽으면
안 됩니다. CPU 합/벽시계는 각각 약0.56·0.82개 코어 분량입니다. PC 전체 CPU 사용률
상승분은 측정하지 않았습니다. 짧은 codegen 명령의 외부 시간은0.00초로 반올림되어
그 값으로 처리량을 계산하지 않습니다. 해당 명령의 최대 RSS는 약21.0~21.8MB였습니다.

## 원본과 재집계

`result/`의 stdout·저장 구성·소스는 `gzip -n`으로 압축한 뒤 원본과 바이트 비교했습니다.
`.gooo.gz`는 과거 관측을 보관한 파일이며 컴파일러의 활성 예제 목록에 추가하지 않습니다.
모델은 별도 공개 원본 링크와 해시로 식별하고, 사용 후 지운 로컬 복사본을 다시 만들지
않았습니다. 생성자 신원과 명령별 시간·RSS, 완료 목록도 보관합니다.

```sh
go run ./docs/research/execution-model-cli-20261010/audit \
  docs/research/execution-model-cli-20261010/result
```

이 Go 도구는 저장 기록만 읽습니다. 모델 판단, 본문 평가, 네이티브 실행을 추가하지
않습니다. 정확한 정수, 모델·소스 신원, 첫 입력의 배열 해시, 사례 통과, 호출 수와
저장 구성의 내용을 확인합니다. 저장 JSON과 stdout은 들여쓰기가 달라 RawMessage의
공백을 JSON 직렬화로 정규화해 비교합니다. 원본 파일 자체는 변경하지 않습니다.

연결 테스트와 관련 패키지 전체 race 검사, 정적 검사를 통과했습니다. 분해 검사도
실제 변환기로 수행해 바뀐 논리 파일7개의 생성 결과가 각75줄 이내임을 확인했습니다.
이 시점에는 후속 컴파일러 소스를 아직 원격 CI에 제출하지 않았습니다.
