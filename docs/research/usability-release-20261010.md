# 입력부터 시작하는 Gooo 사용 흐름

2026-10-10 KST에 Hacker News, GeekNews, GitHub Trending을 다시 읽고,
관련 프로젝트의 원문을 확인했습니다. Trending 조회에는 저장소 목록이
나오지 않아 순위나 인기를 근거로 삼지 않았습니다.

## 지금 줄이는 불편

새 작업장은 네이티브 계획을 읽지만 공개 0.6.22 실행 파일에는 조회 명령이
없었습니다. 사용자가 특정 개발 소스를 따로 빌드해야 했습니다.
0.6.23 후보에는 이미 구현된 조회·입력 전용 실행을 넣고, 배포 대상마다
그 흐름을 실제 실행하는 검사를 추가합니다.

사용자는 먼저 필요한 입력을 보고, 입력 파일을 만들고, 실제 값을 실행합니다.
나중에 기대값이 생기면 저장한 프로그램에 테스트를 붙입니다. 설계도에
부품 이름과 연결선을 먼저 적고, 조립한 물건을 같은 작업대에서 다시
확인하는 흐름입니다. 기대값이 없는 단계의 정답률은 미측정으로 남습니다.

이는 Gooo에 적용한 설계 판단입니다. 외부 구현을 가져오거나 해당 프로젝트의
성능을 Gooo의 성능으로 환산하지 않았습니다. 모델이 지원하는 부분은
소스가 선언한 선택의 순서를 제안하는 것입니다. 생성·실행 기록에서
호출 수와 본문 선택을 별도로 확인할 수 있습니다.

## 덜어내고 보류하는 것

공개 기능을 쓰기 위한 별도 개발 빌드 준비 단계를 줄입니다. 저장된 결과의
다음 작업을 시작할 때 이미 있는 원본과 입력을 다시 작성하는 부담도 줄입니다.
큰 모델의 상시 연결, 시간만으로 유효성을 정하는 캐시, 별도 시각화 프레임워크는
현재 범위에서 보류합니다. 사용자의 입력 관측에 기대값을 자동으로 붙이는
방식도 적용하지 않습니다. 테스트는 호출자가 정한 의도를 확인할 수 있어야 합니다.

## 확인할 지표와 다음 언어 작업

네 가지 입력 흐름마다 계획과 템플릿을 만들 수 있는지, 원래 입력이 그대로
저장되는지, 생성 결과를 그대로 다시 쓰는지 확인합니다. 입력만 있을 때는
0/0·UNKNOWN이며, 별도 기대값을 넣으면 해당 사례의 통과 수가 생깁니다.
조회의 모델 호출·후보 검사·실행 수는 각각 0입니다. 모델 생성 때의 호출과
실행·재생 때의 새 호출 수를 나눠 기록합니다. 배포 검사에서 이 값이
빠지거나 달라지면 성공으로 집계하지 않습니다.

다음 언어 작업은 typed-path 본문을 다른 본문과 함께 호출자 반례로 다시
조립하는 경로입니다. 현재 실행·저장 재생 기능과 연결하고, 후보 예산이
부족한 결과는 부분 결과로 유지합니다. 사용자가 실패한 원래 입력과
어느 선택을 다시 시도했는지 볼 수 있게 만드는 것이 다음 완성도 기준입니다.
