## 검사 원본과 발견한 문제

- 최초 CLI 테스트는 기존 레코드 전용 제한으로 실패했습니다. 원본을 남기고 typed 사전 확인을 구현했습니다.
- 첫 전체 검사에서 도움말의 기존 `THREE_FIELD_CHOICES_REQUIRED` 예시가 빠진 것을 발견했습니다.
  그 예시를 복구한 최종 전체 race 검사는 본문34.942초·CLI125.578초에서 PASS였습니다.
- 정적 검사, 기존 billing 의미 검사, Go fix 차이 검사와 모델 입력의 네이티브 비교가 통과했습니다.
- 내부 변경 파일 세 개를 12개 생성 파일로 추출한 projection도 모델 사전 확인 race 검사를 통과했습니다.
  큰 기존 `body_paths.go`의 공통 dispatch 정리는 추출에 맞지 않아 작업 범위에서 되돌렸습니다.
  CLI 파일의 별도 추출 관측은 `CALLEE_EFFECTS_UNPROVEN`으로 남습니다. 전역 자동 추출 지원을 주장하지 않습니다.

공개 기존 실행 파일은 일반 분기의 `--model` 사전 확인을 실패로 종료했습니다.
그 원본 종료값과 출력도 보관합니다. 개발 실행 파일은 같은 입력의 표현 거절을 정상 결과로 반환합니다.
기록 비교 중 `context`와 `model_context`를 잘못 읽어 불일치를 보고했다가 필드 확인 후 바로 정정했습니다.
`summary.json`은 올바른 필드와 존재하는 호출 수를 검사한 뒤 작성했습니다.

gzip 파일은 원본을 변경하지 않고 압축한 뒤 해제 바이트를 비교했습니다. `FILES.sha256`이 공개 바이트를 묶습니다.
새 모델 학습·업로드, 원격 서비스 호출 또는 새 공개 릴리스는 이 관측의 작업 범위에 포함되지 않습니다.

## 원본 CI에서 확인한 후속 수정

첫 후보4be의 원본 CI37990072227/attempt1에서 의미 일관성 검사가 실패했습니다.
81줄 도움말의 단일 선언을 자동 분할할 수 없다는 원본 실패였습니다. 도움말을 별도 상수
파일로 옮겨 각각54줄·30줄로 구성하고, CLI 처리를 짧은 함수로 나눴습니다.
그 CLI 세 논리 파일의 새 추출은8개 생성 파일로 통과했고 overlay race 검사도 통과했습니다.
CI와 준비 검사를 취소·재시작하지 않고 각 원본의 정상 종료를 확인했습니다.
첫 전체 CI는 FAILURE, 준비 검사는 SUCCESS였으며
[첫 후보의 최종 원본](ci-4be/README.md)에 실행·job·check suite·실패 로그를 보존합니다.

첫 개발 생산자2ee의 typed 사전 확인은 `model_load_ms: 0`과 `no_model` 단계 이름을 남겼습니다.
실제로는 모델을 읽었고 `model_compatibility.model.setup_ms`가 그 초기화를 기록합니다.
후속 수정은 실제 로드 구간을 측정하고 전체 시간에 포함됐다고 표시하며 예측0회를 유지합니다.
앞선 원본 출력을 바꾸거나 새 생산자로 재표기하지 않습니다.
