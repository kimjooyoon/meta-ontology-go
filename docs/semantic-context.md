# 필요한 개념 주변부터 읽기

`gooo context`는 안정적인 ID 하나를 출발점으로 선언, 조건과 본문 조립 계약,
연결된 입출력과 실행 바인딩을 JSON으로 보여 줍니다. 큰 설계도를 한 번에 펼치는
대신 지금 고칠 부품과 연결된 부품부터 보는 방식입니다.

```sh
gooo inspect examples/billing/main.gooo
gooo context examples/billing/main.gooo billing://activity/pay-order \
  --depth 1 --max-nodes 16 --max-bytes 8192
```

ID는 `inspect`의 결과에서 고릅니다. 현재 체크아웃에서는
`GOWORK=off GOTOOLCHAIN=go1.27.2 go run ./cmd/gooo`를 `gooo` 대신 사용할 수 있습니다.
공개 0.6.34 이후 개발 기능이며, 해당 명령이 포함된 릴리스에서 설치 명령으로 사용할 수 있습니다.

응답은 다음 정보를 담습니다.

- 원본 파일 전체의 `source_digest`와 기존 IR의 `semantic_digest`.
- 선택한 선언의 ID, 이름, 종류와 출발점에서의 거리.
- 활동의 원래 `value_program`, IR에 명시된 다중 입력 순서, 전체 `assembly` 계약.
- 선택한 선언 사이의 결정론적 PROV-O 관계와 참여자가 모두 포함된 실행 바인딩.
- `truncated`, 제한 이유, 아직 포함하지 않은 인접 선언 수와 다음에 조회할 `next_root`.

관계는 양방향으로 따라가며 명시적 실행 바인딩의 참여자도 이웃으로 셉니다.
단일 입력은 기존 IR 규칙대로 `prov:used` 관계에서 읽고, 다중 입력의 순서와
동일 타입의 반복은 `input_sequence`에 보존합니다.
동일한 입력과 한도로 반복하면 같은 결과가 나옵니다. 선언 하나의 사례나 조건을
중간에서 자르지 않습니다. 출발 선언 자체가 바이트 제한보다 크면 출력 전에
오류를 내므로 한도를 높여 다시 조회할 수 있습니다.

## 작은 응답을 이어서 읽기

기본값은 깊이 1, 선언 32개, JSON 16,384바이트입니다. 각각 최대 8, 256개,
1,048,576바이트까지 지정할 수 있습니다. 바이트 수에는 마지막 줄바꿈도 포함됩니다.
노드 한도에 맞춰 너비 우선으로 선택하고, 바이트 한도를 넘으면 마지막에 선택한
선언부터 제외합니다. 관계와 실행 바인딩은 필요한 선언이 모두 남았을 때 유지합니다.

`truncated: true`이면 `next_root`를 다음 조회의 ID로 사용합니다.
이전 `source_digest`를 `--expect-source`에 넣으면 파일이 바뀐 경우 바로 알려 줍니다.
다음 조회는 새로운 주변 조회여서 앞서 본 선언과 겹칠 수 있습니다. `omitted_adjacent_nodes`는
현재 응답과 직접 연결된 미포함 선언의 수입니다. 전체 프로젝트의 미조회 선언 수는 별도입니다.

`context_digest`는 자기 필드를 제외한 응답의 압축 JSON을 SHA-256으로 해시한 값입니다.
종료 코드 0은 조회 성공을 뜻합니다. 주변 전체를 확인했는지는 `truncated`로 읽습니다.

## 모델과 함께 쓰기

개발 에이전트는 이 응답으로 어떤 선언과 조립 계약을 수정할지 고를 수 있습니다.
조회는 원본 파일을 읽고 기존 IR로 내릴 뿐, 후보를 실행하거나 모델을 호출하지 않습니다.
활동별 수치 모델 입력은 기존 `body-context`에서 조회합니다. 이 명령의 전체 조립 계약에는
소스에 선언된 holdout 사례도 포함되므로 학습·평가 자료 구분은 해당 실험 계획을 따릅니다.

현재 범위는 단일 파일의 선언과 명시적 관계입니다. 후보 사실, 외부 Go 함수의 호출 그래프,
실제 실행 관측은 포함하지 않습니다. 기존 일반 CLI의 EntityFields 제한도 적용됩니다.
응답 크기가 작아졌다는 사실과 모델 판단 품질·유료 토큰 비용은 각각 측정해야 합니다.

이 명령의 사용자 흐름은 [Semaprax의 context 구현과 경계 검사](https://github.com/wavect/semaprax/blob/933196b9ef3cb611343f1401e9eb0b08fa404d0a/tests/agent_context.rs)에서
착안했습니다. Gooo 구현은 기존 Gooo IR과 PROV-O 관계를 사용합니다.
