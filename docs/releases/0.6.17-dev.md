# Gooo 0.6.17 development guide

This candidate extends caller-guided construction across package imports.
A helper can satisfy its local examples and still fail when a caller uses it.
`package construct` retains its declared alternatives and tries other complete
combinations within the supplied attempt budget.

The [release page](https://github.com/kimjooyoon/meta-ontology-go/releases) records
published assets and their exact source. Check `gooo version --build --json` for
the installed revision. The build and native runtime now require Go 1.27.2; the optional model runtime remains
v0.2.26-experimental.

## Construct a caller and its imported helper

Build from this source and run the frozen two-package example:

```sh
go build -trimpath -o .gooo ./cmd/gooo
./.gooo package construct --json \
  --construction-cases examples/package-caller-construction/construction-cases.json \
  --cases examples/package-caller-construction/evaluation-cases.json \
  --attempts 6 examples/package-caller-construction/gooo.workspace.json \
  > /tmp/gooo-package-construction.json
```

The caller uses an imported retry-budget function. One candidate stops too late,
one caps at the wrong value, two fail local checks and another reaches division
by zero. Their original outcomes remain in the receipt. Six attempts reach a
program matching the four supplied evaluation rows; five preserve a partial
result matching one of four. The source and expected values stay unchanged.

The receipt keeps the original package source image and activity identities,
the lowered program, all candidate attempts and their caller observations.
Integers such as `9007199254740993` retain their exact value.

## Reuse the saved choice

```sh
./.gooo package construct --json --receipt /tmp/gooo-package-construction.json \
  --cases examples/package-caller-construction/evaluation-cases.json \
  examples/package-caller-construction/gooo.workspace.json
```

Replay checks every saved attempt against the current package sources and
executes the selected program on the supplied evaluation inputs. It loads no
model and makes zero new predictions. The prior construction history remains
unchanged. The package source closure can be moved to another directory while
keeping its manifest-relative paths and contents.

## Let Gooo decide the next bounded attempt

The public [ecosystem workbench](https://github.com/kimjooyoon/gooo-ecosystem-workbench)
connects this command to Gooo's `joint-feedback` and `joint-next` programs:

```sh
go run ./cmd/workbench construct --compiler /absolute/path/to/gooo \
  --workspace examples/package-caller-construction/gooo.workspace.json \
  --construction-cases examples/package-caller-construction/initial-cases.json \
  --evaluation-cases examples/package-caller-construction/evaluation-cases.json \
  --holdout-cases examples/package-caller-construction/holdout-cases.json \
  --max-program-budget 8 --max-rounds 5 --out /tmp/gooo-package-feedback
```

Run that command in the workbench checkout with a fresh output directory.
Gooo selects the original failing caller row for the next round and proposes a
larger budget when needed. Go copies the declared files, invokes the compiler
and stores observations. The final holdout only runs after selection stops.

The retained examples used five rounds/14 attempts for the budget package and
eight rounds/105 attempts for a three-package program using the existing small
graph model. Both finished with 4/4 separate holdout observations and no new
inference in that final replay. Each fresh round restarts construction, so
repeated attempts count again. Original records are in the workbench's
`publication/package-construction-20261009` directory.

## Model scope and finite completeness

Without a model, construction follows deterministic source order. `--model`
lets a compatible local model rank record choices; `--fill-model` supplies a
compatible operation classifier for initial fill preparation. Model files are
distributed separately. Saved replay needs neither flag.

In the related three-package example, fixed order used 48 attempts and the
unchanged own graph model used 41, with identical selected source and 4/4 final
observations. That is a single bounded comparison. Model transfer and whole
program speed require separate measurements. A complete finite result means
the declared local and caller obligations matched; the supplied evaluation
rows retain their own denominator.

## Native platform coverage

Each release platform now executes partial package construction, complete
construction and saved replay. The validator rebuilds the expected package
image from original sources, binds original/lowered case keys, and checks
rejections, fault operands, selected code, completed native processes and the
unchanged saved history. Platform CI and publication remain separately visible
in their Actions runs and release records.
