# Gooo 0.6.23-dev: plan inputs, run values, check the saved program

This development candidate includes the native input-planning and input-only
commands consumed by the ecosystem workbench. Publication is a separate step:
the release workflow requires a successful readiness run for the exact merged
`dev` revision before creating the new immutable `v0.6.23-dev` tag.

## First use

From the compiler source tree, with the matching `gooo` executable and Go 1.27.2:

```sh
gooo body-plan --source examples/body-codegen/native-input-joins.gooo.fixture --entry Label
gooo body-plan --source examples/body-codegen/native-input-joins.gooo.fixture \
  --entry Label --inputs-template > inputs.json
gooo body-compose --source examples/body-codegen/native-input-joins.gooo.fixture \
  --entry Label --inputs inputs.json --out out/label
```

Edit the typed placeholders in `inputs.json` before using your own values.
`Left`, `Right`, `Label.input1` and `Label.input2` are caller inputs. The graph
supplies `Label.input0` from `Add`. Inspection uses zero model calls, candidate
tests and native executions. Its JSON export contains source and plan digests,
stable IDs, bindings and the assembly order of called helpers.

Input-only execution records actual values with correctness `UNKNOWN`, zero
expectations and zero passes. Each native request runs twice for replay checking.
`--repeat 2` retains both requests and reuses the compiled executable on the second.
The [complete input example](../../examples/composition-inputs/README.md) runs
the full seven-activity graph and later checks 49 supplied named expectations.

## Continue the same program

Use the output directory's `original.gooo` and `composition.json` with
`body-compose --inputs` for more observations, or `--cases` for later scoring.
Both preserve the selected program and use zero new predictions. New expectations
belong to the caller. Source-declared selection cases retain their own counts.

The [full graph workbench](https://github.com/kimjooyoon/gooo-ecosystem-workbench/tree/0d7d30a9e89576b4963e18b0967a71836849c234/examples/full-graph-assembly)
uses the native plan and passes original failing caller rows into Gooo feedback
rules. Records, source-search, source-fill and additional roots can share a saved
graph. Typed paths execute and replay; caller-guided joint reconstruction for
typed paths is still an implementation task. Input-only observations request
expectations before feedback construction starts.

## Own model and deterministic use

The [scalar identity source](../../examples/scalar-identity/README.md) includes an
unchanged own model with 446 bytes of packed weights. An explicit `--model`
ranks source-declared record choices. Omitting it starts deterministic selection.
`body-context --model` inspects compatibility without predicting. The compiler
checks the finite source cases after ordering candidates.

The native input profile uses the model once for Korean record generation.
English record generation uses fixed ordering. Both retain integers above 2^53,
Boolean values and Unicode text. The matching later caller suites contain four
expectations each. These observations cover those examples and finite choices.

## Release observation scope

Each of the four native targets runs four journeys: Korean record with the own
model, English record with fixed ordering, a seven-activity join and nested called
helpers. Every journey retains five original CLI reports: structural plan, typed
input template, repeated input-only generation, input-only saved replay and
scored saved replay. The 20 reports are additional command observations; the
structural release corpus remains 26 cases with 39 meta-bound indicators.

Validators require explicit zero counters and UNKNOWN for unscored execution,
exact source and plan equality, unchanged generated code on replay, no invented
oracles, exact large inputs and second-request executable reuse. The later
suites provide 4, 4, 49 and 2 named expectations in their separate programs.
These counts measure supplied cases. They do not measure arbitrary program intent.

Four-platform readiness and publication receipts determine whether the candidate
is distributed. [Research and design decisions](../research/usability-release-20261010.md)
explain the usability choices and deferred additions.
