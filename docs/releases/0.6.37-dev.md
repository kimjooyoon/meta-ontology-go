# Gooo 0.6.37-dev: source-bound release documents

This development release carries the compiler and the licenses for its two
direct modules in each platform archive. The [release payload guide](../language/release-payload-origins.md)
lists the pinned versions, source revisions and text digests. The release
readiness job builds every native archive twice and independently opens it to
check the five required files. An archive checksum alone does not establish
that its license files are present or match their sources.

The `RequiredMembers` activity in Gooo source selects the binary and document
paths, module versions and expected hashes. Go performs the byte-level archive
work and checks that the executable embeds those pinned modules. Without a
decision model, this path is deterministic.

The previous [0.6.36 release](0.6.36-dev.md) introduced `map_values`,
build-limit discovery and source-fragment generation. Their supported scopes
remain documented there. This release changes the platform receipt schema from
v1 to v2 to carry member-level origins. Keep the matching compiler and receipt
reader when inspecting historical releases.

The release becomes downloadable only after the exact `dev` revision passes
native readiness and the publication workflow creates a new immutable tag.
