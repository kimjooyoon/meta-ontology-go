# Gooo 0.6.29-dev: source-relative decisions and input accounting

The [0.6.29-dev experimental release](https://github.com/kimjooyoon/meta-ontology-go/releases/tag/v0.6.29-dev)
is published from source `90ff2bb5aeffc2ac553496b646d14db1e8d33fdb` after its CI, native platform observations
and release workflow completed. [Publication and actual installation](https://github.com/kimjooyoon/meta-ontology-go/wiki/Source-Relative-Release-0.6.29)
record the verified files and scope. The original model observation remains tied
to its earlier frozen development source; that experiment was performed once.

## Connect a small local decision model

This release includes Go decision-runtime 0.2.41. Its source-relative model
reads how inputs relate to a source comparison and to the requested Boolean
result. Gooo owns the permitted code paths, assembles the body, checks the
requirements and emits Go. The model supplies the order in which candidates
are inspected.

The [batch amount example](../../examples/body-codegen/source-relative-batch.gooo.fixture)
combines variable assignment, a comparison, two arithmetic branches and declared
output/condition cases. It has two binary choices and four permitted bodies.
The [model guide](../source-relative-contract-model.md) gives the fixed public
weight file, checksum, supported source shapes and full commands.

From the `v0.6.29-dev` source checkout, after obtaining that model:

```sh
GOWORK=off GOTOOLCHAIN=go1.27.2 go build -o ./gooo ./cmd/gooo
./gooo body-context --activity Choose --model "$model" \
  examples/body-codegen/source-relative-batch.gooo.fixture

./gooo body-construct \
  --source examples/body-codegen/source-relative-batch.gooo.fixture --entry Main \
  --construction-cases examples/body-codegen/source-relative-batch-construction.json \
  --cases examples/body-codegen/source-relative-batch-evaluation.json \
  --model "$model" --attempts 4 --out batch-result --format json > result.json

./gooo body-construct --report result.json --format markdown
```

Input inspection exports the 528 source feature cells and condition relationships
with zero predictions and zero candidate tests. Construction predicts once
before checking candidates. Later candidates reuse the ordering. Omitting the
model selects deterministic ordering. Unsupported source shapes retain a reason
and continue without inference; an invalid artifact produces a load error.
Saved replay reads the selected construction and makes zero new model calls.

## What the original observation showed

The [fixed native observation](../research/source-relative-native-20261011/results.md)
used one new authored task and the existing public relation weights. Both model
and fixed ordering checked two candidates. The first matched 1/4 outputs and 3/3
conditions; the second matched 4/4 and 3/3. Both later native evaluation and saved
replay matched the same four cases. Those repeated cases are dependent observations.

The model has 19,034 FP32 parameters and 76,136 weight-array bytes. One prediction
took 0.106833ms and constructor setup 7.822ms on Apple M4. Whole commands took 0.81s
fixed and 0.64s model, with maximum RSS 82.375MiB and 81.578MiB respectively. Normal
build caching, fixed order and shared hardware prevent a causal speed comparison.
This example supplied no candidate-count improvement. The default stays unchanged.

## Count condition inputs as construction inputs

The ordinary composition input-separation metric now includes values used only
by intermediate Boolean requirements. A value already seen in a condition case
is overlapping even when no output example used it. Native helper arguments are
compared as typed values, so a new caller input can still map to an old helper input.

The new regression covers direct and helper calls, positive and negative int64
values beyond 2^53, and one separate input. All four native outputs
match, while the corrected disjoint-input count is 1/1 rather than 4/4. This fraction
describes the recorded construction boundary; model-training exposure stays unknown.

Fresh joint construction now carries the original helper identities into native
observation after materializing ordinary source. Every candidate records the
actual helper arguments it used. Evaluation compares its arguments with local
cases and the complete caller history, including failed candidates. Saved replay
rechecks these observations with zero inference. Text and Markdown reports show
overlap, disjoint cases and unknown cases separately.

The original frozen observation and older receipts retain their `UNKNOWN`;
unrecorded history is never filled in retrospectively. Calls made while scoring
local candidates remain a limit when their arguments were not observed. These
measurements describe the recorded construction boundary, with model-training
exposure unknown. Failed, partial and unobserved results remain visible.

The earlier canonical, interaction and declared-case formats remain supported.
Go 1.27.2 remains required for native execution. Keep a matching compiler when
reading historical receipts whose formats change between development releases.
