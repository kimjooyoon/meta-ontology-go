# Gooo 0.6.12 development guide

A helper can match its own small examples and still make its caller fail.
`body-construct` tries other source-declared combinations, immediately compiles
and executes each complete program, and retains both local and caller results.
Changing an upstream helper also rechecks the examples of dependent helpers.

The [release page](https://github.com/kimjooyoon/meta-ontology-go/releases)
identifies published files and exact source revisions. This guide describes the
0.6.12 candidate. Native execution uses Go 1.27.1 and decision runtime
v0.2.26-experimental.

## A small example

The helper's local example is `0 -> 0`, which both `input` and `input * 2` satisfy.
The caller expects `3 -> 6`. Use the repository's
[source and independent case files](../../examples/caller-guided-construction):

```sh
gooo body-construct \
  --source examples/caller-guided-construction/main.gooo.fixture --entry Main \
  --construction-cases examples/caller-guided-construction/construction-cases.json \
  --cases examples/caller-guided-construction/evaluation-cases.json \
  --attempts 2 --out /tmp/my-caller-construction
```

Choose a new output directory. The first program returns 3; the second returns
6. Both retain the helper's original 1/1. Four subsequent evaluation rows check
positive, negative and large exact-integer values. The output labels one caller
input consumed during construction and three other root tuples.

Replay without inference:

```sh
gooo body-construct \
  --source /tmp/my-caller-construction/original.gooo \
  --construction /tmp/my-caller-construction/construction.json \
  --cases examples/caller-guided-construction/evaluation-cases.json
```

Saved replay rechecks every recorded construction attempt before evaluating the
selected program. Fresh construction evaluates its selected program directly.
The output directory also contains the selected ordinary Gooo source and
generated Go files for inspection and use.

## Choices, feedback and partial results

The initial locally selected combination is tried first. Remaining combinations
follow the retained per-activity rankings. This can cross a plateau where two
helpers must change together before the caller improves.

Source `attempts` values bound eligible ranking prefixes. The command's
`--attempts` limits whole-program combinations to 1..64. One composition can
contain up to 16 record-choice bodies, with a three-minute construction deadline.
The source keeps its original local expectations throughout the search.

`COMPLETE_FINITE` means every supplied local and construction-caller expectation
matched. Contradictions or an insufficient budget retain `PARTIAL_FINITE` and the
best observed combination. Logical partial results return exit code 0; inspect
the decision and separate evaluation counts. Compilation and execution errors
stop with a recorded failure.

An explicit `--model` can rank initial choices using the independently trained
small model. Subsequent failures advance that order without another prediction.
Omitting the model uses deterministic ordering. Saved replay makes zero new
predictions and retains historical inference separately from rechecked behavior.

The [frozen observation](../research/caller-guided-construction-20261008) used one
three-choice program at four budgets under two orders. Model order completed in
one attempt; fixed order required eight. Both completed routes selected identical
source and matched seven evaluation rows, including one consumed caller input.
Zero was also a local helper example. The experiment did not retrain the model
or measure unseen-task accuracy.

## Release checks and remaining scope

Each native platform runs the two-choice caller example, checks the failed and
successful attempts against actual values, evaluates all four rows, and replays
the saved history. Original local values, selected program, input overlap and
zero runtime/replay inference are checked. These are existing-example release
regressions, separate from structural release checks and model quality studies.

Package-wide joint construction, source-fill and IR-search participation, and
Gooo policies for choosing joint combinations remain future work. Existing
package continuation and source-defined local policies keep their own commands.
