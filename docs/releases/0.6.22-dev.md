# Gooo 0.6.22 development guide

Check whether a source-owned record assembly fits an explicit local model before
ranking candidates. The compiler prepares the model's input representation and
reports a reason when it needs deterministic selection. This candidate uses Go
1.27.2 and decision runtime v0.2.26-experimental.

The [release page](https://github.com/kimjooyoon/meta-ontology-go/releases) records
publication and exact sources. `gooo version --build --json` identifies your binary.

## Check the included source and model

From this compiler checkout:

```sh
go build -trimpath -o .gooo ./cmd/gooo
./.gooo body-context --activity Describe \
  --model examples/scalar-identity/model/model.json \
  examples/scalar-identity/source.gooo.fixture
```

The existing own model includes metadata and 446 bytes of packed weights.
The command verifies both files, checks source alternative types and exports the
model input. Prediction and candidate-test counters are explicitly zero.

| Result | Next step |
| --- | --- |
| `READY_FOR_RANKING` | Request assembly to rank and check source-declared candidates. |
| `DECLINED_TO_DETERMINISTIC` | Read the representation reason and use the source's deterministic selection order. |
| `FAIL_CLOSED`, nonzero exit | Correct the source or model input indicated by the retained error. |

For example, this model requires three field choices. A source with one choice
retains `THREE_FIELD_CHOICES_REQUIRED`. Readiness describes an input contract;
source cases and actual native calls supply separate correctness observations.
Default input exports omit case inputs and expected outputs. `--include-plan`
explicitly adds the separate source plan, including selection cases.

## Assemble and replay

```sh
./.gooo body-compose --source examples/scalar-identity/source.gooo.fixture \
  --entry Describe --cases examples/scalar-identity/cases.json \
  --model examples/scalar-identity/model/model.json --out out/scalar-model
./.gooo body-compose --source out/scalar-model/original.gooo \
  --cases examples/scalar-identity/cases.json \
  --composition out/scalar-model/composition.json
```

Omit `--model` for deterministic assembly. Repeat with `english.gooo.fixture` and
a fresh output directory to use English type names with the same stable IDs.
The example's condition, local assignments and three field choices remain authored
in Gooo. Selection cases, field observations and caller cases stay separate.
Replay keeps the selected program and performs zero fresh inference.

The native release profile retains ten scalar observations per platform: Korean
and English preflight plus fixed/model construction and replay. It checks source,
model and stable field identities, explicit zero preflight counters and the same
input digest in assembly and replay. The existing structural corpus remains 26 cases.

## Let Gooo choose the next route

The [ecosystem workbench](https://github.com/kimjooyoon/gooo-ecosystem-workbench/tree/a03966f8c3e5807390681360b8a0a30017b268e3/examples/model-assembly)
provides `assemble`: actual preflight, a Gooo routing rule, native assembly and saved
replay in one command. Its default output gives the reason, finite results and
generated code location. `--json` emits the saved short report; original graphs
and command outputs remain in files. Go transports the commands and records.

`gooo help models`, `gooo help body-context` and `gooo help body-compose` show
runnable commands. See [preflight scope](../record-model-preflight.md) and the
[0.6.21 scalar guide](0.6.21-dev.md) for source/model boundaries and exact values.
