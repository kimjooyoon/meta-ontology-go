# Gooo 0.6.32-dev source: string operations and one-condition assembly

This source version adds a small reusable string package and permits one
source-declared hole in an otherwise explicit computation. Release preparation
now checks both examples with native package execution and saved replay on each
of the four supported platforms. Publication status and exact source identity
belong to the release manifest and final publication receipt.

Go remains pinned to 1.27.2 and the decision runtime to 0.2.41. Existing model
weights and their original learning records remain unchanged.

## Reuse a Gooo string package

The [string operations example](../../examples/bounded-string-operations/README.md)
implements `Index`, `Count`, `RuneCount` and `MatchAt` in Gooo. An importing
application returns a record with the substring offset, non-overlapping count
and Unicode rune count. Twenty committed queries are compared independently with
Go `strings.Index`, `strings.Count` and `utf8.RuneCountInString`.

Text is valid UTF-8 and at most 1,024 bytes. Search offsets count bytes. An empty
needle has offset zero and a count of rune count plus one, following Go's
contract. The source uses counted loops with explicit bounds; every helper call
continues to contribute to the compiler's static call budget.

## Fill one predicate while keeping the program structure

The [single-condition example](../../examples/single-condition-byte-search/README.md)
leaves a byte equality condition open while declaring its loop, bounds and
returns. Its source offers two explicit expressions. The compiler checks them
against six selection cases and records four held-out cases separately.

The source grammar and IR body-fill support one through eight holes. Zero holes
and nine holes remain rejected. This narrows assembly to a useful local decision
without requiring a model to emit a whole function.

From a compiler checkout with Go 1.27.2:

```sh
GOWORK=off GOTOOLCHAIN=go1.27.2 go build -o ./gooo ./cmd/gooo
./gooo package execute --json \
  --cases examples/single-condition-byte-search/cases.json \
  examples/single-condition-byte-search/gooo.workspace.json > execution.json
./gooo package replay --json --receipt execution.json \
  --cases examples/single-condition-byte-search/cases.json \
  examples/single-condition-byte-search/gooo.workspace.json
```

## Measurements and their denominators

| Observation | Selection cases | Held-out cases | Native package cases | New model calls |
| --- | ---: | ---: | ---: | ---: |
| Retained byte-condition preparation | 6/6 | 4/4 | 10/10, then saved 10/10 | 0 |
| Retained string package preparation | Fixed source | None | 20/20, then saved 20/20 | 0 |

The first deterministic byte predicate matched 1/6 cases before selection chose
the equality predicate. The ten package rows reuse its six selection and four
held-out inputs. Running these rows on four platforms expands platform coverage;
it does not create forty independent behavioral inputs. The local preparation's
test producer recorded `UNBOUND_LOCAL_SOURCE`; its known checkout identity alone
does not make it a public source-bound binary measurement.

The release reader requires every case index, input, expected value and actual
value. It also requires exact manifest/case digests, the freshly lowered committed
source graph, complete finite denominators, zero model calls, and the same
generated program and exact original receipt on replay. The one-condition profile
checks its source fill, activity, generated bytes and separate 6+4 counts.
Synthetic regression receipts exercise missing and altered fields; they establish
reader behavior rather than fresh native execution or model accuracy.

The existing [source-relative model](../source-relative-contract-model.md) can
rank declared choices where its input format is supported. Model-free order and
saved replay remain available. These examples retain their explicit Gooo
algorithms and finite contracts. Larger traversal, arbitrary byte-array outputs
and model-assisted generalization remain further development work.
