# Gooo 0.6.27-dev: compare outcomes when a rule changes

This development candidate adds `body-outcomes-delta` to compare saved workflow
results. Publication requires the accepted source's CI and four-platform release
readiness. The currently published 0.6.26 binary predates this command.

When a batch limit changes from 16 to 32, input 17 should produce 17 instead of 16.
The new command shows both the observed change and the changed expectation. A
failure against the same expectation is reported separately as a regression.

## Compare two saved runs

```sh
gooo body-outcomes-delta --before before.json --after after.json
gooo body-outcomes-delta --before before.json --after after.json --json
```

Use the JSON output from `body-construct` or `body-compose`, or a construction
folder's saved `evaluation.json`. The text view summarizes changed and unassessed
inputs. JSON includes unchanged observations and original case indices as well.
The comparison performs zero model calls or generated-program executions.

The [complete walkthrough](../workflow-outcome-delta.md) includes Gooo source,
construction commands and the expected comparison. To use the candidate before
a public release, build its source with Go 1.27.2:

```sh
GOWORK=off GOTOOLCHAIN=go1.27.2 go build -o /tmp/gooo-outcomes ./cmd/gooo
/tmp/gooo-outcomes body-outcomes-delta --before before.json --after after.json
```

Inputs align by the complete external input tuple and stable activity ID, so
row reordering and changed intermediate values do not create false additions.
Large integers retain exact int64 values. Missing expectations or outcomes stay
unobserved, and conflicting duplicate observations remain ambiguous. Exit 0
means a comparison was produced; inspect the assessment counts for regressions.

## What was measured

The [original saved batch records](../research/workflow-outcome-delta-20261011/README.md)
contain ten input groups. Comparing limits 16 and 32 gives five changed outcomes
with changed expectations and five unchanged matches. Comparing the original
with its saved replay gives ten unchanged matches. These are observations of
one synthetic rule; customer savings and unseen inputs remain unmeasured.

The report structure is declared in Gooo and projected into Go and JSON Schema.
The first CI exposed a missing registration in the repository's declaration
inventory. The correction registers the report projection and checks changed or
missing generated artifacts. Existing source syntax obligations remain present.

The release preparation runs this new comparison on each native platform using
the retained input files and exact published comparison outputs. It does not
repeat the original model study or execute its generated programs.
