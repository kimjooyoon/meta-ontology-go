# Gooo 0.6.13 development guide

Gooo can reconsider an integer expression inside a helper using the actual
result of the program that calls it. It can combine that search with record
choices. A locally rejected expression is recorded and consumes one attempt;
the next declared combination can still be tried.

This guide describes the 0.6.13 candidate. The
[release page](https://github.com/kimjooyoon/meta-ontology-go/releases) identifies
published archives and their exact source commits. Native execution uses Go
1.27.1 and decision runtime v0.2.26-experimental.

## Try the expression search

```sh
gooo body-construct \
  --source examples/caller-search-rejection/main.gooo.fixture --entry Main \
  --construction-cases examples/caller-search-rejection/construction-cases.json \
  --cases examples/caller-search-rejection/evaluation-cases.json \
  --attempts 5 --out /tmp/my-caller-search
```

The helper retains `0 -> 0`. Its caller expects `3 -> -1`:

1. The first expression, `input`, makes the caller return 1.
2. The next expression, `0`, is a constant zero denominator and fails typechecking.
3. `-input` makes the caller return -1 and matches the unchanged local case.

Three combinations are attempted; two programs execute natively. The four
subsequent evaluation inputs are retained separately. With `--attempts 2`, the
command keeps a partial result and the rejection instead. Inspect `decision`
and finite counts: a logical partial result returns exit code 0.

## Reuse the selected program

```sh
gooo body-construct \
  --source /tmp/my-caller-search/original.gooo \
  --construction /tmp/my-caller-search/construction.json \
  --cases examples/caller-search-rejection/evaluation-cases.json
```

Saved replay rederives every attempted expression and the recorded local error,
re-executes successful constructions and checks the selected ordinary program.
It does not make a new model prediction. The output directory includes selected
Gooo source and generated Go files for direct inspection and reuse.

## Models, limits and counts

`mixed-model.gooo.fixture` in the same directory combines the expression with
three record choices. Use its `mixed-` case files, `--attempts 40`, and an explicit
`--model` path for own-model record ordering. Integer expression order remains
deterministic. Without that option all candidate ordering is deterministic.

Source `attempts` bounds eligible expressions separately from the command's
1..64 combination budget. One composition supports up to 16 assembly bodies.
Histories with local rejections use `gooo/joint-construction/v3`; rows with a
`rejection` have no caller score. Their local totals cover only already scored
helpers before the rejection. Existing v1 and v2 histories remain supported.

The separate [ecosystem workbench](https://github.com/kimjooyoon/gooo-ecosystem-workbench)
uses Gooo rules to add unchanged counterexamples and increase the attempt budget
automatically. Its final holdout runs only after that loop finishes. Iterations,
combination attempts, locally rejected combinations and native programs are
different counts.

Local typecheck and pure-evaluation rejection can continue. Request cancellation,
source reconstruction, native toolchain and compiled-program execution failures
still stop the request. Initial local construction must produce a valid body.
Multi-hole joint search and package-wide joint construction remain future work.
