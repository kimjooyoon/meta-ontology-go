# Gooo 0.6.25-dev: declare intermediate conditions and reuse their failures

This development candidate connects source condition examples to program
assembly, caller reconstruction, model feedback and saved replay. It uses
Go 1.27.2 and public decision-runtime v0.2.28-experimental. Publication requires
the accepted source's CI and release readiness. Earlier releases retain their
original source and assets.

## Describe a condition you expect

Inside an integer activity's `assembling` block:

```gooo
condition_case "comparison" input "-1" -> "true"
condition_case "comparison" input "0" -> "false"
condition_case "comparison" input "1" -> "false"
```

`comparison` names an existing choice for an `if` condition. Gooo evaluates that
condition using the current variables for each input, alongside final-output
cases. A mismatching or unreached condition excludes the candidate. If none
matches, the result retains the failure evidence and the attempted candidates.
The feature currently covers Integer → Integer typed paths, up to 128 condition
examples, exact int64 inputs and explicit Boolean expectations.

## Assemble and replay without a model

Run these commands from the matching source tree, using a fresh output directory:

```sh
gooo body-construct --source examples/body-codegen/source-condition-cases.gooo.fixture \
  --entry Main --construction-cases examples/body-codegen/source-condition-construction-cases.json \
  --cases examples/body-codegen/source-condition-evaluation-cases.json \
  --attempts 8 --out out/source-conditions

gooo body-construct --source out/source-conditions/original.gooo \
  --construction out/source-conditions/construction.json \
  --cases examples/body-codegen/source-condition-evaluation-cases.json
```

The fixture keeps its seven local output cases, three intermediate condition
cases and eleven caller evaluation rows separate. Several evaluation inputs also
occur locally. Saved replay reconstructs source conditions, checks the emitted
typed structure and makes zero new model predictions. Large integer values remain
exact, including the caller output `18014398509481990`.

## Use a small decision model with the same declared paths

For an explicit compatible local path model, `body-codegen` accepts
`--path-model model/model.json --path-step-attempts 1 --path-feedback-rounds 2`.
The retained small Gooo model can be unpacked from this source tree. Use a fresh
directory; these commands make a new local observation rather than reproducing
the timing of the earlier study:

```sh
mkdir -p out/condition-model
gzip -dc docs/research/condition-feedback-20261010/original/model/model.json.gz > out/condition-model/model.json
gzip -dc docs/research/condition-feedback-20261010/original/model/weights.bin.gz > out/condition-model/weights.bin

gooo body-codegen --json --activity Choose \
  --path-model out/condition-model/model.json \
  --path-step-attempts 1 --path-feedback-rounds 2 \
  examples/body-codegen/source-condition-cases.gooo.fixture > out/condition-feedback.json
```

Each feedback round retains the full original intent and source header, appending
committed output and condition failures. An unreached condition is recorded as
`UNOBSERVED`. When the complete context exceeds the model's input bound, inference
is declined and existing candidate search continues. No weights change at runtime.

The [frozen-model observation](../research/condition-feedback-20261010/README.md)
includes runnable commands, the model and original records. For that one source,
feedback used three instead of five candidates and nine instead of three model
predictions. Both selected the same program, with outputs 7/7 and conditions 3/3.
The complete feedback inputs occupied 456–493 of the available 512 bytes. Longer
intentions and different program structures need separate measurements.

A separate [24-prediction input comparison](https://raw.githubusercontent.com/wiki/kimjooyoon/meta-ontology-go/observations/condition-feedback-ablation-20261010/README.md)
kept those weights and six original feedback inputs fixed. Removing the condition
clause changed the comparison choice in both rounds; exchanging expected/actual
Boolean values changed no eligible choice. The current representation mixes
text content and relative position. The result motivates separate intent and
observation inputs in future training; it does not establish semantic
understanding or a new functional success rate. Source conditions continue to
determine which candidates are eligible.

## Execution errors retain their cause

Native process errors preserve a deadline or cancellation cause together with
the original operating-system error. Go callers can use `errors.Is` for context
interruption and `errors.As` for the native exit error. The compiler still joins
the child and keeps the existing time limits. This improves error interpretation;
it does not establish why a machine took longer to start or execute a program.

See [source assembly](../source-assembly.md) for syntax and
[the previous release guide](0.6.24-dev.md) for typed branches, source/model
inspection and mixed record construction. Finite results apply to declared cases;
unlisted behavior remains unmeasured.
