# Gooo 0.6.31-dev: bounded Text operations

[Gooo 0.6.31-dev](https://github.com/kimjooyoon/meta-ontology-go/releases/tag/v0.6.31-dev)
adds counted loops and byte access for bounded Text operations. Its four platform
archives bind to source `c56007f5881296cb3181ff056c50a4ae917a9850`, Go 1.27.2
and decision runtime 0.2.41. The release manifest, report and checksums identify
the published files.

## Find a byte with a Gooo package

The [search example](../../examples/bounded-text-search/README.md) implements
`IndexByte` in Gooo and imports it from another Gooo package. Its `Query` record
contains Text and an integer needle. A match returns the original byte offset;
absence or a needle outside 0..255 returns -1.

| Text | Needle | Result |
| --- | ---: | ---: |
| `gooo` | 111 (`o`) | 1 |
| `가x` | 120 (`x`) | 3 |
| `가` | 176 (its second UTF-8 byte) | 1 |
| empty Text | 97 (`a`) | -1 |

Build a checkout containing these changes with Go 1.27.2, then run the committed
example and its saved receipt:

```sh
GOWORK=off GOTOOLCHAIN=go1.27.2 go build -o ./gooo ./cmd/gooo
./gooo package execute --json \
  --cases examples/bounded-text-search/cases.json \
  examples/bounded-text-search/gooo.workspace.json > search-execution.json
./gooo package replay --json --receipt search-execution.json \
  --cases examples/bounded-text-search/cases.json \
  examples/bounded-text-search/gooo.workspace.json
```

The examples need no model file or API key. Saved replay retains the selected
program and source/input identities.

## The counted-loop boundary

The supported form is `for i = 0; i < N; i = i + 1`, where `i` is an existing
local and `N` is a literal from 1 to 1,024. The body can return early and update
other locals. Counter mutation, counter shadowing, nested loops and dynamic
bounds are rejected. Calls made inside a loop contribute their maximum repeated
cost to the existing 4,096-call limit.

The example checks text length before reading `text[offset]`. Byte values are
unsigned 0..255; `int64(text[offset])` converts one into a Gooo Integer. The
interpreter preserves Go's byte arithmetic behavior and reports invalid offsets.
Inputs remain valid UTF-8 Text of at most 1,024 bytes. Byte-array outputs, bitwise
operations and more general traversal remain follow-up work.

## Formatting a computes body

The syntax-adapter update accepts a body surrounded by indentation or
newlines. It normalizes the outer whitespace when forming semantic declarations,
while retaining the original syntax body and source span. Spaces inside a string
literal remain part of its value. A whitespace-only body is still rejected.

## What was checked

The feature's interpreter tests compare five texts and 258 needle values with
Go `strings.IndexByte`: 1,290 finite combinations. Ten importing-package cases
also execute natively and replay their saved program. They include empty Text,
absence, repetition, NUL, multibyte offsets, the 1,024-byte boundary and invalid
needle values. The cases describe this authored operation's behavior.

A separate local release-reader preparation used clean development producer
`e664837f865502e9b84cd5075cd6a38f26df8568` on macOS arm64. It retained one package
execution and one saved replay, each passing 10/10 cases with zero model calls.
The candidate still reported version 0.6.30-dev; its source identity distinguishes
that preparation from the published 0.6.30 artifact. The release reader checked
both records against their real manifest/case digests and the exact original
receipt digest used by replay. This local record establishes no other platform
result or published 0.6.31 asset set.

The [accepted-source native checks](https://github.com/kimjooyoon/meta-ontology-go/actions/runs/38156418124)
run the same ten cases and saved replay on Linux amd64, macOS amd64/arm64 and
Windows amd64. Each platform retains its two raw receipts. These are repetitions
of ten independent cases across four platforms, rather than forty different
behavioral cases. Model calls are zero for this example.

## Existing models and earlier evidence

The decision runtime remains 0.2.41. Existing model weights and their original
measurements are retained. A model can rank compatible declared choices; fixed
ordering and saved replay remain available. See the
[source-relative model guide](../source-relative-contract-model.md) and the
[0.6.30 guide](0.6.30-dev.md) for the preceding construction features and their
original observations.
