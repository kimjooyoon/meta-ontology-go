# Gooo 0.6.28-dev: understand and reuse a construction result

This is a release preparation candidate. Publication requires the original CI,
native platform observations and exact-source release workflow to pass. The
currently published compiler is 0.6.27; these additions require the new source.

## A small changing rule

A backend rule such as a queue's batch limit can have a short implementation but
several requirements: an upper bound, behavior for negative inputs, and a condition
used to select the result. Gooo records those requirements in source, constructs a
bounded candidate, and records what was checked. A small local model can suggest
which source-owned candidate to try first. Fixed ordering remains available.

The first candidate may return every supplied expected output while violating an
explicit intermediate condition. The construction summary shows both populations
and the body used by the selected caller program. It keeps the first failure
visible after a later candidate succeeds.

## Read the result you already have

From the matching source checkout, save full JSON stdout during construction:

```sh
gooo body-construct --source examples/caller-guided-construction/main.gooo.fixture \
  --entry Main --construction-cases examples/caller-guided-construction/construction-cases.json \
  --cases examples/caller-guided-construction/evaluation-cases.json \
  --attempts 2 --format json > result.json

gooo body-construct --report result.json
gooo body-construct --report result.json --format markdown
```

The two report commands make no model calls and execute no generated program.
They need no source files, model weights or Go toolchain. The preamble identifies
the saved file and explains that the rows describe its original invocation. Exit0
means the report was read; the saved invocation may itself have failed. The split
`--out` files `construction.json` and `evaluation.json` lack the full envelope.
`--report` accepts one full JSON file up to 32MiB; `--format json` returns its bytes.

During a new construction or saved replay, use `--format text` or `--format markdown`
to display the same summary. Saved replay remains a separate execution mode:
`--construction`, the original source and current cases recheck recorded choices
and execute the selected program. See the [report guide](../construction-results.md).

## Compare a rule change

```sh
gooo body-outcomes-delta --before previous.json --after result.json --markdown
```

The comparison joins stable activity IDs and complete caller input tuples. It
shows changed expectations separately from changed actual outputs. Missing or
conflicting observations stay visible. Percentages name the supplied check
population. Behavior outside those observations remains unmeasured.

## Explicit local models

This candidate includes decision-runtime 0.2.40. Native loading supports
[ordered-source interaction models](../interaction-contract-model.md) and the
[canonical branch model](../canonical-contract-model.md), alongside earlier
choice-conditioned formats. Supported equivalent direct-return and assignment
forms give the canonical model the same arrays. The original source continues to
own the selected program and its semantic identities.

These are small local decision models written in Go. Unsupported source shapes
report a reason and use fixed ordering without inference. Omit the model for the
deterministic path. The linked guides include model files, checksums and limitations.

The retained canonical example needed four local candidates with its model versus
one with fixed ordering. Its first candidate matched8/8 outputs and1/3 conditions;
the selected candidate matched 8/8 and 3/3. The same eight authored inputs were reused
for evaluation. This supplies compatibility evidence, not an independent accuracy
measurement or a reason to replace the default. Customer savings are unmeasured.

## Release checks

The release profile reads two retained observations in text, Markdown and JSON on
each native platform. It checks named historical counts, failed conditions, the
input-file digest and exact JSON bytes, and retains each output in its actual format.
Those six reads do not repeat the original construction or model experiment.
The existing native execution profiles and 26 top-level release cases remain.

Go 1.27.2 remains the requirement for native execution. Keep a matching compiler
for historical receipts whose formats change between development releases.
