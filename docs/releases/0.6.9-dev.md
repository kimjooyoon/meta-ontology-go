# Gooo 0.6.9 development guide

This version adds string operations, follows values through source helpers and
connects an ordered value graph to the optional small-model path. Check the
[release page](https://github.com/kimjooyoon/meta-ontology-go/releases) for published
assets and their exact source. Native execution requires Go 1.27.1. The public
decision runtime is v0.2.26-experimental.

## Write and assemble a filename classifier

Gooo bodies can use string `len` and byte-range slices. Prefix/suffix checks,
suffix removal and byte length are written as ordinary Gooo helpers in the
[filename example](../../examples/text-operations/README.md). Lengths and slice
positions count UTF-8 bytes. The compiler preserves the source's operand order,
branches and integer bounds when it emits Go.

```sh
gooo version --build --json
gooo body-compose --entry Classify \
  --source examples/text-operations/source.gooo.fixture \
  --cases examples/text-operations/cases.json --out out/filenames-069
gooo body-compose --source out/filenames-069/original.gooo \
  --cases examples/text-operations/cases.json \
  --composition out/filenames-069/composition.json
```

Use a new output directory for construction. The example has five construction
cases with fifteen expected fields, plus twelve native execution inputs.
Omitting a model uses deterministic candidate order. A compatible existing
record-field model can be supplied with `--model /path/to/model.json`. Saved
execution reconstructs the selected program without new inference.

The earlier [candidate-order study](https://github.com/kimjooyoon/meta-ontology-go/wiki/Text-Operations-and-Choice-Order)
found that the existing v1 model picked the accepted body first in one of eight
arrangements of this program. Finite continuation completed all arrangements.
Keep that observation separate from this version's new input representation.

## Follow what a helper computes

The source value-flow graph now binds actual arguments to same-source helper
parameters and brings conditional return values back to the caller. Nested
calls and helpers used only by an alternative retain their stable identities
and source spans. The [helper scope](../record-value-flow.md) documents the
supported forms and unresolved cases.

```sh
gooo body-context --value-flow --activity Classify \
  --feature-version triple_record_value_graph_v3_shared_v1 \
  examples/text-operations/source.gooo.fixture
```

This analysis performs zero model predictions and zero candidate evaluations.
The model context preserves ordered operators, canonical literals, input
positions/types, field IDs and guards. Source offsets and helper display names
remain in the provenance graph. Test inputs, expected outputs and attempt
budgets stay outside the model feature array.

## Connect a model with the matching input contract

The v3 contract is explicit. A model trained for it can be passed through
`body-codegen --path-model` or `body-compose --model`. The model orders the
declared choices once; Gooo observes their behavior within the source budget.
Existing v1/v2 model files retain their original input paths.

This release includes no trained v3 weights. The fixed-size projection still
uses hashed channels, and the shared judge scores fields independently.
The source graph has a 512-node/64-KiB input bound and a 1,024-byte string bound.
Unsupported optional values and oversized context retain a reason and continue
in deterministic order. Saved construction rebuilds the context with zero new
model calls. See [graph input and limits](../record-graph-model-input.md).

In the [source-bound input study](https://github.com/kimjooyoon/meta-ontology-go/wiki/Source-Graph-Model-Input),
the same eight filename arrangements produced two v1 arrays, four v2 arrays and
eight v3 arrays. That is one source family. It establishes preserved distinctions
for those rows; prediction quality needs new training and separate programs.

## Release observations

Each native readiness runner uses the actual candidate executable to construct
and replay division (8 cases), retry (12 cases) and filenames (12 cases).
It also exports the filename v3 context, checks source/context digests and zero
call counts, then decodes and projects it with the public SDK. The raw outputs
are retained in platform artifacts. Synthetic-weight integration tests exercise
model dispatch and continuation separately.

These example counts are separate from the 26 structural release cases, four
platform receipts and nine published asset identities. Finite cases describe the
supplied inputs. Source graph and receipt formats may change between development
versions; preserve the original compiler for historical replay.

## 한국어

Gooo로 파일 이름을 다루는 함수들을 작성하고, 그 함수가 계산한 값이 코드 조립까지
이어지도록 연결했습니다. 모델에도 AND·OR와 값의 순서를 구분해 전달합니다.
계산한 과정을 함께 건네서 작은 모델이 판단할 때 필요한 정보가 사라지지 않게 하는
작업입니다. 모델을 연결하지 않으면 같은 후보를 고정 순서로 확인합니다.

새 입력 전용 모델은 아직 학습하지 않았습니다. 한 프로그램의 후보 배치가 입력에서
구분되는지 먼저 측정했고, 실제 모델 판단은 별도 프로그램과 한글·영어 의도로
평가할 다음 단계입니다. 실행한 사례와 남은 범위는 계속 따로 기록합니다.
