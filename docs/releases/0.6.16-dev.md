# Gooo 0.6.16 development guide

This candidate continues finite whole-program construction after an observed
int64 division/remainder by zero. It retains the fault's activity, expression
location, projection digest and exact operands. Independent results survive;
activities that need the missing value are explicitly blocked.

The [release page](https://github.com/kimjooyoon/meta-ontology-go/releases)
identifies published assets and their exact source. This guide alone does not
establish publication. Check `gooo version --build --json` for the source revision.
The toolchain remains Go 1.27.1; optional model execution uses decision runtime
v0.2.26-experimental.

## Continue beyond a failing caller

Build from this source, then run the original six-candidate fixture:

```sh
go build -trimpath -o .gooo ./cmd/gooo
./.gooo body-construct \
  --source examples/caller-native-failure/source.gooo.fixture --entry Main \
  --construction-cases examples/caller-native-failure/construction-cases.json \
  --cases examples/caller-native-failure/evaluation-cases.json \
  --attempts 6 --out /tmp/gooo-six-candidates
```

Use a fresh output directory. The local examples accept a candidate that later
divides by zero at the caller. Its failure consumes a bounded attempt and the
next candidate remains reachable. Six attempts include two local rejections and
four native combinations, one of which faults. The selected program matches the
four supplied final expectations. An attempt budget of five retains a partial
result matching 1/4, with the fault still in its history.

Local scoring, source holdout and caller expectations retain separate counts.
Candidate expressions and all original expected values remain unchanged.

## Keep successful values and explain missing ones

```sh
./.gooo body-compose \
  --source examples/caller-native-failure/graph.gooo.fixture \
  --cases examples/caller-native-failure/graph-cases.json \
  --out /tmp/gooo-fault-graph
```

Across two rows the graph retains six matching outputs, one arithmetic fault
and one blocked activity. Earlier and independent outputs survive, including
the exact integer `9007199254740993`.

`runtime.outcomes` counts supplied expected outputs as `matched`, `mismatched`,
`faulted`, `blocked`, or `unobserved`. A completed observation has zero unobserved
outputs. The trace also includes activities without named expectations. Faults
outside those expectations still prevent a complete construction decision.

## Replay and reuse

```sh
./.gooo body-construct --source /tmp/gooo-six-candidates/original.gooo \
  --construction /tmp/gooo-six-candidates/construction.json \
  --cases examples/caller-native-failure/evaluation-cases.json
./.gooo body-compose --source /tmp/gooo-six-candidates/selected.gooo --entry Main \
  --cases examples/caller-native-failure/evaluation-cases.json
./.gooo body-compose --source /tmp/gooo-fault-graph/original.gooo \
  --composition /tmp/gooo-fault-graph/composition.json \
  --cases examples/caller-native-failure/graph-cases.json
```

Saved construction replays original candidates, inputs, expectations and fault
observations. It performs no new inference. Original Gooo and pure Go projections
remain available; separate observed projections carry source-bound fault sites.
Existing construction v1–v5 records preserve their previous interpretation;
histories containing native arithmetic faults use v6.

## Gooo feedback and the own model

The [ecosystem workbench](https://github.com/kimjooyoon/gooo-ecosystem-workbench)
reads the new observations and executes next-step rules written in Gooo. One
example adds an evaluation-only arithmetic fault as an unchanged construction
counterexample: three rounds, four total attempts and 3/3 final observations.
The six-candidate budget example uses five rounds, 14 attempts and 4/4 final
observations. These are finite supplied examples.

The mixed fixture combines these fill choices with record choices. The unchanged
own graph model can order the initial record candidates via `--model`. Recorded
fixed-order and model-order runs took 48 and six attempts to select the same
source. Fill order remains source-defined. See the [original observations](../research/native-arithmetic-outcomes-20261009.md)
for scope, model digests and timings.

## Candidate validation scope

Platform readiness executes partial construction, complete construction, saved
construction replay, graph execution and graph replay with the actual candidate
binary. It compares original source/cases, exact values, failed/blocked outcomes,
candidate counts, process completion and zero new inference. Source-bound
mutation regressions retain changed evidence as failures.

Current language-fault scope is int64 zero-divisor `/` and `%`. Unknown panic,
native process failure, timeout and cancellation retain the error path. Native
execution still requires two fresh runs with matching output. Deployment status
and platform-specific observations are published separately.
