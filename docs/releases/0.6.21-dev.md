# Gooo 0.6.21 development guide

This version resolves native scalar values by recognized type identity while
keeping authored source names. Integer, Boolean and string declarations can be
named `Count`, `Enabled`, `Message` or `정수`, `논리`, `문자열` with the same IDs.
The compiler follows the part's specification number as well as its nameplate.

```gooo
entity 정수 id "urn:gooo:type:integer"
entity 논리 id "urn:gooo:type:boolean"
entity 문자열 id "urn:gooo:type:string"
```

The [release page](https://github.com/kimjooyoon/meta-ontology-go/releases) records
publication and exact sources. `gooo version --build --json` identifies a local
installation. This candidate uses Go 1.27.2 and decision runtime v0.2.26-experimental.

## Assemble three source-declared fields

The example calculates a local string and an enabled/positive condition, then
fills text, active and count fields. Three binary choices provide eight possible
combinations. Four source cases check 12 field observations while selecting.
Four different input tuples check the constructed program, including exact
integers +/-9007199254740993, Korean text and an emoji.

From this compiler checkout:

```sh
go build -trimpath -o .gooo ./cmd/gooo
./.gooo body-compose --source examples/scalar-identity/source.gooo.fixture \
  --cases examples/scalar-identity/cases.json --entry Describe --out out/scalar-fixed
./.gooo body-compose --source examples/scalar-identity/source.gooo.fixture \
  --cases examples/scalar-identity/cases.json --entry Describe \
  --model examples/scalar-identity/model/model.json --out out/scalar-model
```

The source includes the unchanged own graph chooser's metadata and 446-byte
packed weights. No service or model download is required for this example.
The fixture provenance and limits are in [model/README.md](../../examples/scalar-identity/model/README.md).

Read `record_assembly.attempts` for each candidate's case/field observations.
`model_calls` and `model_context` distinguish actual inference from a model
representation decline. The own model supports three field choices; a different
choice count can continue through deterministic selection with the reason retained.
The observed first candidate may be incomplete. Gooo checks further combinations
within the declared attempt budget and saves the selected program.

## Keep names, identities and exact values together

Repeat the commands with `examples/scalar-identity/english.gooo.fixture`, using
fresh output directories. The English example changes only the three entity
names and their source references. The generated native program should be the
same. Typed plans keep the authored names and canonical entity IDs.

Replay rebuilds the saved selected program and runs the same external cases:

```sh
./.gooo body-compose --source out/scalar-model/original.gooo \
  --cases examples/scalar-identity/cases.json \
  --composition out/scalar-model/composition.json
```

Saved assembly reports retain their original model call count. The replay's
runtime call count is zero. The release's native profile runs both languages,
fixed/model construction and saved replay on four platforms, checking exact input
and field values, IDs, generated markers and matching generated-code hashes.

Unknown nominal IDs still need a supported value layout. Explicit record blocks,
including empty blocks, do not supply a scalar layout. Legacy scalar spellings
with other nominal IDs retain their prior profile. Source edits need fresh receipts.
See [scalar identity](../language/scalar-identity.md) and the earlier
[0.6.20 activity identity guide](0.6.20-dev.md).
