# Gooo 0.6.11 development guide

Gooo source already declares a package name and its imports. This version lets
the workspace reader use those declarations when the corresponding manifest
fields are omitted. Adding a helper package no longer requires writing the same
dependency in two places.

The [release page](https://github.com/kimjooyoon/meta-ontology-go/releases)
identifies published files and exact source revisions. This guide describes the
0.6.11 source candidate. Native execution uses Go 1.27.1; the decision runtime
remains v0.2.26-experimental.

## Write the source metadata once

A three-package diagnostic can use this workspace:

```json
{
  "schema": "gooo/package-workspace-manifest/v1",
  "entry": {"package_path": "app/explain", "activity": "Main"},
  "packages": [
    {"path": "app/explain", "sources": ["app.gooo.fixture"]},
    {"path": "tools/diagnostics", "sources": ["diagnostics.gooo.fixture"]},
    {"path": "tools/rules", "sources": ["rules.gooo.fixture"]}
  ]
}
```

The listed files supply the package names and imports. Paths and the entry stay
explicit. All files within a package must agree on its name; imports are merged,
deduplicated and sorted. A supplied name or import list continues through the
existing consistency checks. In particular, `imports: []` declares no imports,
while an omitted or null list asks the compiler to read the source declarations.

From the repository root, create a new output directory and run:

```sh
mkdir out
gooo package execute --json --cases examples/package-body-calls/cases.json \
  examples/package-body-calls/source.workspace.json > out/diagnostic.json
gooo package replay --json --receipt out/diagnostic.json \
  --inputs examples/package-body-calls/inputs.json \
  examples/package-body-calls/source.workspace.json
```

Use the same manifest form for construction and replay. Explicit and inferred
forms resolve to the same package graph but retain their original file digests.
Saved replay makes zero new predictions and can run on new inputs. The shared
reader also serves `package resume` and source-defined assembly-policy workspaces.

The library and diagnostic starters emit the shorter manifest:

```sh
gooo init --template library my-library
gooo init --template diagnostic my-diagnostic
```

The [workspace guide](../language/workspace-manifest.md) describes identity and
replay rules. [Imported function calls](../../examples/package-body-calls/README.md)
shows which Gooo expressions can call package helpers.

## Use and measurements

The public [Gooo standard library](https://github.com/kimjooyoon/gooo-standard-library)
has number, logic and text packages. We reused its unchanged preview program and
existing graph QAT model to check this compiler change. Explicit and source-derived
workspaces produced the same generated program and native input/output traces.
Both fixed and model-guided construction required eight attempts, and both matched
the same ten evaluation inputs. Saved reuse made zero new predictions.

This is an existing-program regression with frozen sources and weights.
[Plan, raw results and comparison](../research/source-package-metadata-20261008/README.md)
retain the model's unsuccessful earlier candidates as well as the completed result.
Model training and broader transfer are separate work.

## Release observations

Readiness retains the existing division, retry, filename and source-graph checks.
It additionally constructs and replays the three-package diagnostic with each
manifest form. Four input rows have two named expectations each: eight expected
outputs per run. The witness compares actual outputs with the independent case
file and requires the same generated program across both constructions and both
replays. Runtime and replay model-call counts must be zero. Every native platform
retains these four raw receipts. These repeated runs use the same four input rows;
they are separate from the 26 structural release cases.

## 한국어

Gooo 파일에 적어 둔 패키지 이름과 가져오기를 설정 파일에 반복하지 않도록 했습니다.
함수를 다른 도구에서 가져다 쓸 때 맞춰 고칠 곳이 줄어듭니다. 파일 위치와 실행할
함수는 설정에 남겨 두며, 조립한 결과를 저장하고 다시 쓰는 과정도 같은 구성을 읽습니다.
기존 자체 모델과 공개 라이브러리로 사용해 결과가 유지되는지 확인했습니다.
