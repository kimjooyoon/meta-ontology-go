# Gooo 0.6.26-dev: let a small local model read the cases before choosing a path

This development candidate connects the public choice-conditioned decision model
to Gooo's ordinary body construction and saved replay. It uses Go 1.27.2 and
decision-runtime v0.2.37-experimental. Publication still requires the accepted
source's CI and release readiness.

Gooo source describes the available branches, comparisons and operand choices,
along with example inputs and expected results. The local model gives each
declared choice two scores. Gooo assembles the proposed body, checks every output
and intermediate condition example, and continues through remaining candidates
when a proposal fails. The source examples decide which candidate is accepted.

## Get a model and inspect what it receives

Use the matching source checkout and a fresh output directory. The two model
files and their checksums are published with SDK0.2.37:

```sh
mkdir -p out/choice-model
gh release download v0.2.37-experimental \
  --repo kimjooyoon/gooo-decision-runtime \
  --pattern 'model-*.json' --pattern MODEL-SHA256SUMS \
  --dir out/choice-model
(cd out/choice-model && shasum -a 256 -c MODEL-SHA256SUMS)

gooo body-context --activity Choose \
  --model out/choice-model/model-choice-v1.json \
  examples/body-codegen/source-condition-cases.gooo.fixture
```

The export contains the actual source features and all seven declared output
cases. Inspection makes zero model predictions and tests zero candidates. The
fixture also declares three intermediate Boolean conditions; Gooo checks these
when constructing a candidate. Exact large integers remain exact throughout
source binding, candidate checking and native execution.

## Construct a body, then run the saved program

```sh
gooo body-codegen --json --activity Choose \
  --path-model out/choice-model/model-choice-v1.json --path-step-attempts 1 \
  examples/body-codegen/source-condition-cases.gooo.fixture

gooo body-construct \
  --source examples/body-codegen/source-condition-cases.gooo.fixture \
  --entry Main --model out/choice-model/model-choice-v1.json \
  --construction-cases examples/body-codegen/source-condition-construction-cases.json \
  --cases examples/body-codegen/source-condition-evaluation-cases.json \
  --attempts 8 --out out/choice-native

gooo body-construct --source out/choice-native/original.gooo \
  --construction out/choice-native/construction.json \
  --cases examples/body-codegen/source-condition-evaluation-cases.json
```

Each fresh construction makes one initial prediction. Later candidate checks
reuse that ordering. Saved replay uses the selected body and makes zero new
predictions; the model file is no longer needed. Native execution requires the
Go 1.27.2 toolchain on the host.

Omit `--path-model` or `--model` for deterministic candidate ordering. An explicit
model file that cannot be read produces an error. The declared-case model's
current fixed ranking mode does not combine with sampling, repeated model
feedback or an external execution oracle.

## What the current model has shown

The choice model has 12,818 FP32 parameters, occupying 51,272 bytes for the weight
arrays. Training and inference run locally in Go. It reads 1–128 authored output
cases and up to 16 binary choices, using each choice's source context before
pooling case features. Older shared-mean and global-pooling model files remain
supported.

The [SDK study](https://github.com/kimjooyoon/gooo-decision-runtime/tree/3f032abfc41cf0b2082949fede4abb8f9919a1b6/studies/choice-context-learning-20261010)
used 388 related Gooo documents, with 32 reserved for training. Among the other
356, the first proposed body satisfied all cases in 177 deterministic runs,
180 global-model runs and 202 choice-model runs. Some families regressed. These
results describe that finite corpus and its declared requirements.

The [compiler observation](../research/choice-contract-cli-20261010/README.md)
used three previously published examples. Total candidate attempts changed from
5 to 4, with first-choice completion at 2/3 for both methods. Native construction
and model-free replay each passed 24/24 output checks. Model prediction took a
median 46.250 microseconds; complete model-based construction took 4.26–5.20ms,
including model loading, and was slower than deterministic construction in these
small examples. No new training was performed for that compiler observation.

Declared-case completeness and separate caller evaluation remain separate
measurements. Unlisted inputs remain unmeasured. See the [model guide](../declared-contract-model.md)
for model formats, recorded identities and earlier observations, and the
[0.6.25 guide](0.6.25-dev.md) for the condition syntax and retained path-model
feedback mode.
