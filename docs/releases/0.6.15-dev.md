# Gooo 0.6.15 development guide

A body-fill plan can now contain a candidate with the wrong type or an expression
that fails on its training input. Gooo keeps the failure and tries the next
assignment. The result shows which candidates ran, which were rejected, and how
many original cases matched.

The [release page](https://github.com/kimjooyoon/meta-ontology-go/releases) identifies
published archives and their exact source commits. Native execution requires Go
1.27.1. This version retains decision runtime v0.2.26-experimental.

## Try five assignments

```sh
gooo body-construct \
  --source examples/caller-fill-rejection/budget.gooo.fixture --entry Main \
  --construction-cases examples/caller-fill-rejection/construction-cases.json \
  --cases examples/caller-fill-rejection/evaluation-cases.json \
  --attempts 5 --out /tmp/my-fill-construction
```

Use a fresh output directory. This example calculates the next budget and caps
it at a limit. Its five source-owned assignments include an incorrect Boolean
value and an expression that divides by zero. Initial preparation scores three
candidates and records two rejections. Whole-program construction counts all five
assignments, including the rejected ones, against its attempt budget.

With `--attempts 3`, one combination runs and two assignments are rejected. The
result is `PARTIAL_FINITE` and matches 1/4 later evaluation rows. With five attempts,
three combinations run, two are rejected, and the chosen program matches 4/4.
Original actual/expected values stay in the record, including integers above 2^53.
A partial logical result returns exit code 0; read `decision` and `stop_reason`.

## Read failures separately from scores

`rejected_candidates` records initial failures at `TYPECHECK` or
`TRAINING_EVALUATION`. Those candidates have no invented success score. The
`gooo/joint-construction/v5` history retains the rejected assignment, every hole
expression, source/plan identities and the whole-program rejection reason.
Rejected attempts do not execute a native program. Earlier scored activities
remain visible when a later activity rejects the combination.

Source-local holdouts remain outside ranking. `COMPLETE_FINITE` concerns the
supplied local training and caller construction cases. Later evaluation reports
its own actual/expected values after selection. These finite results describe the
provided inputs; broader behavior needs additional cases.

When only one valid fill candidate remains, selection is deterministic and makes
zero model predictions. If all candidates fail, the result retains every failure
and stops before loading the fill model. Malformed source/contracts, cancellation,
holdout evaluator failures and native execution failures still stop the request.

## Replay and reuse

```sh
gooo body-construct \
  --source /tmp/my-fill-construction/original.gooo \
  --construction /tmp/my-fill-construction/construction.json \
  --cases examples/caller-fill-rejection/evaluation-cases.json

gooo body-compose \
  --source /tmp/my-fill-construction/selected.gooo --entry Main \
  --cases examples/caller-fill-rejection/evaluation-cases.json
```

Saved replay rechecks the complete attempted history with zero new inference.
The selected source is ordinary Gooo and can be used on later inputs. Valid fill
histories retain v4; the earlier saved records remain readable.

## Small-model observation and Gooo feedback

The [mixed fixture](../../examples/caller-fill-rejection/mixed-model.gooo.fixture)
combines these five assignments with three binary record choices: 40 declared
combinations. In the [frozen feature observation](../research/caller-fill-rejection-20261009/README.md),
fixed ordering tried all 40 (16 rejected), while the existing graph QAT model tried
five (two rejected). Both selected the same source and matched four later rows.
The model orders record choices; complete fill assignments follow source order.
No new model was trained. This observation covers related finite examples.

The public [ecosystem workbench](https://github.com/kimjooyoon/gooo-ecosystem-workbench)
uses Gooo rules to carry an original failing caller input into the next round and
adjust the attempt budget. Its recorded loop took five rounds and 13 attempts:
five rejected combinations plus eight native combinations. Final separate
evaluation matched 4/4. Repeated attempts remain counted.
