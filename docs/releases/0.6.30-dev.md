# Gooo 0.6.30-dev: continue construction and preserve helper context

[Gooo 0.6.30-dev](https://github.com/kimjooyoon/meta-ontology-go/releases/tag/v0.6.30-dev)
publishes accepted source `d75cbb23db560c334301035a7243eaea167aad53` with
Go 1.27.2 and decision runtime 0.2.41. The release includes four platform
archives, checksums, version metadata and its source-bound evidence.
Historical preparation observations below keep their original producer and timing.

## What changes for a Gooo program

When a declared candidate fails during local evaluation, Gooo keeps its failure
and the inputs it reached. Record assembly can continue to the next candidate
within the source attempt budget. An incomplete evaluation receives no completed
case score. If every candidate fails, the failed construction keeps its original
receipt. Canceling a request stops it; cancellation does not start fallback work.

Body-fill assignments can call fixed pure Gooo helpers, including helpers added
by the chosen expression. Composition assembles required helper bodies first.
The selected source keeps helper identities and body digests through Go emission
and saved replay. See the [helper-fill example](../../examples/caller-fill-calls/README.md)
for integer, multiple-argument and declared-record call support.

Context-dependent expression search now keeps the bounded candidate pool derived
at the actual helper checkpoint. A later caller combination uses that original
pool and reevaluates its expression with the current helper. This fixes valid
constructions that previously stopped because the pool was regenerated against
an earlier helper body. The pool's planning source and the current execution
source have separate digests. Expressions that a fresh grammar pass could propose
under different helpers remain outside this fixed pool.

## Try construction and saved replay

From a compiler checkout containing the example files, install the published
version with Go 1.27.2. Use a new output directory:

```sh
GOBIN="$PWD/.gooo-bin" GOWORK=off GOTOOLCHAIN=go1.27.2 \
  go install github.com/kimjooyoon/meta-ontology-go/cmd/gooo@v0.6.30-dev
export PATH="$PWD/.gooo-bin:$PATH"
gooo body-construct --source examples/caller-search-checkpoint/main.gooo.fixture \
  --entry Main --attempts 8 \
  --construction-cases examples/caller-search-checkpoint/construction-cases.json \
  --cases examples/caller-search-checkpoint/evaluation-cases.json \
  --out checkpoint-result --format json > checkpoint-result.json

gooo body-construct --report checkpoint-result.json --format markdown
gooo body-construct --source checkpoint-result/original.gooo \
  --construction checkpoint-result/construction.json \
  --cases examples/caller-search-checkpoint/evaluation-cases.json --format text
```

`Seed` selects doubling, then `Build` chooses an offset using that helper.
The [recorded development observation](../../examples/caller-search-checkpoint/README.md)
used clean source `722161a1` once, followed by one saved replay. Both native
evaluation and replay matched 3/3 supplied cases. The first combination was
selected from fourteen fixed-pool combinations, with an eight-attempt budget.

Whole-command wall time was 1.00 seconds for construction and evaluation, and
0.36 seconds for replay. Maximum RSS was 87,605,248 and 85,082,112 bytes. Those
single runs include compilation and subprocesses. They are historical
development observations, not measurements of a published 0.6.30 binary or a
controlled performance comparison.

## Read the input-exposure counts

Recorded local search, record and fill evaluations now contribute the helper
arguments they actually used. This includes rejected candidates and the entered
prefix of a failed case. Source-search and fill preflight also keep their original
observations at each source checkpoint. Exact integers, optional fields and
repeated calls keep their typed identity.

An evaluation can pass while using an input already encountered inside a failed
candidate. In the [fill-history example](../../examples/caller-fill-history/README.md),
3/3 evaluation cases pass, two inputs overlap construction and one remains
unknown. In the helper-checkpoint observation, all three remain unknown. These
counts answer different questions. Missing or partial capture cannot establish
that an input was unused, and model-training exposure remains unknown.

Saved replay checks new histories against their source and actual deterministic
evaluations. Replaying an explicitly recorded preflight repeats that preflight
work. Historical receipts keep their original absence of observations. Keep the
matching compiler for older receipt formats. The
[local-call contract](../local-call-observations.md) defines the capture limits.

## Use the existing small decision model

The compiler continues to use Go decision-runtime 0.2.41 and the existing public
model files. This release changes compiler behavior and reporting;
it introduces no new weights or model-quality result.

The [model-to-fill example](../../examples/caller-model-fill/README.md) connects
one source-relative prediction to a helper's branch ordering, then fills the
dependent body deterministically. Its original model proposal matched 0/4 declared
output cases; the next permitted combination matched 4/4. The failed first result stays
visible. The [model guide](../source-relative-contract-model.md) gives the public
file, checksum and supported input shapes. Omitting a model uses deterministic
ordering; saved replay makes no new predictions.

## Publication contract

The [accepted-source CI](https://github.com/kimjooyoon/meta-ontology-go/actions/runs/38138576156)
and [native release checks](https://github.com/kimjooyoon/meta-ontology-go/actions/runs/38138575981)
bind the release to source `d75cbb23`. The native checks cover Linux amd64,
macOS amd64, macOS arm64 and Windows amd64. The release's `release-manifest.json`,
`release-report.json`, `release-eligibility.json` and `version.json` identify
its source and artifact set; `SHA256SUMS` covers the eight other assets.

The [publication run](https://github.com/kimjooyoon/meta-ontology-go/actions/runs/38140655223)
published all nine assets. The public macOS arm64 archive was downloaded, checked
against its checksum and source metadata, and installed. This installation check
did not repeat model training, predictions or the historical native observations.

Both new profiles construct and replay their own finite example. The search
profile checks its fixed candidate pool and complete saved construction history.
The helper-fill profile checks the failed-call prefix, prepared-source preflight,
helper identities and separate training/holdout results. Each profile requires
3/3 native output checks against separate cases and zero new model calls. Helper-fill retains
two overlapping inputs and one unknown input; search retains three unknown inputs.
Repeating those examples on four platforms establishes platform coverage for
those cases. It does not create a larger set of independent language tasks.
