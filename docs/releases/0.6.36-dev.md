## Apply one source activity to each value

```gooo
return Decisions{values: map_values(input.values, IsPackageLabel)}
```

The [collection-map workspace](../../examples/collection-map/README.md) supplies
the complete record declarations, mapper, inputs and commands. It transforms
an ordered scalar collection using a fixed unary activity declared in Gooo.
Input and output types may differ. Duplicates keep distinct positions.

The profile accepts at most 256 Integer, Text or Boolean elements. Each map
reserves `256 × (1 + mapper call bound)` static calls, including enclosing loop
multipliers, within the existing 4,096-call budget. Actual input length can be
smaller. Record elements, filtering, captured functions and parallel evaluation
remain future work.

The runtime records the mapper's stable identity, input coordinates and each
attempted element's read interval. Saved-origin readers can inspect those
records without executing the producing program. A retained read interval
describes an observed evaluation; it does not establish every scalar dependency.

## Let an agent inspect its compiler

```sh
gooo version --build --json
```

The existing build JSON adds `pure_body_limits`, derived directly from the
validator constants:

| Key | Maximum |
| --- | ---: |
| `max_record_types` | 16 |
| `max_fields_per_record` | 32 |
| `max_elements_per_collection` | 256 |
| `max_activity_calls_per_invocation` | 4,096 |
| `max_activities_per_call_closure` | 32 |
| `max_activity_call_depth` | 16 |
| `max_iterations_per_counted_loop` | 1,024 |
| `max_syntactic_collection_iteration_product` | 65,536 |

Record count covers the whole loaded body-generation semantic model, including
unused record declarations. Call-closure size includes the entry and reachable
activities; call depth counts edges from the entry at depth zero. These maxima
help an agent prepare a program. Type, source and runtime checks still determine
whether that program is accepted.
The fields do not describe wall time, memory availability or all supported syntax.
An absent field in an older binary means unknown. The command performs no model
call and does not manufacture a source revision when VCS identity is unavailable.

## Native release checks and their limits

The existing package smoke runner now includes the map workspace on all four
native release platforms. Each run executes and replays two authored input rows:
five Boolean decisions and an empty array. A separate regular-expression oracle
checks the mapper's byte-loop rule. The shared reader checks original source,
inputs, program identity and the saved receipt; model calls must remain zero.

The original readiness artifacts retain successful execution and saved replay
on Linux amd64, macOS amd64, macOS arm64 and Windows amd64. The two authored rows
matched on each platform with zero model calls; the saved-parent digest and
each mapped input position were checked. Repeating these two inputs on four
platforms adds platform coverage. The release keeps 26 structural cases,
eight publication activities and nine release assets.

All nine public assets were streamed and hashed against their published metadata;
eight entries also matched the published
[SHA256SUMS](https://github.com/kimjooyoon/meta-ontology-go/releases/download/v0.6.36-dev/SHA256SUMS).
The macOS arm64 archive reported the source above, clean VCS metadata,
Go 1.27.2, SDK v0.2.51-experimental and all eight body limits. The download
inspection read version metadata only; the map observations belong to the
original readiness run. Those observations establish this finite release scope.
