# Gooo 0.6.14 development guide

Gooo can now reconsider a complete `source_fill` assignment using the results of
its caller. Conditions, variable values and return expressions can be filled
together. Each candidate is checked, compiled and executed within a finite budget.
Original local examples and caller expectations remain attached to the result.

The [release page](https://github.com/kimjooyoon/meta-ontology-go/releases) lists
published archives and their exact source commits. Native execution uses Go
1.27.1 and decision runtime v0.2.26-experimental.

## Fill a condition and an assignment together

```sh
gooo body-construct \
  --source examples/caller-source-fill/budget.gooo.fixture --entry Main \
  --construction-cases examples/caller-source-fill/construction-cases.json \
  --cases examples/caller-source-fill/evaluation-cases.json \
  --attempts 3 --out /tmp/my-budget-construction
```

The helper calculates the next budget and keeps the value within a declared
limit. Its local example does not distinguish three complete assignments:

1. A late boundary condition leaves an unbounded result.
2. An earlier boundary condition keeps the wrong value at the limit.
3. The correct boundary and cap satisfy the caller too.

The three-attempt run matches the local and caller examples, then four separate
evaluation inputs. Using `--attempts 2` retains a partial result and final 1/4.
A logical partial result returns exit code 0; inspect `decision`, the stop reason
and the original actual/expected values.

## Read the evidence

`gooo/joint-construction/v4` adds `source_fill_index` selectors and a
`fill_candidates` array. Each candidate keeps source and plan identities, every
hole expression, original training cases and separate source-local holdout cases.
`local_passed/local_total` uses training cases only. Source-local holdout outcomes
never affect ranking or `COMPLETE_FINITE`; that status concerns the supplied local
training and caller cases. Final evaluation runs after selection.

Source-declared or grammar-derived assignments retain the existing 2..16 candidate
and hole/type contracts. Whole-program construction supports 1..16 assembly bodies
and 1..64 combinations. Record choices, integer search and multi-hole fills can
participate together. Existing v1/v2/v3 histories keep their original behavior.

## Replay or use the selected code

```sh
gooo body-construct \
  --source /tmp/my-budget-construction/original.gooo \
  --construction /tmp/my-budget-construction/construction.json \
  --cases examples/caller-source-fill/evaluation-cases.json

gooo body-compose \
  --source /tmp/my-budget-construction/selected.gooo --entry Main \
  --cases examples/caller-source-fill/evaluation-cases.json
```

The first command rechecks the saved candidate history before evaluation. The
second compiles the already selected ordinary Gooo source. Both make zero new
model predictions. The directory also retains generated Go files for reuse.

## Optional small models and automatic feedback

`--model` orders record choices. `--fill-model` accepts the existing compatible
operation-classifier profile during initial source-fill preparation. These are
different model profiles. With no model option, selection is deterministic.
The complete assignment stays source-owned; the model suggests the initial choice.

The [mixed fixture](../../examples/caller-source-fill/mixed-model.gooo.fixture)
adds three record choices to the budget helper, for 24 combinations. In the
original frozen observation, fixed ordering tried 24 combinations and the
unchanged own graph QAT model tried three; both selected the same code and matched
four final inputs. The graph model ordered record choices, while fills followed
source order. These observations cover two related programs and finite cases.

The public [ecosystem workbench](https://github.com/kimjooyoon/gooo-ecosystem-workbench)
uses Gooo rules to retain failed caller examples and increase the budget. Its
final holdout runs after the loop ends. The original source-fill loop retained
one counterexample across four rounds/seven combinations and matched final 4/4.
Repeated combinations remain counted. No new model was trained for these runs.

Initial source-fill preflight still checks all assignments and stops on invalid
ones. Integer-search rejection rows retain their separate continuation behavior.
Cancellation, native toolchain and compiled-program failures still stop requests.

## 한국어

`언제 멈출지`와 `멈출 때 어떤 값을 남길지`처럼 함께 맞춰야 하는 빈칸을
후보 하나로 묶어 채웁니다. 실제 호출 결과가 맞지 않으면 다음 후보를 시도합니다.
실패한 예제와 기대값을 남기고, Gooo 피드백 규칙으로 다음 조립에 이어 씁니다.
선택에 사용한 사례와 별도 평가를 구분하며, 선택된 코드는 일반 Gooo 소스로
저장해 다음 입력에도 사용할 수 있습니다.
