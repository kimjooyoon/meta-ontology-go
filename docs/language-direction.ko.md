# Gooo가 만들고 있는 언어와 작은 모델

업데이트: 2026-10-03. 전체 입력 모델 학습, 환경별 재현성, SDK v0.2.15 공개까지 반영했습니다.

**지금의 위치:** Gooo로 허용된 코드 조립 경로를 표현하고, 자체 소형 모델이
시도할 순서를 제안하며, 실행 결과를 다음 판단과 개발에 연결하고 있습니다.
공개 컴파일러에는 V3 모델 연결이 들어가 있고, 새 V4 모델은 연구 실행기와
Go SDK에서 실행할 수 있습니다. 다음 단계는 새 모델로 실제 Gooo 코드를 생성하고
빌드·실행하는 통합 관측입니다. 아래에서 사용 가능한 경로와 진행 상태를 설명합니다.

## 어떤 작업을 쉽게 만들고 싶은가

“이 조건에서는 이 값을 쓰고, 다른 조건에서는 저 연산을 하며, 결과는 이
예시들을 만족해야 한다”는 의도를 코드와 연결하고 싶습니다. 그 연결이
변경과 반복 생성 과정에서도 남아 있어야 다음 작업을 자동으로 이어갈 수 있습니다.

설계도와 작은 조립 작업장을 떠올리면 이해하기 쉽습니다. Gooo 선언은
부품의 의미와 연결 규칙을 표현합니다. 소형 모델은 허용된 조립 경로 중
시도할 순서를 제안합니다. 컴파일러는 타입과 조건을 확인하고 Go 코드를
만듭니다. Go로 만든 실험 실행기는 그 결과를 빌드하고 실행합니다.
실패한 예시는 다음 시도에 전달되고, 작업 기록에는
성공한 부분과 아직 확인하지 못한 부분이 함께 남습니다.

현재 경로 계획에는 원본 Gooo, 한국어·영어 의도, 허용된 대안, 유한한 입출력
예시가 들어갑니다. 원본과 계획 문서는 해시로 연결됩니다. 조건식, 변수
할당, 참조, 중첩 분기, 연산 순서를 조합하는 제한된 정수 함수부터 실험하고
있습니다. 경로 계획의 일부는 JSON으로 표현하며, 이 경험을 바탕으로
Gooo 자체의 표현 범위를 넓혀갈 예정입니다.

### 한 번의 조립을 따라가 보면

설명을 위한 예로 “값이 기준보다 작으면 보정하고, 마지막에 두 배로 만든다”는
함수를 생각할 수 있습니다. 계획은 비교 조건, 보정 연산, 마지막 연산에 각각
두 대안을 줍니다. 세 선택을 조합하면 여덟 개의 함수 바디가 생깁니다.
모델은 원본 구조와 의도를 보고 먼저 시도할 조합을 고릅니다. 입출력 예시에서
실패하면 실제 입력·기대값·결과가 다음 판단의 문맥이 됩니다. 이 선택 단계는
유한 평가기로 바디를 평가합니다. 선택된 바디를 Go로 생성한 뒤 실험 실행기가
별도로 빌드하고 실행하며, 각각의 결과가 원본 선언에 연결됩니다.

이 예시는 현재의 유한 경로 조립 방식을 풀어 쓴 것입니다. 실제 호출 계약과
실행 가능한 자료는 [바디 생성 안내](language/body-codegen.md)와
[세 선택 모델 안내](three-choice-path-model.md)에 있습니다. 현재는 대안과
예시를 계획에 제공하며, 자연어에서 계획 자체를 찾는 능력은 다음 연구 범위입니다.

## 언어·모델·실행기가 맡는 일

IR은 원본 선언을 컴파일러가 다루기 쉬운 구조로 옮긴 중간 표현입니다.
예를 들어 조건, 대입할 변수, 두 분기의 연산을 각각 이름 있는 부품처럼
다룹니다. 모델은 선언된 부품의 조합에 순위를 주고, 타입 검사와 예시 평가가
조립 결과를 확인합니다. 이 과정을 언어의 기능으로 다루는 것이 여기서 말하는
메타프로그래밍입니다.

| 구성 | 현재 역할 | 살펴볼 곳 |
| --- | --- | --- |
| Gooo / meta-ontology-go | 의미 ID, 선언, IR, Go 생성, 실제 실행, 관측 기록 | [컴파일러](https://github.com/kimjooyoon/meta-ontology-go) |
| 자체 소형 모델 | 세 개의 이진 선택으로 이루어진 여덟 경로의 순위 제안 | [Hugging Face 모델](https://huggingface.co/asketeddy/gooo-shared-judgment-tiny-v1) |
| Go 실행 라이브러리 | 모델 로딩, 배열 기반 계산, 요청별 작업 메모리, 피드백 탐색 | [gooo-decision-runtime](https://github.com/kimjooyoon/gooo-decision-runtime) |
| 실험 저장소 | 데이터 생성, GPU 학습, 품질·속도·메모리 비교, 원본 증거 공개 | [연구 저장소](https://github.com/kimjooyoon/gooo-neural-decision-experiments) |

학습에는 로컬 GPU의 MPS와 오프라인 PyTorch를 사용합니다. 모델 로딩과
추론, 탐색, 코드 조립, 측정 도구는 Go로 구성합니다. 모델이 연결되지 않거나
입력이 모델의 지원 범위를 넘으면 전체 입력을 보존하고 결정론적 경로로
이어갑니다. 이때 모델 호출 수는 0으로 기록됩니다.

## 차별점으로 발전시키려는 부분

1. **의도와 생성물의 연결을 언어에 남기기.** 이름이 바뀌어도 의미 ID로
   같은 대상을 추적하고, 생성된 구조와 실행 결과를 원본 선언에 연결합니다.
2. **작은 판단을 반복해서 프로그램을 조립하기.** 모델의 역할을 조건 선택과
   세부 경로 순위처럼 좁게 잡아 저사양 환경에서도 실험할 수 있게 합니다.
3. **완전성을 여러 축으로 관찰하기.** 생성률, 예시 충족률, 실행 여부,
   원본으로의 역추적, 미관측 경계를 각각 기록합니다. 다음 단계가 무엇인지
   시스템이 읽을 수 있도록 첫 미해결 항목과 원인을 보존합니다.
4. **바뀐 이유를 재현할 수 있게 만들기.** 입력, 모델, 도구, 소스 리비전,
   시도한 경로와 실패 예시를 연결합니다. 비교 조건이 같을 때 수치 증감을
   계산하고 조건이 바뀌면 그 변경을 드러냅니다.

이 네 가지를 함께 구현하는 것이 프로젝트의 목표입니다. 다른 언어와의
비교는 앞으로 같은 과제·도구·예산으로 수집한 증거를 바탕으로 확장합니다.

### 차별점을 어떤 수치로 확인할 것인가

| 발전시키려는 성질 | 확인할 지표 | 현재 근거와 다음 질문 |
| --- | --- | --- |
| 의도에서 동작까지 연결 | 전체 예시를 충족한 함수 비율, 개별 예시 충족률 | 유한 정수 함수에서 관측했으며 새 과제와 타입으로 확장 예정 |
| 작은 판단으로 조립 비용 줄이기 | 추가 후보 수, 모델 호출 수, 생성·실행 시간 | 고정된 여덟 경로에서 비교했으며 더 큰 계획으로 확장 예정 |
| 한·영 의도를 일관되게 받기 | 양쪽 모두 유효한 경로를 고른 쌍, 함께 틀린 쌍 | 전체 입력을 보존한 표현 비교 진행 |
| 바뀐 이유를 추적하기 | 원본·모델·결과 연결, 미해결 항목의 변화 | 내용 해시와 `completeness-delta`로 관측 연결 |
| 작은 장치에서도 실행하기 | 저장 크기, 상주 배열, 전체 RAM, 지연 시간 | 각 비용을 따로 측정하며 새 모델과 실행 환경의 재현성 확인 중 |

완전성은 작업 지시서의 항목별 체크 기록에 가깝습니다. 여기서 “368/512”는
512개 입력 중 첫 후보가 제공된 16개 예시를 모두 만족한 수입니다. 일부
예시만 맞은 정도, 다음 시도에서 완성된 수, 실행 권한처럼 아직 관측하지 못한
조건도 별도로 남깁니다. 이 기록이 다음 개발 작업을 고르는 재료가 됩니다.

숫자는 다음처럼 읽으면 됩니다. 모델이 어떤 경로에 준 0.8이라는 점수는
선택 분포의 값입니다. 16개 예시 중 12개를 통과했다면 그 예시 집합의
충족률은 75%입니다. 원본 연결이나 실행 권한을 아직 관측하지 못했다면
해당 항목은 `UNKNOWN`으로 남습니다. 서로 다른 질문에 답하는 세 기록을
함께 보여주어야, 다음에 무엇을 고칠지 판단할 수 있습니다.

## 컴파일러에 연결된 모델과 실행 관측

공유 판단 모델은 256→8→2 네트워크를 세 번 재사용하며 학습 파라미터는
2,072개입니다. 같은 초기화 규칙으로 만든 dense 대조군과 함께 총 3,200회의
GPU 업데이트를 수행했고 FP32, 학습 후 삼진 양자화(PTQ), 양자화를 고려한
학습(QAT) 결과를 공개했습니다.

| 관측 | 결과 | 읽는 방법 |
| --- | --- | --- |
| 개발용 512개 표현의 첫 선택으로 모든 예시 충족 | dense FP32 95개 → shared FP32 113개 | 이전에 관측한 개발 집합에서의 구조 비교 |
| 순위대로 탐색할 때 추가 시도 합계 | 1,572 → 1,469 | 같은 유한 후보 집합에서 탐색 부담 감소 |
| 같은 의도의 한국어·영어 첫 경로 불일치 | 256쌍 중 255쌍 | 의미 일관성 개선이 필요한 핵심 과제 |
| 압축 표현 비교 | 48쌍의 생성·실행 동작 일치 | 같은 모델의 저장 구조 변경을 확인 |
| 실제 코드 생성과 실행 | 96회 생성, 298회 모델 예측, 192회 프로그램 실행 | 선택 뒤 생성과 실제 실행을 바로 이어서 관측 |
| 제공한 실행 예시 | 2,304개 모두 충족 | 제한된 과제와 제공한 기대값 범위의 결과 |

압축 모델의 FP32 가중치는 8,288바이트, 삼진 가중치 파일은 446바이트입니다.
삼진 모델은 메모리에 2,096바이트의 텐서와 8바이트의 스케일을 두고 계산하며,
요청별 작업 배열은 3,200바이트입니다. 프로세스 전체 RAM에는 컴파일러와
실행 환경의 비용이 추가됩니다.

로컬 arm64 / Go 1.27.1 실험에서 예측 중앙값은 23.7–30.2µs,
새 프로세스에서의 전체 코드 생성 중앙값은 27.8–29.5ms였습니다. QAT의 전체
코드 생성 시간은 압축 후 소폭 증가했습니다. 첫 빌드의 캐시 비용과 느린
표본도 보고서에 남아 있습니다. CPU 수치는 코드 생성 프로세스가 한 코어를
기준으로 사용한 비율이며 중앙값은 83.7–84.6%였습니다. 컴퓨터 전체 사용률의
증가량은 이번 실험에서 측정하지 않았습니다.

[품질·언어별 결과](https://github.com/kimjooyoon/gooo-neural-decision-experiments/blob/main/docs/shared-three-judgment-results-20261003.md)와
[실제 코드 생성·시간·메모리 결과](https://github.com/kimjooyoon/gooo-neural-decision-experiments/blob/main/docs/compact-shared-native-results-20261003.md)에서
분모, 실패한 변형, 원본 기록을 확인할 수 있습니다. 모든 실행 기록의 첫 미해결
완전성 항목은 `permission_boundary`로 남아 있습니다.

### 최근에 드러난 병목: 의도 앞에 붙은 문장

“함수를 구성할 때,” 같은 도입 문구가 현재 모델의 선택에 큰 영향을 줍니다.
작업 지시서 앞에 인사말을 붙였더니 작은 조립기가 다른 부품을 고르는 상황에
비유할 수 있습니다. 여섯 모델의 가중치와 원본 Gooo, 후보, 기대값을 고정하고
다섯 표현 방식으로 총 92,160회 판단을 수집했습니다.

| shared FP32의 개발 집합 | 첫 경로에서 전체 예시 충족 /512 | 한·영 선택 불일치 /256쌍 |
| --- | ---: | ---: |
| 기존 도입 문구를 포함한 입력 | 113 | 255 |
| 실험에서 지정한 도입 문구를 제거한 입력 | 480 | 32 |
| 같은 도입 문구를 뒤로 옮긴 입력 | 233 | 180 |

480개라는 결과는 이미 관측한 과제를 학습 때의 문장 형식으로 바꾼 조건에서
나왔습니다. 공개 모델의 기존 입력 성과는 113/512로 유지합니다. 이 실험에서는
학습 업데이트를 추가하지 않았고, 실제 컴파일러는 사용자의 전체 입력을
보존합니다. 문장 조각, 위치, 정규화가 함께 바뀐 효과를 확인한 뒤,
전체 입력을 유지한 새 학습 조건을 비교했습니다. [진단 조건과 원본 기록](https://github.com/kimjooyoon/gooo-neural-decision-experiments/blob/main/docs/bilingual-wrapper-audit-results-20261003.md).

## 최신 연구: 입력을 그대로 둔 채 작은 판단 개선하기

위 진단을 바탕으로 네 가지 2,072개 파라미터 모델을 새로 초기화해 학습했습니다.
문장 조각의 위치를 쓰는 표현과 전체 빈도를 쓰는 표현, 원래 문장만 학습하는
조건과 다섯 표현을 학습하는 조건을 조합했습니다. 사용자 입력은 모두 보존했습니다.
위치와 조각 충돌 구조가 함께 달라지므로 효과의 세부 원인은 후속 비교로 좁혀갑니다.

| FP32 조건 | 첫 경로에서 전체 예시 충족 /512 | 추가 후보 수 합계 | 한·영 양쪽 유효 /256쌍 |
| --- | ---: | ---: | ---: |
| 위치 표현 · 원래 문장 | 113 (22.07%) | 1,469 | 1 |
| 위치 표현 · 다양한 문장 | 266 (51.95%) | 528 | 75 |
| 전체 조각 빈도 · 원래 문장 | 368 (71.88%) | 186 | 180 |
| 전체 조각 빈도 · 다양한 문장 | 320 (62.50%) | 326 | 132 |

같은 개발 과제를 반복 관측한 비교입니다. 세 번째 조건에서도 한·영 68쌍은
같은 오답을 골랐습니다. 새 접두·접미 표현에서 그 조건은 358/512와 368/512를
충족했지만, 네 번째 조건은 새 접미 표현에서 173/512로 내려갔습니다.
문장 다양화의 효과는 입력 표현과 함께 살펴봐야 한다는 결과입니다.

삼진 변형까지 열두 모델을 모두 공개했습니다. 세 번째 조건의 PTQ는 94/512,
QAT는 287/512였습니다. 또한 전체 조각 빈도는 “1을 더한 뒤 2를 곱한다”와
그 역순에 해당하는 통제 문장을 같은 특징으로 표현했습니다. 이 순서 구분
문제는 특징 배열을 비교한 반례이며, 실제 코드 생성 결과는 후속 관측 대상입니다.

이번 학습의 6,400회 업데이트는 로컬 MPS에서 42.18초 걸렸습니다. 학습
프로세스의 평균 CPU는 한 코어 기준 49.83%, 최대 RSS는 약 1.81GB였습니다.
Go 감사 도구는 25,824회 실제 판단과 학습 기록을 대조했습니다. 새 모델의
추론 지연과 전체 코드 생성 비용은 별도 측정이 남아 있습니다.
[전체 결과·실패한 변형·원본 자료](https://github.com/kimjooyoon/gooo-neural-decision-experiments/blob/main/docs/full-input-judgment-initial-results-20261003.md).

### 실행 환경이 바뀌었을 때 발견한 문제

arm64와 Linux에서 18,432개 입력의 첫 선택은 같았지만, 후순위까지 포함한
272개 후보 순위가 달랐습니다. 최대 점수 차이는 약 0.00000143이었고,
이 작은 차이가 부분 완성도 곡선에 영향을 주어 정확 비교가 실패했습니다.
이후 곱셈·덧셈의 반올림 시점을 명시한 규칙으로 두 환경에서 총 147,456회
호출을 수행했습니다. 새 규칙에서는 같은 18,432개 입력 쌍의 중간 계산값,
확률, 전체 후보 순위가 모두 정확히 일치했습니다. 부품을 잴 때 쓰는 자의
눈금을 맞춘 셈입니다. 첫 경로의 완성도와 완성까지의 추가 시도 수는 유지됐고,
일부 중간 예산의 부분 완성도는 양방향으로 소폭 달라졌습니다.
[원래 실패와 새 규칙의 전체 대조 자료](https://github.com/kimjooyoon/gooo-neural-decision-experiments/blob/main/docs/full-input-separate-arithmetic-results-20261003.md)를 함께 공개했습니다.

현재 컴파일러가 사용하는 SDK는 `v0.2.14-experimental`이며 V3 계약을
지원합니다. 새 V4 표현과 명시적 반올림 규칙은
[SDK v0.2.15-experimental](https://github.com/kimjooyoon/gooo-decision-runtime/releases/tag/v0.2.15-experimental)로
공개했습니다. SDK 소스 `59c8d34`에서 로컬 arm64와 Linux CI가 각각
18,432개 입력을 36,864회 판단했고, 저장된 중간 계산값·확률·전체 순위와
모두 일치했습니다. 이 단계의 학습 업데이트는 0회입니다.
[Linux SDK 실행 기록](https://github.com/kimjooyoon/gooo-decision-runtime/actions/runs/37070241916).

이제 연구용 계산을 실제 사용 라이브러리로 옮긴 상태입니다. 다음 통합 관측에서는
새 모델을 이용한 Gooo 생성 직후 Go를 빌드하고 실행할 계획입니다.
계획한 400회 생성과 800회 실행은
[사전 계획서](https://github.com/kimjooyoon/gooo-neural-decision-experiments/blob/daecfea3583614e006c960de263448a1645a9190/docs/full-input-sdk-native-protocol-20261003.md)의
목표 횟수이며, 결과가 수집되면 실제 완료 횟수와 실패한 지점을 함께 공개합니다.

앞으로의 차별점도 이 기록으로 판단하려 합니다. 같은 과제와 예산에서 필요한

얼마나 남는지, 그 과정에 시간과 메모리가 얼마나 드는지를 함께 공개합니다.

## 다음 개발의 우선순위

- **계산과 순서의 재현성:** SDK로 공개한 계산 규칙을 컴파일러로
  연결합니다. 문장의 연산 순서를 구별하면서 작은 배열로 표현하는 방법도
  비교합니다. 새 모델을 연결할 때 원문·후보·관측의 연결을 유지합니다.
- **한국어·영어와 Gooo 의미 연결:** 남은 데이터 분할·표현 조건을 평가하고
  새 과제로 확장합니다. 번역 쌍의 유효한 선택, 같은 오답, 추가 탐색 비용을
  함께 측정합니다.
- **완전성 변화 비교:** 현재 `completeness-delta`가 제공하는 이전·이후
  관측 비교를 자연어 탐색과 더 넓은 실행 프로필까지 확장합니다.
- **더 풍부한 언어 표현:** 더 다양한 타입과 조합을 표현하고 생성·역관측
  규칙을 함께 늘립니다. 각 기능은 실행 가능한 예시와 연결합니다.
- **반복 사용 비용:** 모델을 한 번 로드한 요청 처리의 지연, 동시성,
  프로세스 RAM을 분리 측정합니다. 원본 실험 기록에는 저장 예산을 둡니다.
- **배운 조립법의 재사용:** 반복해서 성공한 구조를 설명 가능한 언어 구성으로
  축적하고, 새 과제에서 탐색 횟수와 미해결 항목이 어떻게 달라지는지 봅니다.

## 참고하고 감사하는 연구

- **Solar-Lezama 외, SKETCH (2006):** 부분 프로그램과 기능 명세를 함께 두고
  빈 부분을 합성하는 접근에서 출발점을 얻었습니다.
  [Combinatorial Sketching for Finite Programs](https://people.csail.mit.edu/asolar/papers/asplos06-final.pdf).
- **Ellis 외, DreamCoder (2020/2021):** 신경망으로 프로그램 탐색을 돕고
  재사용 가능한 추상화를 쌓는 연구는 언어와 모델이 함께 발전하는 방향을
  생각하는 데 도움이 됩니다. [논문](https://arxiv.org/abs/2006.08381).
- **Balog 외, DeepCoder (2016/2017):** 입출력 예시에서 프로그램의 성질을
  예측해 탐색을 돕는 접근을 참고합니다. Gooo에서는 작은 판단이 전체 탐색
  비용을 얼마나 줄이는지 살피는 질문으로 이어집니다. [논문](https://arxiv.org/abs/1611.01989).
- **Laya / ConvAI Innovations:** 상태와 선택지를 주고 구조화된 판단을 받는
  인터페이스를 초기 실험에서 사용했습니다. 현재 자체 모델은 새로 초기화한
  가중치와 Gooo 데이터로 학습했습니다. [모델·구현 안내](https://huggingface.co/convaiinnovations/laya).
- **Ma 외, BitNet b1.58 (2024):** `-1, 0, 1` 가중치를 다루는 연구를 참고해
  삼진 저장과 QAT를 실험합니다. Gooo의 Go 실행기는 압축 파일을 배열로 풀어
  계산하며 저장 크기와 실행 메모리를 따로 측정합니다. [논문](https://arxiv.org/abs/2402.17764).
- **W3C PROV-O (2013):** 엔티티·활동·에이전트와 생성 관계를 연결하는
  어휘를 참고해 결과가 어디서 왔는지 추적합니다. [표준](https://www.w3.org/TR/prov-o/).
