# Gooo가 만들고 있는 언어와 작은 모델

업데이트: 2026-10-03. 구현, 모델, 실험을 함께 읽기 위한 현재 안내입니다.

## 어떤 작업을 쉽게 만들고 싶은가

“이 조건에서는 이 값을 쓰고, 다른 조건에서는 저 연산을 하며, 결과는 이
예시들을 만족해야 한다”는 의도를 코드와 연결하고 싶습니다. 그 연결이
변경과 반복 생성 과정에서도 남아 있어야 다음 작업을 자동으로 이어갈 수 있습니다.

설계도와 작은 조립 작업장을 떠올리면 이해하기 쉽습니다. Gooo 선언은
부품의 의미와 연결 규칙을 표현합니다. 소형 모델은 허용된 조립 경로 중
시도할 순서를 제안합니다. 컴파일러는 타입과 조건을 확인하고 Go 코드를
만들어 실행합니다. 실패한 예시는 다음 시도에 전달되고, 작업 기록에는
성공한 부분과 아직 확인하지 못한 부분이 함께 남습니다.

현재 경로 계획에는 원본 Gooo, 한국어·영어 의도, 허용된 대안, 유한한 입출력
예시가 들어갑니다. 원본과 계획 문서는 해시로 연결됩니다. 조건식, 변수
할당, 참조, 중첩 분기, 연산 순서를 조합하는 제한된 정수 함수부터 실험하고
있습니다. 경로 계획의 일부는 JSON으로 표현하며, 이 경험을 바탕으로
Gooo 자체의 표현 범위를 넓혀갈 예정입니다.

### 한 번의 조립을 따라가 보면

설명을 위한 예로 “값이 기준보다 작으면 보정하고, 마지막에 두 배로 만든다”는
함수를 생각할 수 있습니다. 계획은 비교 조건, 보정 연산, 마지막 연산에 각각
두 대안을 줍니다. 세 선택을 조합하면 여덟 개의 함수 바디가 생깁니다.
모델은 원본 구조와 의도를 보고 먼저 시도할 조합을 고릅니다. 입출력 예시에서
실패하면 실제 입력·기대값·결과가 다음 판단의 문맥이 됩니다. 선택된 바디는
Go로 생성되어 빌드와 실행을 거치고, 각각의 결과가 원본 선언에 연결됩니다.

이 예시는 현재의 유한 경로 조립 방식을 풀어 쓴 것입니다. 실제 호출 계약과
실행 가능한 자료는 [바디 생성 안내](language/body-codegen.md)와
[세 선택 모델 안내](three-choice-path-model.md)에 있습니다. 현재는 대안과
예시를 계획에 제공하며, 자연어에서 계획 자체를 찾는 능력은 다음 연구 범위입니다.

## 언어·모델·실행기가 맡는 일

| 구성 | 현재 역할 | 살펴볼 곳 |
| --- | --- | --- |
| Gooo / meta-ontology-go | 의미 ID, 선언, IR, Go 생성, 실제 실행, 관측 기록 | [컴파일러](https://github.com/kimjooyoon/meta-ontology-go) |
| 자체 소형 모델 | 세 개의 이진 선택으로 이루어진 여덟 경로의 순위 제안 | [Hugging Face 모델](https://huggingface.co/asketeddy/gooo-shared-judgment-tiny-v1) |
| Go 실행 라이브러리 | 모델 로딩, 배열 기반 계산, 요청별 작업 메모리, 피드백 탐색 | [gooo-decision-runtime](https://github.com/kimjooyoon/gooo-decision-runtime) |
| 실험 저장소 | 데이터 생성, GPU 학습, 품질·속도·메모리 비교, 원본 증거 공개 | [연구 저장소](https://github.com/kimjooyoon/gooo-neural-decision-experiments) |

학습에는 로컬 GPU의 MPS와 오프라인 PyTorch를 사용합니다. 모델 로딩과
추론, 탐색, 코드 조립, 측정 도구는 Go로 구성합니다. 모델이 연결되지 않거나
입력이 모델의 지원 범위를 넘으면 전체 입력을 보존하고 결정론적 경로로
이어갑니다. 이때 모델 호출 수는 0으로 기록됩니다.

## 차별점으로 발전시키려는 부분

1. **의도와 생성물의 연결을 언어에 남기기.** 이름이 바뀌어도 의미 ID로
   같은 대상을 추적하고, 생성된 구조와 실행 결과를 원본 선언에 연결합니다.
2. **작은 판단을 반복해서 프로그램을 조립하기.** 모델의 역할을 조건 선택과
   세부 경로 순위처럼 좁게 잡아 저사양 환경에서도 실험할 수 있게 합니다.
3. **완전성을 여러 축으로 관찰하기.** 생성률, 예시 충족률, 실행 여부,
   원본으로의 역추적, 미관측 경계를 각각 기록합니다. 다음 단계가 무엇인지
   시스템이 읽을 수 있도록 첫 미해결 항목과 원인을 보존합니다.
4. **바뀐 이유를 재현할 수 있게 만들기.** 입력, 모델, 도구, 소스 리비전,
   시도한 경로와 실패 예시를 연결합니다. 비교 조건이 같을 때 수치 증감을
   계산하고 조건이 바뀌면 그 변경을 드러냅니다.

이 네 가지를 함께 구현하는 것이 프로젝트의 목표입니다. 다른 언어와의
비교는 앞으로 같은 과제·도구·예산으로 수집한 증거를 바탕으로 확장합니다.

## 지금까지의 성과와 배운 점

공유 판단 모델은 256→8→2 네트워크를 세 번 재사용하며 학습 파라미터는
2,072개입니다. 같은 초기화 규칙으로 만든 dense 대조군과 함께 총 3,200회의
GPU 업데이트를 수행했고 FP32, 학습 후 삼진 양자화(PTQ), 양자화를 고려한
학습(QAT) 결과를 공개했습니다.

| 관측 | 결과 | 읽는 방법 |
| --- | --- | --- |
| 개발용 512개 표현의 첫 선택으로 모든 예시 충족 | dense FP32 95개 → shared FP32 113개 | 이전에 관측한 개발 집합에서의 구조 비교 |
| 순위대로 탐색할 때 추가 시도 합계 | 1,572 → 1,469 | 같은 유한 후보 집합에서 탐색 부담 감소 |
| 같은 의도의 한국어·영어 첫 경로 불일치 | 256쌍 중 255쌍 | 의미 일관성 개선이 필요한 핵심 과제 |
| 압축 표현 비교 | 48쌍의 생성·실행 동작 일치 | 같은 모델의 저장 구조 변경을 확인 |
| 실제 코드 생성과 실행 | 96회 생성, 298회 모델 예측, 192회 프로그램 실행 | 선택 뒤 생성과 실제 실행을 바로 이어서 관측 |
| 제공한 실행 예시 | 2,304개 모두 충족 | 제한된 과제와 제공한 기대값 범위의 결과 |

압축 모델의 FP32 가중치는 8,288바이트, 삼진 가중치 파일은 446바이트입니다.
삼진 모델은 메모리에 2,096바이트의 텐서와 8바이트의 스케일을 두고 계산하며,
요청별 작업 배열은 3,200바이트입니다. 프로세스 전체 RAM에는 컴파일러와
실행 환경의 비용이 추가됩니다.

로컬 arm64 / Go 1.27.1 실험에서 예측 중앙값은 23.7–30.2µs,
새 프로세스에서의 전체 코드 생성 중앙값은 27.8–29.5ms였습니다. QAT의 전체
코드 생성 시간은 압축 후 소폭 증가했습니다. 첫 빌드의 캐시 비용과 느린
표본도 보고서에 남아 있습니다. CPU 수치는 코드 생성 프로세스가 한 코어를
기준으로 사용한 비율이며 중앙값은 83.7–84.6%였습니다. 컴퓨터 전체 사용률의
증가량은 이번 실험에서 측정하지 않았습니다.

[품질·언어별 결과](https://github.com/kimjooyoon/gooo-neural-decision-experiments/blob/main/docs/shared-three-judgment-results-20261003.md)와
[실제 코드 생성·시간·메모리 결과](https://github.com/kimjooyoon/gooo-neural-decision-experiments/blob/main/docs/compact-shared-native-results-20261003.md)에서
분모, 실패한 변형, 원본 기록을 확인할 수 있습니다. 모든 실행 기록의 첫 미해결
완전성 항목은 `permission_boundary`로 남아 있습니다.

### 최근에 드러난 병목: 의도 앞에 붙은 문장

“함수를 구성할 때,” 같은 도입 문구가 현재 모델의 선택에 큰 영향을 줍니다.
작업 지시서 앞에 인사말을 붙였더니 작은 조립기가 다른 부품을 고르는 상황에
비유할 수 있습니다. 여섯 모델의 가중치와 원본 Gooo, 후보, 기대값을 고정하고
다섯 표현 방식으로 총 92,160회 판단을 수집했습니다.

| shared FP32의 개발 집합 | 첫 경로에서 전체 예시 충족 /512 | 한·영 선택 불일치 /256쌍 |
| --- | ---: | ---: |
| 기존 도입 문구를 포함한 입력 | 113 | 255 |
| 실험에서 지정한 도입 문구를 제거한 입력 | 480 | 32 |
| 같은 도입 문구를 뒤로 옮긴 입력 | 233 | 180 |

480개라는 결과는 이미 관측한 과제를 학습 때의 문장 형식으로 바꾼 조건에서
나왔습니다. 공개 모델의 기존 입력 성과는 113/512로 유지합니다. 이 실험에서는
학습 업데이트를 추가하지 않았고, 실제 컴파일러는 사용자의 전체 입력을
보존합니다. 문장 조각, 위치, 정규화가 함께 바뀐 효과를 확인했으므로 다음에는
각 영향을 나누어 비교할 예정입니다. [전체 조건과 원본 기록](https://github.com/kimjooyoon/gooo-neural-decision-experiments/blob/main/docs/bilingual-wrapper-audit-results-20261003.md).

## 어떤 순서로 발전하고 있는가

| 단계 | 현재 상태 | 다음 단계에 남기는 것 |
| --- | --- | --- |
| Laya로 구조화된 선택 실험 | 초기 실험과 기록 공개 | 의도·선택지·실패 문맥을 연결하는 호출 방식 |
| Gooo 전용 자체 모델 학습 | 새 초기값에서 학습한 FP32·PTQ·QAT 공개 | 모델 크기, 선택 품질, 실패한 변형의 비교 자료 |
| Go 실행기와 컴파일러 연결 | 압축 모델로 생성·빌드·실행 관측 | 고정 작업 배열, 결정론적 이어가기, 원본과 연결된 결과 |
| 언어의 완전성 관측 | 선언된 의무와 이전·이후 관측 비교 구현 | 충족·실패·미확인 항목과 다음 작업의 근거 |
| 표현 변화에 견디는 작은 모델 | 입력 민감도 진단 완료, 개선 비교 예정 | 전체 입력을 유지한 한·영 유효 경로 일관성 |

앞으로의 차별점도 이 기록으로 판단하려 합니다. 같은 과제와 예산에서 필요한
시도가 줄었는지, 생성물이 의도를 얼마나 충족하는지, 설명 가능한 미해결 항목이
얼마나 남는지, 그 과정에 시간과 메모리가 얼마나 드는지를 함께 공개합니다.

## 다음 개발의 우선순위

- **한국어·영어와 Gooo 의미 연결:** 최신 진단을 바탕으로 문장 형식의 다양성과
  위치 표현을 비교합니다. 번역 쌍이 각각 유효한 경로를 선택하는지, 함께 틀리는
  경우는 얼마나 되는지 측정하며, 입력 원문을 유지합니다.
- **완전성 변화 비교:** 현재 `completeness-delta`가 제공하는 이전·이후
  관측 비교를 자연어 탐색과 더 넓은 실행 프로필까지 확장합니다.
- **더 풍부한 언어 표현:** 더 다양한 타입과 조합을 표현하고 생성·역관측
  규칙을 함께 늘립니다. 각 기능은 실행 가능한 예시와 연결합니다.
- **반복 사용 비용:** 모델을 한 번 로드한 요청 처리의 지연, 동시성,
  프로세스 RAM을 분리 측정합니다. 원본 실험 기록에는 저장 예산을 둡니다.
- **배운 조립법의 재사용:** 반복해서 성공한 구조를 설명 가능한 언어 구성으로
  축적하고, 새 과제에서 탐색 횟수와 미해결 항목이 어떻게 달라지는지 봅니다.
