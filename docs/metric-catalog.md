# Design-only metric catalog

Status: `DESIGN_ONLY`. This catalog names initial metric questions and their
deterministic contracts; it does not add an evaluator, verifier, workflow,
protection rule, merge rule, or blocking check. The common `DecisionMetric`
fields in [metrics-rfc.md](metrics-rfc.md) remain authoritative.

Every row uses the same closed failure-reason enum:
`PREDICATE_FALSE`, `REQUIRED_INPUT_MISSING`, `INPUT_AMBIGUOUS`,
`SNAPSHOT_MISMATCH`, `APPLICABILITY_UNPROVEN`, `CATALOG_MISMATCH`,
`EVALUATOR_ERROR`, `CATALOG_NOT_APPLICABLE`, `EXCEPTION_WINDOW_ACTIVE`,
`NOT_RUN`, and `NONE`. Missing or ambiguous authority input, resolution,
witness, or snapshot binding is `UNKNOWN`, never `PASS`. `NONE` is reserved for
`PASS`; `CATALOG_NOT_APPLICABLE` is a valid non-error only with catalog proof.
`NOT_APPLICABLE` is valid only when the immutable catalog row proves it for the
same snapshot. `UNOBSERVED` means that no exact-bound retained evidence exists
for this catalog row; it is not a claim that the row is impossible to observe.
No row below is `BLOCKING`.

Coverage denominators are immutable declared question, input, and obligation
sets; a zero denominator is never reported as 100%.

The `failure_domain` column is the predicate-false default only. The
`failure_domain_rule` column maps every actual closed failure reason and
snapshot condition to exactly one concrete evaluated domain; `NONE` and
`CATALOG_NOT_APPLICABLE` have no failure domain. Failure codes use the RFC
construction `<MetricID>#<failure_reason-kebab-case>`; each row therefore has a
stable, reason-specific code and never reuses a predicate-false code for a
missing or ambiguous input. `REPOSITORY_INTEGRITY` is reserved for policy or
protection tamper, unknown or overlapping ownership/scope, corrupted
evidence/catalog, unsafe topology/target authority, or cross-scope conflict.
Each applicability cell also names one closed `DecisionMetric.scope` value:
`feature`, `global`, `integration`, `promotion`, or `retirement`.

`gooo.metric.design.intent-cardinality.v1` is not reinterpreted: its
cardinality-and-budget predicate is superseded by
`gooo.metric.design.intent-cardinality.v2` plus the separate budget rows below.
The v1 definition remains historical in prior catalog digests.

Catalog completeness is a closed invariant: every family and priority claim in
the RFC resolves to at least one concrete `MetricID` below or to an explicit
cataloged gap; zero denominator is never complete.

The following named rules are exact catalog values used in the
`failure_domain_rule` column:

For every rule, `EXCEPTION_WINDOW_ACTIVE` and `NOT_RUN` use that rule's
unresolved-input branch; `NONE` and `CATALOG_NOT_APPLICABLE` bypass routing and
carry no failure domain. This makes the rule mapping total without turning a
valid catalog-proven `NOT_APPLICABLE` result into an error.

- `debt`: predicate false, snapshot mismatch, missing, ambiguous, or evaluator
  error -> `DEPENDENCY_LOCAL`; catalog or applicability mismatch ->
  `REPOSITORY_INTEGRITY`.
- `policy`: predicate false, snapshot, applicability, or catalog mismatch ->
  `REPOSITORY_INTEGRITY`; missing, ambiguous, or evaluator error ->
  `DEPENDENCY_LOCAL`.
- `catalog`: predicate false, snapshot, or catalog mismatch ->
  `REPOSITORY_INTEGRITY`; missing, ambiguous, applicability, or evaluator error
  -> `DEPENDENCY_LOCAL`.
- `protection`: predicate false or snapshot mismatch ->
  `REPOSITORY_INTEGRITY`; missing, ambiguous, applicability, or evaluator error
  -> `DEPENDENCY_LOCAL`; catalog mismatch -> `REPOSITORY_INTEGRITY`.
- `feature`: predicate false or snapshot mismatch -> `FEATURE_LANE`; missing,
  ambiguous, or evaluator error -> `DEPENDENCY_LOCAL`; applicability or catalog
  mismatch -> `REPOSITORY_INTEGRITY`.
- `scope`: known lane mismatch -> `FEATURE_LANE`; unknown or overlapping
  ownership/scope and cross-scope conflict -> `REPOSITORY_INTEGRITY`; other
  missing, ambiguous, or evaluator errors -> `DEPENDENCY_LOCAL`; applicability
  or catalog mismatch -> `REPOSITORY_INTEGRITY`.
- `ci`: one-PR/run predicate or snapshot mismatch -> `FEATURE_LANE`; shared
  evidence-producer dependency -> `DEPENDENCY_LOCAL`; a single PR/run missing
  or ambiguous input -> `FEATURE_LANE`; evaluator error follows the same
  producer/single-run split; only corrupted evidence/catalog or policy tamper
  -> `REPOSITORY_INTEGRITY`; applicability proof failure ->
  `DEPENDENCY_LOCAL` unless the catalog itself is corrupted.
- `integration`: target-tip predicate or snapshot mismatch ->
  `INTEGRATION_BARRIER`; shared producer failure -> `DEPENDENCY_LOCAL`; target
  authority or catalog corruption -> `REPOSITORY_INTEGRITY`; other missing,
  ambiguous, applicability, or evaluator failure -> `INTEGRATION_BARRIER`.
- `promotion`: any non-corruption result -> `PROMOTION_ONLY`; corrupted
  catalog, protection, or target authority -> `REPOSITORY_INTEGRITY`.
- `retirement`: any non-corruption result -> `RETIREMENT_ONLY`; corrupted
  catalog, ref evidence, or target authority -> `REPOSITORY_INTEGRITY`.
- `routing`: every malformed or missing routing field ->
  `REPOSITORY_INTEGRITY` because the evidence contract itself is corrupted.
- `resource`: predicate or snapshot mismatch -> `FEATURE_LANE`; missing,
  ambiguous, or evaluator error -> `DEPENDENCY_LOCAL`; applicability or catalog
  mismatch -> `REPOSITORY_INTEGRITY`.
- `docs`: a candidate docs PR with false normalized contract parity or a
  mismatched candidate snapshot -> `FEATURE_LANE`; a parity failure already
  present at the protected target -> `INTEGRATION_BARRIER`; only active
  normative-authority or policy corruption, including a corrupted catalog,
  -> `REPOSITORY_INTEGRITY`; missing, ambiguous, applicability, or evaluator
  failure -> `DEPENDENCY_LOCAL`. A proposed docs mismatch never globally stops
  the repository.
- `dependency`: predicate, snapshot, missing, ambiguous, or evaluator error ->
  `DEPENDENCY_LOCAL`; applicability or catalog mismatch ->
  `REPOSITORY_INTEGRITY`.

Observability is grounded in checked-in `origin/dev` views only: the RFC and
governance contract, the current semantic/compiler sources, and the checked-in
CI policy. `NOW` means an exact source-backed observation exists; `PARTIAL`
means at least one required input or witness is not yet exact; `MISSING` means
the observation has not been defined or retained. These labels do not claim
that an existing check implements the metric.
