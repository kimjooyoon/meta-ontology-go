# 사례를 읽고 경로를 고르는 작은 모델

Gooo에는 만들 수 있는 코드 경로와 기대하는 결과를 함께 적을 수 있습니다.
새 결정 모델은 비교식·분기·변수의 구조와 작성된 입출력 사례를 읽고, 먼저 시도할
경로를 고릅니다. 컴파일러는 그 경로의 본문을 구성한 뒤 모든 출력·조건 사례를 검사합니다.
첫 선택이 틀리면 남은 후보를 순서대로 확인합니다.

SDK [0.2.36 실험 배포](https://github.com/kimjooyoon/gooo-decision-runtime/releases/tag/v0.2.36-experimental)의
`model-contract-v1.json`을 개발 컴파일러에 연결했습니다. 모델은 9,746개 FP32 가중치,
38,984바이트의 가중치 배열을 사용합니다. 학습과 판단을 Go로 로컬 CPU에서 수행합니다.
공개 컴파일러 0.6.26부터 이 연결을 사용할 수 있습니다.

개발 소스에는 출력과 중간 조건을 함께 읽는 [SDK 0.2.39 상호작용 모델](interaction-contract-model.md)도
연결했습니다. 아래 표와 기존 관측은 앞선 모델들의 입력 형식과 결과를 기록합니다.

SDK0.2.40의 [같은 계산을 같은 입력으로 읽는 연구 모델](canonical-contract-model.md)도 개발 소스에서
사용할 수 있습니다. 기존 모델의 입력과 기본 선택은 유지합니다.

이번 개발 변경에서는 [SDK0.2.37](https://github.com/kimjooyoon/gooo-decision-runtime/releases/tag/v0.2.37-experimental)의
선택별 사례 모델과 전역 집계 모델도 같은 명령으로 읽습니다. 두 파일은 새 문서 388개 중
미리 정한 32개로 학습한 공개 가중치입니다. 기존 v1 형식도 계속 사용할 수 있습니다.

| 파일 | 사례를 읽는 방법 | FP32 가중치 |
| --- | --- | ---: |
| `model-contract-v1.json` (0.2.36) | 전체 사례의 공유 평균 | 38,984B |
| `model-global-v2.json` (0.2.37) | 전체 사례에서 절댓값이 가장 큰 신호 보존 | 38,984B |
| `model-choice-v1.json` (0.2.37) | 선택 지점의 소스를 먼저 반영한 뒤 사례 집계 | 51,272B |

가중치 크기는 프로그램 전체 메모리와 구분합니다. 모델의 형식·계산 방식·가중치 식별값은
입력 확인과 조립 결과에 함께 남습니다. 새 선택별 모델의 호출은 후보 검사 전 한 번이며,
다음 후보를 검사할 때 추가로 호출하지 않습니다.

## 실행하기

위 배포에서 모델 파일과 `MODEL-SHA256SUMS`를 받아 같은 폴더에 저장합니다.
개발 저장소 루트에서 다음 명령을 실행할 수 있습니다.

```sh
shasum -a 256 -c MODEL-SHA256SUMS

go run ./cmd/gooo body-context --activity Choose \
  --model model-contract-v1.json \
  examples/body-codegen/source-condition-cases.gooo.fixture

go run ./cmd/gooo body-codegen --json --activity Choose \
  --path-model model-contract-v1.json --path-step-attempts 1 \
  examples/body-codegen/source-condition-cases.gooo.fixture
```

첫 명령은 실제로 전달할 소스 배열과 사례 배열을 보여 줍니다. 모델 판단과 후보 실행은
0회입니다. 두 번째 명령은 모델을 한 번 호출한 뒤 후보 구성과 검사를 진행합니다.
결과의 `declared_contract_ranking`에는 제안, 호출 수, 입력·모델 해시가 들어갑니다.
`declared_contract_progress`는 각 단계와 최초 판단을 연결합니다.

새 모델을 사용할 때는 위 두 명령의 파일명을 `model-choice-v1.json`으로 바꿉니다.
같은 경로에 `model-global-v2.json`을 넣으면 전역 집계 모델을 선택합니다. 형식이 맞지
않거나 비어 있는 파일은 읽기 오류가 되므로, 모델 없이 실행할 때는 옵션을 생략합니다.

`--path-model`을 생략하면 고정 순서로 같은 사례를 검사합니다. `body-construct`에서도
`--model`로 이 파일을 사용할 수 있습니다. 저장된 구성은 이후 모델 파일 없이 실행합니다.
이 모델의 초기 순위는 고정됩니다. 시드 샘플링, 실패 후 재추론, 외부 오라클 관측을 함께
요청하면 현재 지원하는 조합을 설명하는 오류가 반환됩니다.

## 모델이 받는 정보

| 입력 | 구성 |
| --- | --- |
| 각 선택의 소스와 의도 | 관계 특징 384칸, 기존 v6 입력 |
| 각 작성 사례 | 입력·기대 출력의 특징 32칸, 전체 1~128개 |
| 사례의 요약 | 모델 파일의 평균 또는 절댓값 집계로 8칸 구성, 선택별 모델은 선택마다 요약 |
| 결과 | Gooo가 선언한 각 이진 선택의 두 점수 |

기대 출력은 작성자가 제시한 요구입니다. 실행 뒤의 관측 결과와 구분해서 기록합니다.
모델은 출력 사례를 읽고, 컴파일러의 승인 검사는 모든 출력 사례와 `condition_case`를
확인합니다. 전체 정수를 부동소수로 바꾸는 과정은 없습니다. `9007199254740993`처럼
큰 정수의 1 차이도 입력 식별과 결과 비교에서 유지합니다.

한 번 읽은 가중치는 여러 구성 요청이 공유하고, 각 요청은 자기 작업 공간과 진행 기록을
갖습니다. 사례 집계는 정보를 압축하므로 드문 사례가 순위에 충분히 반영되지 않을 수
있습니다. 최종 사례 검사는 평균이나 모델 점수로 대체하지 않습니다.

## 관측된 성과

새 선택별 모델의 [388개 문서 실험](https://github.com/kimjooyoon/gooo-decision-runtime/tree/3f032abfc41cf0b2082949fede4abb8f9919a1b6/studies/choice-context-learning-20261010)에서
첫 선택의 전체 사례 통과는 고정 순서 193개, 전역 집계 197개, 선택별 집계 221개였습니다.
학습에 사용하지 않은 356개에서는 각각 177개, 180개, 202개였습니다. 전역 집계와 비교하면
87개가 개선되고 63개가 퇴보했으며, 학습하지 않은 곱셈 형태는 32/64에서 31/64로 낮아졌습니다.
세 방식 모두 해결 가능한 386개를 유한 탐색으로 완료하고, 모순된 요구 두 개는 완료하지 못했습니다.

선택별 모델의 판단 중앙값은 37.584µs, 전역 집계는 16.791µs였습니다. 선택 지점마다
사례를 다르게 읽는 방식은 이번 묶음에서 첫 선택을 개선했지만, 판단 계산은 더 길었습니다.
이 수치는 SDK 관측이며 실제 컴파일러 명령 전체의 시간과 구분합니다.

공개 가중치를 연결한 [CLI 15개 명령의 관측](research/choice-contract-cli-20261010/README.md)에서는
세 예제의 후보 시도가 5→4회였고, 첫 선택 성공은 양쪽 모두 2/3이었습니다. 네이티브 구성과
모델 없는 저장 재실행은 각각 24/24개 사례를 통과했습니다. 모델을 사용하는 구성 전체는
4.26~5.20ms였으며 파일 읽기 비용을 포함해 고정 순서보다 길었습니다.

### 앞선 공유 평균 모델

[SDK의 고정 실험](https://github.com/kimjooyoon/gooo-decision-runtime/tree/88ef3de7895c832b91ece179e3623a57fd5997db/studies/contract-goals-20261010)은
196개 Gooo 원문과 모든 성공·실패를 공개합니다. 학습에서 제외한 해결 가능한 170개 중
첫 선택의 전체 사례 통과는 고정 순서 85개, 모델 107개였습니다. 전체 196개에서는
49개가 개선되고 21개가 퇴보했습니다. 두 방식 모두 해결 가능한 194개를 유한 탐색으로
완료했고, 모순된 요구 2개는 미완료로 남겼습니다.

후보 시도는 396회에서 271회로 줄었지만 합산 탐색 시간은 18.278ms에서 27.837ms로
늘었습니다. 판단 중앙값은 16.375µs, 한 번의 CPU 학습은 356.692ms였습니다.
이는 작고 서로 관련된 SDK 사례의 측정입니다. 일반 컴파일러의 파일 읽기·분석·네이티브
실행 비용과 새로운 한글·영어 요청에 대한 판단은 별도로 확인해야 합니다.

97쌍의 반대 요구 중 61쌍에서는 모델이 같은 첫 경로를 골랐습니다. 요구가 달라져도
선택을 바꾸지 못하는 사례와 드문 마지막 사례는 계속 확인할 과제입니다.

이후 공개 가중치로 [실제 CLI 20개 명령](research/contract-model-cli-20261010/README.md)을
실행했습니다. 알려진 네 예제에서 시도는 8→5회, 첫 선택 성공은 2/4→3/4였고,
네이티브 구성과 모델 없는 저장 재실행은 각각 32/32개 사례를 통과했습니다.
모델 구성 시간은 3.53~4.18ms로 고정 순서의 0.83~1.74ms보다 길었습니다.
