# 선택된 Gooo 소스의 사용 위치까지 연결하기

지역 변수의 대입뿐 아니라 각 사용 표현의 위치를 기록했다. 예를 들어
`let copy=원본; 원본=원본+211; return copy+원본`에서 `원본`을 읽는 세 곳은
같은 선언을 공유하지만 각각 다른 사용 위치를 가진다.

사용 위치는 생성 전 구문 노드에서 보존하고, 코드 변환 뒤의 변수별 사용 순서에
연결한다. 선언·대입·사용은 선택된 Gooo 소스의 해시를 가진다. 생성된 Go의 위치와
해시는 별도로 유지한다. 생성 과정에서 추가된 미사용 변수 표시에는 Gooo 사용
기원을 붙이지 않는다.

10841은 저장된 기록에서 입력을 선택했으며, 원래 생산 프로그램을 실행한 횟수는
0이다. 위 과정의 모델 호출은 모두 0이다. 숫자는 각 프로그램의 유한 입력 범위에
한정한다. [실행 목록](runs.json), [추출한 요약](summary.json), 소스 오버레이의
해시 목록과 압축 파일을 함께 보관한다. 기준 개발 트리는
`246772c25a6b78a6b58d8f81689df8c275729816`이며 해당 트리에 대한 변경 파일을 담았다.

10709에서는 결과 저장 환경 변수명을 잘못 설정해 상세 실행 JSON을 남기지 못했다.
소스 스냅샷·종료 상태·실제 검사의 로그는 남아 있다. 이를 다시 실행하지 않았고,
후속 결과는 별도의 새 프로그램·입력으로 얻었다. 10773 이후 기록은 원래 JSON에서
runtime을 선택하거나 요약을 추출한 것이다. 추출은 생산 프로그램을 재실행하지 않는다.

## 통합 검사에서 발견한 문제

[PR #1547](https://github.com/kimjooyoon/meta-ontology-go/pull/1547)의 원래 통합 실행에서
저장 기록을 읽는 오류가 드러났다. `BodyLocalOrigin`이 포함한 익명 구조체의 필드는
JSON에 출력됐지만, 명시된 필드 이름을 읽는 기존 해석 경로에는 등록되지 않았다.
`decoded_start`, `decoded_end`, `expression`을 명시적인 JSON 필드로 정의해 출력과
읽기의 계약을 맞췄다. 10773의 실제 CLI 저장·새 입력 실행으로 이 경로를 확인했다.

또한 지역 변수의 연결을 한 함수에서 처리하던 코드는 구조 변환기의 도우미 크기
한도에 들어오지 않았다. 대입 연결·함수 지역 범위·사용 위치·기록 순서 검사를
각각 작은 함수로 나누고 실제 렌더러에서 확인했다. [최초 로그의 출처와 발췌](predecessor-failures.json)를 남긴다.
자기 관찰 검사에서 출력이 파일로 전환돼 보이지 않았던 실패도 원래 CI 아티팩트의
`test.json`에서 확인했다. 실패한 개별 테스트 52개 모두 같은 JSON 필드 계약 오류였다.
[원본 아티팩트 식별과 해시](original-artifact-selection.json),
[진단 요약](original-final-failure-diagnosis.json)을 보관한다. 원본 압축 파일은 확인 후
삭제했다. 전체 통합 성공은 후속 제출의 CI에서 판단한다.

## Gooo가 사용하는 입력

[읽기 프로그램](../../../examples/native-origin-reader/locals/locals.gooo)의 입력은
22개 필드다. `source_sha256`, `source_start`, `source_end`, `source_mapping`으로
사용 표현의 Gooo 위치를 받는다. `declaration_*`는 선언, `projection_*`는 생성된 Go의
위치를 가리킨다. 기존 문법 등록 사례를 유지하면서 입력 선언과 Gooo 분류 본문을 확장했다.

[새 예제 기록](../../../examples/native-origin-reader/local10773-runtime.json)은
10773의 첫 CLI 출력에서 runtime을 선택했다. [추출 출처](record-origin.json)에
원래 출력의 해시와 배포한 파일의 해시를 적었다. 예전 기록에는 없던 좌표를 추측해
채우지 않으며, 읽기 프로그램이 그 차이를 `declaration-only`로 표현한다.

위치는 선택된 Gooo 소스 문서 기준이다. 여러 패키지의 물리적인 원본 파일 좌표,
`source_fill` 이전부터의 기원 사슬, 레코드·컬렉션 지역 값의 연결은 후속 범위다.

## 생략된 사용 좌표를 다루는 계약

선택적인 `uses`가 없던 저장 기록은 대입·선언 기원만 비교한다. `uses`가 기록돼
있다면 그 좌표와 순서까지 일치해야 한다. 비교는 입력 기록과 현재 계산 결과를
수정하지 않는다. 새 좌표를 계산할 수 있다는 사실이 과거에 그 좌표를 기록했다는
뜻으로 바뀌지 않도록 했다.

11017 최초 실행은 실험 소스에 후보를 하나만 선언해 기존의 2개 이상 후보 규칙에서
중단됐다. 해당 테스트 소스에는 두 번째 후보를 추가했으며 로컬 재실행은 하지 않았다.
11053은 별도의 분기 구조와 다른 입력을 사용해 위 계약을 확인했다. 두 실행의
원래 소스와 결과를 함께 남긴다. 이 관찰에는 모델 호출과 네이티브 실행이 없다.
