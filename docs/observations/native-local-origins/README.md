# 지역 변수의 기원을 읽은 관찰

2026-10-14 개발 소스에서, 선언한 지역 변수의 대입과 실제 사용을 연결했다.
대입 순서와 함수 호출 회차를 기록해 같은 숫자나 같은 변수 이름을 구분한다.
Gooo 읽기 프로그램은 이 기록을 입력받아 연결 상태를 설명한다.

## 작은 프로그램에서 시작하기

예제 기록의 `Prepare` 본문은 다음과 같다.

```gooo
let first = input + 173
let second = first * 3
if input < 0 { first = second + 5 } else { first = second - 5 }
return Batch{values: []int64{second, first}}
```

`23`을 넣으면 `[588,583]`, `-181`을 넣으면 `[-24,-19]`가 된다.
`second`를 읽은 곳은 두 번째 선언의 대입으로, 마지막 `first`는 선택된 분기의
재할당으로 연결된다. 원래 선언 위치와 생성된 Go의 실제 사용 위치도 구분해 남긴다.

[저장된 실행 기록](../../../examples/native-origin-reader/local10433-runtime.json)과
[Gooo 읽기 프로그램](../../../examples/native-origin-reader/locals/locals.gooo)을
[예제 안내](../../../examples/native-origin-reader/README.md)의 명령으로 사용할 수 있다.
[추출 기록](../../../examples/native-origin-reader/local-record-origin.json)은 원래 JSON의
해시와 선택한 `producer_runtime` 필드, 배포한 예제 파일의 해시를 묶는다.
추출과 페이지 선택은 원래 프로그램을 실행하지 않는다.

## 새 입력에서 관찰한 범위

| 소스 묶음 | 실제 관찰 |
| --- | --- |
| 10301 | 재할당·반복·헬퍼 호출 4/4, 컬렉션 없는 프로그램 2/2 결과 일치 |
| 10337 | 조건·오류 3/4 일치와 의도한 0 나누기 1건; 대입 한도 사례 2/2 일치 |
| 10433 | 생산 프로그램 2/2, 기록을 읽는 Gooo 프로그램 3/3, 32필드 프로그램 2/2 일치 |
| 10543 | Gooo 사용 기록 한도 14/14 일치; 보관 65,536회·누락 6,172회 |
| 10567 (10543 소스 묶음) | 관찰기 Go 백엔드에서 65,537회 계산 유지; 함수 회차 65,536회 보관·1회 누락 |
| 10589 (10543 소스 묶음) | 시간 순서·선언·함수 회차·평가 범위 모순 18종 거부; 네이티브 실행 0회 |

함수 회차 한도는 관찰기 백엔드를 직접 호출한 결과다. Gooo의 별도 호출 예산을
통과한 65,537회 호출로 해석할 수는 없다. 사용·대입 한도에 닿은 Gooo 결과는
계산을 유지하고 `PARTIAL`과 누락 수를 남긴다. 마지막 페이지에도 그 수가 유지된다.

CLI의 별도 두 행은 실제 결과와 기대한 분류가 일치했다. CLI 자체에는 정답을
넣지 않았으므로 상태는 `OBSERVED`, 기대값 분모는 0이다. 단일 CLI 실행의
경과 시간은 약 1.19초, 자식 프로세스 CPU 시간 합계는 약 0.288초였다.
관찰된 최대 자식 RSS는 약 84.2MiB다. 빌드와 두 네이티브 실행이 포함된 값이며,
PC 전체 CPU 사용률이나 반복 성능 비교를 측정한 값은 아니다. 모델 호출은 0회다.

## 실패와 소스의 변화

- 10267은 `_windows.go` 파일명이 플랫폼 조건으로 처리되어 테스트 시작 전에
  빌드가 실패했다. 파일명을 고친 10301에서 해당 새 프로그램들이 처음 실행됐다.
- 10399는 생산 프로그램 2/2가 통과한 뒤, 18필드 읽기 프로그램이 기존 16필드
  한도에서 거절됐다. 필드 한도를 32개로 맞추고 10433의 다른 프로그램·입력으로
  확인했다. 33필드 거절도 포함했다.
- 10433 뒤에는 테스트의 두 반복문을 Go 현대화 규칙에 맞췄다. 이전 사례의 로컬
  재실행 없이 다음 소스 묶음에 변경을 보존했다. 최종 CI가 통합 소스를 실행한다.

[실행 목록](runs.json)은 각 로그와 소스 오버레이의 해시, 종료 상태를 기록한다.
`producer*.tar.gz`는 해당 시점에 덮어쓴 파일의 원본 바이트이며, 기준 저장소 트리는
`e5be04e3ac3ebbbeab87e9e58ad5c32be0136bf8`다. 이 트리는 PR #1546으로 승인된
`6ac5736d89fd19fd823dc80c324e0ecdd523e630`과 같다.
10267 로그의 로컬 경로는 공개본에서 치환했고 원본 로그 해시를 따로 남겼다.
[관찰 목록](observations.json)은 압축 JSON을 풀었을 때의 해시와 원래 Gooo 소스의
해시를 제공한다. [요약](summary.json)은 이 저장 기록에서 추출한 수치다.

## Gooo 소스 등록

`RegisterSyntaxCapability`가 `locals.gooo`를 등록하며 분모 버전 53에서 54를
생성했다. 9개 역할과 9개 파일을 함께 생성했고, 생성한 파일의 바이트를 그대로
통합했다. [요청](registration-request.json), [생성 결과](registration-candidate.json),
[실행 정보](registration-execution.json)를 보관한다. 한 번의 생성 시간은 96ms다.
이 등록에서 네이티브 프로그램 실행과 모델 호출은 0회다.

등록 도구 준비 중 버전 없는 분모 파일명을 잘못 해석한 로컬 스크립트 오류가 있었다.
이를 고친 뒤 생성은 한 번 수행됐다. 완료 후 표시 스크립트가 빈 표준 출력을 JSON으로
읽으려다 실패했지만, 저장된 생성 결과와 9개 파일은 완료된 상태였고 다시 실행하지 않았다.
이 관찰 당시 등록 분모는 89개(유효 86개·무효 3개), 언어 기능 87개·거버넌스 관찰 2개였다.
이 숫자는 등록 범위이며, 제출 소스의 통과 여부는 해당 CI 결과에서 확인한다.

## 남은 연결

현재 원래 Gooo 위치를 제공하는 것은 선언과 대입의 오른쪽 표현이다. 사용 표현
자체의 Gooo 위치, `source_fill` 이전부터의 기원 사슬, 레코드·컬렉션 지역 변수의
값 단위 연결은 후속 작업이다. 평가 구간은 호출된 헬퍼의 사용도 포함한다.
따라서 결과에 반드시 필요한 최소 의존성이나 프로그램 전체 완전성을 뜻하지 않는다.


후속 변경은 [Gooo 사용 표현의 원래 위치](../local-use-source/README.md)를 연결한다.
위 기록은 당시 소스의 관찰이며, 예전 기록에 새 위치가 소급 추가되지는 않는다.
