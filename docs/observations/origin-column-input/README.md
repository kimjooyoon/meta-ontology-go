# 저장된 조립 기원을 Gooo 집계 입력으로 직접 연결

기준 개발 소스는 `66fb86cc037a2d318108af56207af515e16b25cd`다.
각 새 묶음의 변경 소스와 Gooo 계산 소스는 스냅샷에 보관한다.
완료된 과거 로컬 묶음을 다시 실행하지 않았다.

새 CLI 옵션 `--origin-shape local-fill-columns`는 선택한 조각을 여섯 개의 같은 길이
배열로 옮긴다. 최대 128행의 배열 공간을 먼저 할당한다. Go 전송부는 정렬·중복 제거나
비율 계산을 하지 않는다. `examples/derived-origin/coverage.gooo`의 조건문과 반복문이
사례·대입 번호를 묶어 계산한다. 선택한 입력 JSON의 기존 32KiB 한도도 유지한다.

전체·중간·마지막·빈 표마다 Gooo 소비 입력은 하나다. 원래 조각의 수는
`origin_input.returned_rows`, 소비 입력 수는 `consumer_rows`에 따로 남긴다.
읽는 동안 원래 생산 프로그램과 모델을 호출한 횟수는 0이다.

직접 작성한 대입에는 Gooo 소스 위치가 있다. 조립하지 않은 대입의 조립 기원 연결
비율이 0%인 것은 이 별도 관계의 범위를 나타낸다. 이 비율로 일반 소스 위치의 존재나
실행 결과의 정답률을 판정하지 않는다. 기대값 없이 실행한 다섯 소비 결과는 `OBSERVED`와
finite 분모 0을 유지하며, 테스트가 출력 다섯 개를 대조했다.

[outputs.json](outputs.json)에 원래 CLI 파일의 해시, 추출한 런타임의 해시, 실제 출력과
기원 입력 요약을 보관한다. 공개한 런타임은 원래 JSON의 `$.result.runtime` 값을
UTF-8 JSON으로 다시 저장한 것이다. 원래 CLI 파일 전체의 해시와는 구분한다.
[실행 묶음](runs.json), 각 변경 소스 manifest·압축 스냅샷과 원래 로그도 함께 보관한다.
[전체 소스 목록](source-inventory.json)은 기존 Gooo 계산 소스 두 파일까지 포함한
실제 스냅샷의 파일 해시를 적는다.
스냅샷은 실제 실행 시점의 소스다. 이후 정적 스타일 수정이 있으면 최종 제출과
바이트가 다를 수 있으며, 이전 결과를 새 소스 실행으로 바꾸어 기록하지 않는다.
