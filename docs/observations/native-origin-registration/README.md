# Native origin reader registration

The four origin-reader programs are registered through the Gooo-owned
`RegisterSyntaxCapability` operation in
[`contract.gooo`](../../../internal/meta/syntaxregistration/contract.gooo).
Each request binds its source, the current registration inputs and the exact
generator, Go driver and compiler bytes. The generated members update the
syntax corpus, native registry, counts, conformance expectations and versioned
denominator together.

## Why this update exists

[PR 1545](https://github.com/kimjooyoon/meta-ontology-go/pull/1545) added the four
consumer programs but omitted their syntax registrations. Its original
[unit-test job](https://github.com/kimjooyoon/meta-ontology-go/actions/runs/38477857680/job/115572903035)
reported those four files as unregistered. The original
[syntax partition job](https://github.com/kimjooyoon/meta-ontology-go/actions/runs/38477857573/job/115572902165)
also failed. [Selected original log lines](predecessor-failures.json) retain
the exact submitted head and hashes of the downloaded original logs.

The successor retains the complete CLI adapter and consumer implementation.
The new registration includes all four programs in the syntax and
bidirectional transformation checks.

## Generated registration

| Consumer | Denominator transition | Generated roles | Generated members | Observed generation time |
| --- | --- | ---: | ---: | ---: |
| constructions | 49 → 50 | 9 | 9 | 100 ms |
| elements | 50 → 51 | 9 | 9 | 98 ms |
| links | 51 → 52 | 9 | 9 | 96 ms |
| reads | 52 → 53 | 9 | 9 | 99 ms |

These are single local generation observations. Each generation includes
source syntax and transformation checks. Original native producer executions,
native consumer executions and model calls during this registration were zero.
The previous consumer outputs remain in
[native-origin-inputs](../native-origin-inputs/README.md).

The final registry declares 88 cases: 85 valid and three invalid. Of these,
86 are language capability cases and two are governance observations. These
counts describe the registered population. CI determines whether the submitted
population passes.

The four `*-request.json`, `*-candidate.json` and `*-execution.json` files record
each typed request, all generated bytes and role bindings, and the execution
identity. The final 12 changed member paths are the union of four sequential
registrations. Each before-digest matches the preceding state; the original
denominator records remain unchanged.

## Profile and setup observations

These programs have integer, Boolean and string fields. They use the registry's
`ordered_collections` selector for `EntityFieldsV5Support`, which also supports
these scalar fields. The programs retain their original scalar input shapes.

Two initial preflight attempts detected an older Go driver on `PATH`; selecting
the installed Go 1.27.2 driver resolved that mismatch. A V1 registration request
was rejected because V1 supports string fields only. The V5 requests generated
the four candidates. [Setup observations](setup-observations.json) retain those
failures alongside the successful generation results.
