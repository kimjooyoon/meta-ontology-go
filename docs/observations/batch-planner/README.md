# 작업 예산 계획의 소스 조립과 실행

[Gooo 예제](../../../examples/batch-planner/README.md)는 목록 순회 중 계산을 멈추고
부분 결과와 이유를 반환한다. 소스의 두 비교식 후보에서 경계값을 포함하는 조건이
선택됐다. 모델 호출은 0회다.

| 단계 | 관찰 |
| --- | --- |
| 소스 후보 선택 | 3/3 결과 일치, `inclusive` 선택 |
| 별도 보류 사례 | 1/1 일치 |
| 추가 네이티브 입력 | 4/4 일치, 선택·보류 입력과 중복 0 |
| 원본 조건식 | 3개 위치 연결, 조건 관찰 20개, 누락 0 |

[원본 기록](batch8297.json)에 소스, 후보 결과, 생성한 코드, 런타임 입력과 출력,
조건식 위치가 함께 있다. [실행 로그](observation8297.log)와
[생산 소스 목록](producer8297.json), [소스 묶음](producer.tar.gz)을 보관했다.
기준 커밋은 `547ad4cdd34001186509659ea208fc48b0567106`이며,
단일 값·목록 통합 수정 및 출처 분석 메서드 분리가 적용된 소스에서 관찰했다.

한 번 측정한 구성 실행 시간은 약 714ms, 그중 빌드 프로세스는 약 310ms였다.
빌드 프로세스의 최대 RSS는 약 83.5MiB다. 캐시와 실행 환경의 영향을 포함하는 단일
관찰이며, 반복 벤치마크나 실행 프로그램의 상시 메모리 측정으로 해석하지 않는다.

이 관찰은 조립과 실행 라이브러리의 공개 경로를 사용했다. 안내의 CLI 명령을 별도로
반복 실행하지 않았다. 전체 변경안은 후속 공개 커밋의 원래 CI에서 확인한다.
