## Gooo가 맡는 부분

`lineage.gooo`에서 방문 집합과 역순 순회를 직접 구현합니다. Go 전송기는
한 케이스의 기록을 그대로 열로 전달하고, Gooo가 부모와 필드 읽기를 따라가
입력 기원·해결되지 않은 연결·공유 구간 수를 계산합니다.

중첩 컬렉션 순회의 길이 곱 상한은 65,536이고 일반 고정 활동 호출 상한은
4,096회입니다. 반환식의 호출은 활동에서 한 번만 실행되는 것으로 계산합니다.
소비자 프로필은 케이스당 쓰기 60개·읽기 128개, 전송 JSON 32KiB입니다.
전체 필드 기록의 보관 상한과 소비자의 현재 탐색 상한을 구분합니다.

스칼라 지역 변수·분기 제어를 거친 전체 의존성, 복잡한 레코드 전달,
큰 기록의 페이지 탐색은 남은 범위입니다. `SCOPED_FIELD_ORIGINS`는 현재
기록 프로필 안의 연결을 설명합니다. 입력 기록의 생산자 인증도 별도 문제입니다.

## 원본 CI 실패와 변경

[PR 1554](https://github.com/kimjooyoon/meta-ontology-go/pull/1554)의 원본
projection·semantic 작업은 같은 렌더링 메서드를 자동 추출하다 실패했습니다.
정규화된 함수는 70줄이지만 생성하려던 헬퍼는 76줄로 기존 75줄 상한을
넘었습니다. 원래 제출 머리와 워크플로는 유지하고, 후속 소스에서 렌더러를
분기·스코프·레코드 쓰기·스칼라 쓰기·헬퍼 호출로 나눴습니다.
14321은 다른 새 Gooo 소스와 입력으로 이 경로의 실행과 기원 연결을 확인합니다.

원본 로그와 아티팩트의 식별자·해시·진단은
[original-ci-diagnosis.json](original-ci-diagnosis.json)에 있습니다.
원본 CI를 다시 실행하지 않았습니다. 공개 후속 PR의 CI 결과는 해당 PR의
자기 제출 버전에서 별도로 확인해야 합니다.
