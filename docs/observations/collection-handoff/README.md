# 목록 전달과 문법 검사 연결

## 표현할 수 있게 된 작업

[batch-handoff](../../../examples/batch-handoff/README.md)는 반복문에서 계산한
위치로 목록을 자르고, 그 결과 레코드를 bind로 다음 활동에 넘긴다. 다음 활동은
전달받은 목록을 읽어 개수와 합계를 만든다. 선택·부분 결과·재사용을 한 Gooo
프로그램으로 작성한 예다.

## 최초 관찰 8411

[고정된 생산 소스](producer8411.json), [소스 파일 묶음](producer.tar.gz),
[원본 로그](observation8411.log), [종료 상태](ended8411.json)를 함께 보관한다.

- 새 실행 입력 7개, 활동별 기대 출력 14개를 확인하는 어설션까지 통과했다.
  빈 목록, 입력 순서 변경, 음수 값, 예산 0에서 값 0, int64 상한을 포함한다.
- 그 뒤 테스트가 조립 기록을 `Composition.Steps`에서 찾아 실패했다. 워크스페이스는
  본문 조립을 먼저 마치고 `BodyFills`에 기록한 뒤 실행용 composition을 만든다.
- [수정 기록](test-correction.json)은 읽는 위치를 `BodyFills`로 바꾼 파일 해시를
  남긴다. 수정 후 동일한 로컬 입력 묶음을 재실행하지 않았다. 후보 선택 수치와
  bind를 통한 원본 출처 어설션은 후속 PR의 원본 CI에서 확인한다.
- 최초 테스트 전체 결과는 실패다. 14개 출력의 일치와 전체 테스트 통과를 구분한다.
  이 관찰에서 모델 호출은 0회이며 모델 품질이나 일반적인 성능을 측정하지 않았다.

## 새 문법 관찰 8429

[결과](syntax8429.json)는 정수·문자열·불리언 목록과 required·optional을 조합한
서로 다른 소스 6개다. 두 활동 사이의 명시적 bind도 포함한다. 6개 모두 V5에서
AST, 표준 서식, 의미 왕복, GetPut, PutGet을 보존했다. 기존 V1 계약에서는 6개
모두 수용되지 않았다. 네이티브 실행과 모델 호출은 없다.

## 앞선 CI에서 발견한 누락

[PR 1539 원본 검사](parent-diagnosis.json)는 등록된 82개 사례와 세 구조 투영을
통과했으나 `examples/batch-planner/main.gooo`가 검사 목록에 없어 실패했다.
후속 변경은 batch-planner와 batch-handoff를 명시적 V5 경로에 등록한다.
등록 분모는 전체 84개, 언어 기능 82개, 운영 관찰 2개다. 기존에 저장한 82개
기준의 관찰 기록은 그대로 남긴다.

이는 예제 두 개의 등록과 목록 전달을 확인하는 범위다. 독립 사용자 채택,
전체 언어 완성도, 항목별 기원 정확도는 별도 과제로 남아 있다.
