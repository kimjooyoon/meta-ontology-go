## 먼저 드러난 문제

- 18311은 새 업무 실행 2/2 뒤 검사의 해석기 이름 가정이 틀려 실패했습니다.
  스칼라 경로의 실제 이름은 `gooo/bodycodegen-int64-ast-interpreter/v2`입니다.
- 18503은 후보 선택과 별도 실행 뒤 조립된 몸체의 원본 위치 연결에서
  실패했습니다. 원본·선택 조각이 같은 길이라는 가정을 토큰 좌표 매핑으로
  바꾸고, 새 소스·입력 18717로 확인했습니다.
- 19121·19203은 `Integer`와 Go `len`의 `int` 비교에서 소비자 생성이
  중단됐습니다. 새 소스는 기존 명시적 `int64(len(...))` 방식을 사용합니다.
  생산 업무 프로그램은 이 조회 과정에서 실행하지 않았습니다.

각 실패의 입력·로그·다음 새 코호트를 보관합니다. 같은 완료 코호트를 다시
실행해 결과를 덮어쓰지 않았습니다.

## PR 1557의 원래 CI

저장소 투영과 의미 검사에서 같은 `compareSourceFillReplay`가 생성될 도우미
77줄로 관측됐습니다. 소스 함수는 70줄이지만 기존 상한은 생성 도우미에도
75줄입니다. 이어진 추출이 `json.Unmarshal` 출력 효과를 확인하지 못했습니다.

완전성 기록 비교를 별도 함수로 옮겼습니다. 모든 원본·생성물·기원·완전성
비교를 유지하고 새 두 함수의 생성 크기를 55줄·30줄로 관측했습니다.
검사 상한·정책·워크플로는 바꾸지 않았습니다. 후속 PR의 원래 CI가 전체
변경을 새로 검사해야 합니다.

## 등록과 파일

등록 19401은 이 Gooo 집계기의 67→68 추가입니다. 실제 등록기가 아홉 역할과
아홉 구성원을 생성했고 바이트를 그대로 적용했습니다. 입력과 출력은 압축
자료로 보관하며, 등록에 업무 생산 실행이나 모델 호출은 필요하지 않았습니다.

현재 카운터는 0부터 리터럴 상한 1..1024까지 한 칸씩 증가합니다. 중첩·동적
상한·감소·반복문 밖 `++`와 `len` 정수 표현 통일은 후속 언어 범위입니다.

## 전체 동시성 작업 시간

PR 1557의 원래 `go test -race` 작업은 20분 제한에서 취소됐습니다.
완료 로그에는 CLI 600.930초, 본문 실행 569.524초, 별도 CLI 관찰 106.750초,
저장소 추출기 489.099초가 남았습니다. 일부 패키지 통과를 전체 작업 통과로
계산하지 않습니다. 이 로그는 진단용이며 후속 승인 자료를 대신하지 않습니다.

추가로 필드 기원·경계·용량·렌더러의 명령 관찰 네 파일을 별도 CLI 관찰
패키지로 옮겼습니다. 패키지 이름 외 검사 내용은 그대로이며 실제 실행 파일을
사용합니다. 완료한 과거 코호트의 로컬 재실행은 0입니다. 검사 수나 작업 시간
제한을 줄이거나 늘리지 않았고, 후속 원래 CI의 결과는 아직 필요합니다.
