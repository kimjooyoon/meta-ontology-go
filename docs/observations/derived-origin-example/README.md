# 문법 조립과 Gooo 출처 완전성 계산

기준 개발 소스는 `c5ec87a7221918e62ffd2bc2c2359b550c2ba21d`다.
새 소스와 새 입력으로 수행했으며, 완료된 과거 묶음을 로컬에서 다시 실행하지 않았다.

| 새 묶음 | 결과 |
| --- | --- |
| 11903 | 실제 패키지 CLI 생산 3/3. 문법·템플릿 조각 6개를 Gooo가 읽은 출력 6/6 대조. 읽기 실행 자체는 기대값 없는 OBSERVED, 분모 0 |
| 11903 문법 범위 | `integer-offset-constant/v1`의 후보 6개 중 6개 검토. 선택 사례 2개와 별도 실행 입력 3개를 구분 |
| 11983 | Gooo로 작성한 연결 비율 계산 8/8. 저장 기록의 전체·앞부분 페이지 2개와 명시한 합성 조건 6개 |
| 등록 11941 | 예제 소스 v55→v56, 9개 역할·9개 생성 파일 |
| 등록 12017 | Gooo 계산 소스 v56→v57, 9개 역할·9개 생성 파일 |
| 12063 | 별도의 작은 선택 함수가 이미 75줄 이내일 때 그대로 검사하는 경로 확인. 프로그램 실행 0 |

11903은 포맷 전후 조립 명세의 정규형도 비교했다. 문법 이름, 보정 의도와 사례가
유지됐다. 파생 식의 출처는 실제 문법 선언의 바이트 범위를 가리키며, 원문에 없는
후보 표현의 위치를 만들어 붙이지 않았다. 이 과정의 모델 호출은 0이다.

11983의 입력은 저장된 결과에서 조각을 열로 뽑은 자료다. 원래 생산 프로그램을
실행하지 않았다. 합성 조건은 기록 불완전 표시, 열 길이 차이, 동일 대입의 조각
반복, 행 순서 모순, 한 출처의 누락, 빈 기록이다. [입력의 출처](coverage-input-origin.json)에
실제 자료와 합성 조건을 각각 표시한다.

연결 비율의 분모는 기록된 대입 수다. 분자에는 위치 정보가 있는 조각을 가진 대입을
중복 없이 센다. 부분 페이지나 불완전한 기록에서는 전체 비율을 `-1`로 남긴다.
빈 기록에서도 비율을 확정하지 않는다. 이 값은 제공된 출처 기록의 충실도를
계산하며, 실행을 다시 입증하거나 언어 전체의 완전성을 주장하지 않는다.

두 등록의 생성 결과는 수정 없이 보관했다. 생성기의 작은 선택 함수 구조로 다음
분모를 추가하는 실제 경로도 사용했다. 전체 통합 여부는 후속 제출의 원래 CI에서
확인한다.

PR #1549의 원래 저장소 구조 검사에서는 이미 분할된 `evidence_split04.go`에 다시
분할을 요구하던 검사 가정이 실패했다. 작은 단위는 그대로 파싱하고 큰 단위만
분할 계획을 확인하도록 검사 코드를 수정했다. 완료된 11447 묶음을 다시 실행하지
않고 새 작은 소스 12063을 사용했다. [원래 실패 기록](predecessor1549-failure.json)을
보관한다. 코어 semantic 단계의 실패는 출력이 전환된 명령 안에서 발생해, 그 콘솔
로그만으로 정확한 하위 원인을 확정하지 않았다.
