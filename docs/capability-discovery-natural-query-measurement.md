# Natural Capability Discovery Measurement Contract\n\nThis contract measures whether a declaration-bound capability discovery flow helps a\ndeveloper choose a next operation. It does not claim that the domain is complete,\nthat a generated result is correct, or that a capability is safe to execute.\n\n## Observation unit\n\nOne observation is keyed by:\n\n- source declaration digest\n- natural-language query digest\n- capability catalog digest\n- evidence boundary digest\n- toolchain identity\n\nThe observation must preserve the first missing stage when the result is UNKNOWN.\n\n## Outcome states\n\n- AVAILABLE: the declaration and evidence boundary identify a capability that can be described.\n- DEFERRED: the declaration is understood, but the next operation requires evidence not present in the slice.\n- UNKNOWN: the earliest required stage cannot be established from the current evidence.\n\nThese states are observational. None grants execution or authorization.\n\n## Primary metrics\n\n- declaration binding rate: observations with an explicit declaration binding divided by all observations\n- evidence-boundary rate: observations with a non-empty, replayable evidence boundary divided by all non-UNKNOWN observations\n- first-missing-stage localization rate: UNKNOWN observations that name the earliest missing stage divided by all UNKNOWN observations\n- replay continuity rate: replay records whose prior evidence digest matches the receipt divided by all replay records\n- actionable-next-operation rate: AVAILABLE or DEFERRED observations with a bounded next operation divided by all non-UNKNOWN observations\n\nA metric is UNKNOWN when its denominator is zero or its source identities do not match.\n\n## Guardrails\n\n- never use cache presence as semantic evidence\n- never turn a passing fixture into a domain-completeness claim\n- never interpret AVAILABLE as permission to execute or authorize\n- never aggregate observations across declaration, catalog, or toolchain identity changes\n- never replace an UNKNOWN outcome with a guessed success\n- retain the earliest missing stage and the exact evidence needed to resolve it\n\n## Investment decision\n\nInvest in a new usage slice only when it adds a declaration-bound use case, a\nreplayable evidence boundary, and a falsifiable next operation. A higher score alone\nis not sufficient. A decision must record expected change, minimum new evidence,\nestimated cost, a falsifier, and a rollback condition.\n\nThe next implementation target is the smallest slice that can improve actionable-next-\noperation rate without lowering declaration binding, first-missing-stage localization,\nor replay continuity.\n
