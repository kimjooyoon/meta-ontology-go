# Self-Improvement Contract Compiler

This metaprogram compiles the Gooo self-improvement declaration through the
repository's canonical syntax and bidirectional semantic lowering pipeline.

It compares the resulting semantic model with the live generation registry.
No executor list or proof route is inferred from filenames outside that
registry.

The report separates eight indicators across foundation, coherence, and
regression routes. It binds the exact commit and Gooo source digest, requires
a valid semantic IR, verifies the closed loop and Munchhausen choice, checks
every registered executor, verifies the isolated read-only language
observation activity, and replays the projection deterministically.

The tool only observes and reports. It never authorizes promotion or edits
the source contract.

The current generation registry contains five declared operations and four
implemented execution routes. `split-gooo-sections` has no native consumer;
`bootstrap/source-repacker` moves Go declarations and cannot satisfy that Gooo
operation. The report therefore retains all five coverage rows, reports `4/5`,
and returns `FAIL / SELF_IMPROVEMENT_CONTRACT_OPEN`. The language loop itself
can be structurally closed while its executor coverage remains incomplete.
The contract CI and downstream consumers that require a complete contract remain
unsatisfied until this implementation gap is resolved; their acceptance rules
have not been lowered. Candidate planning can still select other implemented
operations while preserving this unresolved declaration.

`gooo package split-source` can propose a declaration-boundary partition for a
V4 package workspace, retaining byte origins and its updated source list. Its
explicit workspace apply path can install prepared changes and revalidate the
declared owners. Native APIs also inspect embedded consumers and predict syntax
registration changes. The repository-wide execution route still needs to connect
discovered consumers, native ABI checks, the whole write set and successor
projection. These separate capabilities therefore do not change the
five-operation denominator or the `4/5` result.
