# 시간 예산에 맞춰 작업 묶음 고르기

작업마다 예상 시간이 있고, 정해진 예산 안에서 입력 순서대로 처리한다고 가정한다.
이 예제는 처리할 작업 개수, 누적 시간, 끝까지 처리했는지, 멈춘 이유를 반환한다.
실제 작업 실행은 호출하는 프로그램이 담당한다.

`main.gooo`가 계산과 선택 범위를 함께 가진다. 반복문은 작업 목록을 읽고,
`source_fill`은 남은 예산과 **같은** 시간이 걸리는 작업도 허용할지 선택한다.
소스의 사례에 따라 `duration <= input.limit - spent`가 선택된다.
덧셈 전에 남은 예산과 비교해 int64 범위에서 합계를 유지한다.

| 입력 | 결과 |
| --- | --- |
| 예산 17, 작업 시간 `[8, 9, 3]` | 2개, 17 사용, `budget`으로 중단 |
| 예산 17, 작업 시간 `[9, 3, 8]` | 2개, 12 사용, `budget`으로 중단 |
| 음수 예산 | 0개, 0 사용, `invalid_limit` |
| 도중에 음수 작업 시간 | 앞서 고른 결과를 반환하고 `invalid_duration`으로 중단 |
| 모든 항목이 들어감 | `complete` 반환 |

## 실행

EntityFields V5와 `for … in`을 포함한 개발 소스의 CLI가 필요하다.
Go 툴체인은 1.27.2다. 저장소 루트에서 새 출력 폴더를 지정한다.

```sh
gooo body-compose --source examples/batch-planner/main.gooo \
  --cases examples/batch-planner/cases.json --out out/batch-planner
```

`original.gooo`에는 후보와 사례, `realized.gooo`에는 선택한 계산이 남는다.
`composition.json`에서 선택 내역을, `runtime.json`에서 입력별 결과와 조건식의
원본 위치를 읽을 수 있다. 모델 경로를 주지 않으면 결정론적으로 후보를 선택한다.

## 확인한 범위

선택용 3개와 별도 보류 1개 사례가 일치했다. 추가 네이티브 실행 4개도 일치했고,
입력 중복 검사에서 선택·보류 사례와 겹치지 않았다. 추가 실행은 위의 두 순서,
음수 예산, int64 최댓값까지 채우는 경우를 포함한다.

원본 조건식 3개가 연결됐고, 이 실행에서 조건 관찰 20개가 저장됐다.
목록은 최대 256개이며, 정적 기원 분석은 반복 원소를 합쳐 보는 범위를 유지한다.
