# 할당과 실행 순서를 함께 고르는 Gooo 예제

이 소스의 요구는 입력의 두 배를 반환하는 것이다. 계산 본문은 두 변수를 만들고,
곱셈 결과를 어디에 넣을지와 두 할당문의 순서를 선택지로 선언한다.
`IsDouble` 조건식은 원래 입력과 후보 결과를 비교한다.

선택지는 소스에 적힌 순서대로 mask의 비트에 대응한다.
첫 이름 `z_target`과 다음 이름 `a_schedule`은 이름순 정렬이 이 순서를 바꾸는지
드러내기 위해 골랐다.

| mask | 곱셈 결과를 `second`에 할당 | 두 할당문의 순서 교환 | 반환 계산 |
| --- | --- | --- | --- |
| 0 | 원래 대상 유지 | 원래 순서 유지 | 입력 + 3 |
| 1 | 적용 | 원래 순서 유지 | 입력 × 2 |
| 2 | 원래 대상 유지 | 적용 | 입력 + 3 |
| 3 | 적용 | 적용 | (입력 + 5) × 2 |

## 한 번 수행한 새 관찰

[소스](main.gooo.fixture)와 [관찰 기록](observation.json)을 함께 보관한다.
작은 합성 모델은 두 번째 옵션을 선호하도록 설정했으며 학습하지 않았다.
한 번의 예측으로 네 조합을 `[3, 1, 2, 0]` 순서로 제안했다.

- 첫 후보 mask 3: 선택 입력 -6과 7의 조건 **0/2**.
- 다음 후보 mask 1: 같은 선택 입력의 조건 **2/2**.
- 선택한 후보를 별도 입력 15로 평가: 조건 **1/1**.
- 사용한 시도 **2/2**, 모델 호출 **1회**, 구성 상태 `COMPLETE_FINITE`.

관찰의 생산자는 공개된 컴파일러 소스 `a94fe484359a60d5dcc518cbf1d21b47c5c550c6`과
새 테스트 파일 하나다. 기록에는 당시 파일·모듈·소스 해시가 들어 있다.
후속 문서나 코드 변경이 이전 관찰의 생산자를 바꾸지 않는다.
이 결과는 합성 순위와 실제 조건 평가의 연결을 확인하며, 학습 모델의 정확도나
전체 Integer 범위의 증명은 별도 평가가 필요하다. 생성된 Gooo 네이티브 프로그램은
실행하지 않았고, CPU 사용률과 전체 프로세스 메모리도 측정하지 않았다.

## 사용 방법

이 변경을 포함한 개발 소스에서 결정론적 경로를 사용한다.

```sh
go run ./cmd/gooo body-codegen --json --activity Double \
  examples/scalar-source-model-multichoice/main.gooo.fixture
```

호환하는 `gooo/scalar-criteria-model/v1` 아티팩트를 연결하려면
`--path-model /path/to/metadata.json`을 추가한다. 이 예제에는 모델 가중치를 포함하지 않는다.
상위 [모델 연결 안내](../../docs/scalar-source-model.ko.md)에서 입력 역할, 실제 조건 평가와
저장 결과의 재사용 범위를 설명한다.
