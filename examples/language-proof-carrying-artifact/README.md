# Proof-carrying artifact

This experiment makes the combination of a generated artifact and its
justification evidence a language-level object. The Gooo source declares the
operation that produces a `ProofCarryingArtifact`; the producer emits three
typed evidence records and carries a four-step verification recipe with them.

The artifact is deliberately not an authorization. It is emitted as
`decision=CARRIED`, with `authority.granted=false` and
`INDEPENDENT_CONSUMER_VERIFICATION_REQUIRED`. The consumer grants authority
only after independently reading the source bytes, rechecking the operation
receipt, checking the invariant, and matching the carried recipe to its own
canonical recipe. A byte-only invocation has no authority path.

## Evidence language

| kind | claim | proof choice | meta-operation | independently rechecked against |
| --- | --- | --- | --- | --- |
| `SOURCE` | source bytes are bound | `FOUNDATION` | `bind-source-bytes` | raw `.gooo` bytes and source digest |
| `OPERATION` | the operation receipt is bound | `COHERENCE` | `bind-operation-receipt` | receipt digest, entry projection, and event sequence |
| `INVARIANT` | generated bytes do not grant authority | `REGRESSION` | `preserve-no-byte-authority` | zero writes, no mutation authority, consumer-required flag |

The four recipe steps are `verify-source`, `verify-operation`,
`verify-invariant`, and `grant-authority`. The last step is a consumer action,
not a producer claim. Its preserved-claim transition is recorded as
`NOT_GRANTED -> GRANTED` only after the three evidence claims transition from
`CARRIED -> PRESERVED`.

## Research decisions

This experiment adopts the following principles from primary specifications and
research:

1. [Necula, *Proof-Carrying Code: Design and Implementation*](https://people.eecs.berkeley.edu/~necula/Papers/marktoberdorf.pdf)
   requires code to carry a precise explanation, while the receiver checks that
   the explanation is acceptable, addresses the receiver's policy, and matches
   the code. We adopt receiver-side matching and a small independent checker.
   We reject the stronger claim that these bounded JSON checks are a formal
   proof of all compiler or program semantics.
2. [SLSA Build Provenance](https://github.com/slsa-framework/slsa/blob/main/spec/build-provenance.md)
   models provenance as an attestation of how a subject was produced, requires
   externally controlled inputs to be verified downstream, and distinguishes
   the trusted builder from the signer. We adopt explicit producer, source,
   operation, and consumer identities plus downstream input rechecks. We do not
   claim SLSA compliance, signer authenticity, or a cryptographic signature:
   this receipt is read-only and unsigned.
3. [in-toto artifact rules and verification](https://in-toto.io/docs/getting-started/)
   chains named steps with materials, products, and verification rules. We
   adopt a fixed recipe whose named steps and inputs must match exactly. We
   reject open-ended or producer-selected rules: an unrecognized or weakened
   recipe cannot grant authority.

## Fixed cases and falsification

The contract has a fixed denominator of five cases and fourteen indicators:

| case | expected result |
| --- | --- |
| valid artifact | `PASS / EXACT`, consumer-only authorization |
| tampered evidence | `FAIL_CLOSED / INVARIANT_ONLY`, evidence digest mismatch |
| missing operation evidence | `FAIL_CLOSED / LOWER_RESOLUTION`, evidence missing |
| artifact bytes only | `FAIL_CLOSED / LOWER_RESOLUTION`, bytes are not authority |
| independent recipe mismatch | `FAIL_CLOSED / INVARIANT_ONLY`, recipe drift rejected |

The claim is falsified if a generated artifact has `authority.granted=true`, if
the consumer grants authority without all three external inputs, if a resealed
tampering case passes, if a missing evidence case is treated as exact, or if a
recipe different from the canonical consumer recipe grants authority. The
receipt also records `producer_dependencies=0`, `semantic_claims=0`, and
`repository_writes=0`; these are scope boundaries, not hidden success claims.
