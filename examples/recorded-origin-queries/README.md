# 선택한 규칙의 사용처 찾기

`Amount`는 기준과 보정량을 후보에서 고른다. 기준은 `passed`라는 변수를 거쳐
조건에 쓰이고, 보정량은 반환할 금액에 들어간다. 기준은 분기를 통해 반환값에도 영향을 준다.

개발 버전의 조회 명령과 범위는 [사용 안내](../../docs/language/recorded-origin-queries.ko.md)에 있다.

[계산 소스](amounts.gooo.fixture), [Gooo 설명 활동](explain.gooo.fixture),
[실제 출처와 소비 결과](query5581.json)를 함께 읽을 수 있다.
기준의 사용처는 조건과 반환식 두 곳이고, 보정량의 사용처는 반환식 한 곳이다.
여기에 기록된 두 문서 관점이 대응되는 경우 각각의 출처 위치를 유지한다.

반복 누적 사례는 `cli5801`에 있다. 선택한 11을 세 번 더해 입력 17과 -5에서
50과 28을 얻었다. 조회 결과는 반환식 `total`이 `total + 11`이라는 대입으로
이어지는 경로를 보여준다. 반복문 분석의 제한 때문에 상태는 `PARTIAL`로 남는다.
[읽기 쉬운 출력](query_text5801.txt)과 [JSON 출력](query_json5801.json)을 비교할 수 있다.

새 구성을 실행하는 명령행 전체는 약 1.29초였다. 저장 기록을 읽는 JSON·텍스트 조회는
각각 약 9.8ms·8.7ms였다. 한 번씩 관찰한 값이며 처리량 비교는 하지 않았다.
조회에는 본문·후보·모델 실행이 없었고 임시 실행 파일은 제거했다.

## 원본 관찰을 보존하는 방법

로컬 관찰의 실제 생산자는 `c7483747864e2f6a8899a583f2ec3f4f85b0a96b`와
각 `producer*.json`의 변경 파일 조합이다. 이후 공개 커밋의 실행 결과로 표기를 바꾸지 않는다.
최종 구현과 달라진 초기 조회 함수는 `snapshots/`에 당시 내용으로 남겼다.
`5581` 묶음의 도움말 실패를 포함한 로그를 유지했고, 도움말을 수정한 뒤에는 새 `5791` 사례와
새 반복 누적 프로그램 `5801`을 사용했다. 이전 프로그램·모델·테스트 묶음을 로컬에서 재실행하지 않았다.

선행 PR #1534의 원래 CI에서 발견한 형식 차이와 미등록 예제도 함께 수정한다.
Go 1.27.2의 포맷터로 두 반복문을 정리하고 `eligibility.gooo`를 구문 검사 목록에 추가했다.
기존 81개 검사는 그대로 두고 새 언어 사례 하나를 더 요구한다. 원래 CI 관찰의
81/81과 미등록 1개라는 결과는 당시 기록으로 유지한다.

반환식만 있는 본문의 최초 파일 연결, 다른 activity로 전달되는 값의 기원,
출처를 이용한 모델 요청의 설명은 이어서 확장할 범위다.
