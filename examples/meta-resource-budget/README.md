# Meta resource budget experiment

This CI-only experiment connects resource observations to a meta claim over the
two real `.gooo` sources in this directory. It measures three operations three
times each:

| operation | stage / step | output |
| --- | --- | --- |
| `source-check` | `LOWER / parse-source` | receipt |
| `project-manifest` | `PROJECT / project-operation-manifest` | generated artifact |
| `replay-manifest` | `REPLAY / replay-generated-artifact` | generated artifact |

Each observation carries the subject SHA, operation ID, stage, step,
meta-operation, proof choice, wall time, peak RSS, receipt bytes, generated
bytes, reason, source raw digest, source semantic digest, and source-derived
target digest. The source raw digest includes the sorted source filenames and
bytes. The semantic digest is reconstructed by the independent consumer with
`syntax.ParseFile` followed by `bidir.Lower`; the activity, input bindings,
output binding, and target digest are derived from that reconstruction rather
than copied from the contract.

The fixed denominator is exactly 19 applicable coordinates:

* 9 resource coordinates: wall time and peak RSS for all three operations,
  receipt bytes for `source-check`, and generated bytes for
  `project-manifest` and `replay-manifest`.
* 10 semantic/effect/binding/sample coordinates: source file set, Go-file
  boundary, source digest, source receipt, artifact replay, artifact digest,
  structured effects, producer binding, fixed sample set, and claim chain.

The three receipt/generated axes that do not apply to an operation are
`NOT_APPLICABLE`; they are neither satisfied nor included in the denominator.
Thus the formula is `3×2 + 1 + 2 + 10 = 19`, not `3×4 + 10`.
Indicators distinguish `SATISFIED`, `REFUTED`, `UNKNOWN`, and
`NOT_APPLICABLE`. Missing or invalid evidence lowers only the affected
operation/coordinate resolution. For example, deleting the third
`replay-manifest` resource observation leaves source-check and project
resource indicators satisfied while replay's applicable resource coordinates
become unknown.

The normal nine observations and three raw operation payloads are
`CURRENT_EVIDENCE`. Every repeated observation is checked against its
operation's raw payload, and all three repeated payload digests must agree.
The over-budget and missing-sample cases are jq-derived
`SYNTHETIC_COUNTEREXAMPLE` inputs and are reported separately; they are not
counted as current runner measurements. A complete budget violation is an
exact refutation of the resource envelope, while missing or invalid samples
remain `OPEN` at `LOWER_RESOLUTION`. Missing semantic payloads are also open;
known malformed or contradictory semantic evidence is `REFUTED`.

The read-only/effect claim is deliberately narrow. CI captures a structured
before and after repository status and tree snapshot around each operation's
three-sample window, plus `git diff --exit-code`, changed paths, and an
authority observation. A discharged claim therefore says only
`NET_REPOSITORY_STATE_UNCHANGED` for each measured window. It does not prove
that a process never wrote and then reverted a file during the window; such a
transient-write claim is not made. Any observed write-set or mutation
authority violation is `REFUTED`; an absent or malformed snapshot is `OPEN`.

The independent consumer is a separate package and binary and imports neither
the reducer nor producer implementation. CI records a raw import-scan artifact
and the consumer recomputes its numerator and denominator from that artifact;
the report does not hard-code an independence fraction. It also validates the
input schema, canonical measurement contract, contract digest, expected head,
and runner identity before consuming raw evidence.

CI reruns the full 3×3 measurement for two interventions. Renaming
`PayOrder` to `RefundOrder` changes the source semantic digest, target digest,
operation artifact, and semantic claim evidence. Adding only a comment changes
the raw source digest while preserving the semantic digest, derived operation,
and operation decision. Resource numbers are runner observations and are not
required to be identical across interventions; sample cardinality and
runner-scoped resolution are the comparison boundary.

The envelope is intentionally runner-scoped:

| resource | limit |
| --- | ---: |
| wall time | 2,000 ms |
| peak RSS | 131,072 KiB |
| receipt bytes | 8,192 bytes |
| generated bytes | 16,384 bytes |

The [GitHub-hosted runner reference](https://docs.github.com/en/actions/reference/runners/github-hosted-runners) documents the VM and hardware boundary. [Bazel's hermeticity guidance](https://bazel.build/basics/hermeticity) explains why declared inputs and tools matter for reproducibility. This experiment adopts that separation of environment from input identity, but does not claim hermeticity: it uses a hosted runner, `/usr/bin/time`, the runner kernel, and the mutable `ubuntu-latest` image. It also does not claim cross-run performance improvement, machine-independent resource bounds, business correctness, production readiness, or repository mutation authority.
