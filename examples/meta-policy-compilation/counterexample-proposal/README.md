# Derive a policy proposal from a counterexample

This experimental host adapter reuses the existing Gooo policy compiler and
AST-based revision primitive. It does not introduce another operation registry,
policy evaluator, adoption authority, or completeness score.

## User path

Supply an original Gooo policy and a counterexample record:

~~~sh
go run ./examples/meta-policy-compilation/counterexample-proposal \
  -policy /caller/input/policy.gooo \
  -counterexample /caller/input/counterexample.json \
  > /caller/output/proposal.json
~~~

The input object has three fields:

- `expected_source_digest`: the pinned original source-byte digest.
- `case`: the existing policy Case, including its validator expectation,
  evidence class, provenance, and original observation identities.
- `observed`: the original DecisionResult for that exact case.

No separate condition, from-decision, or to-decision is supplied. The adapter
derives these three request fields from the observed matched condition, observed
decision, and declared validator expectation. It checks the source rule and
reconstructs the original result before returning the generated candidate.

The example writes its report to stdout only. Redirection is controlled by the
caller. It does not replace the input source or create an adoption decision.

## What the result means

`PROPOSED` means a source-bound candidate was generated for the supplied
counterexample. It does not authenticate the caller's observation or oracle,
execute the candidate, demonstrate user utility, or prove an improvement.

Missing evidence and unresolved original UNKNOWN remain UNKNOWN with stage,
step, reason, unknown_class, next_operation, and blocked_by. Stale observations
require fresh original evidence. Unsupported decisions, including FIXED_POINT,
and contradictions with the source cannot produce a candidate.

`NOT_PROPOSED / NO_DECISION_DIFFERENCE_DECLARED` means only that the caller
declared no decision difference. It is not a successful fixed point.

The report retains the original counterexample and its canonical digest, the
raw input artifact digest, the derived revision request, and both source-bound
policy contracts. Candidate source is generated by the existing Gooo AST
revision primitive. No observation digest or validator expectation is repaired.

The original evidence becomes stale when used unchanged with a different
candidate source. Use the existing `-observe-revision` witness with separately
supplied candidate evidence for the next execution step. Independent validation
and adoption remain outside this proposal capability. The established
compilation and revision-generation output profiles are unchanged.

## CI boundary

Existing policy package tests exercise an actual generated original judge,
derive the proposal, replay proposal generation, and demonstrate rejection of
the original snapshot by the changed candidate judge. A separate native test
builds this example once and executes it twice using caller-owned temporary
inputs. These are synthetic conformance cases, not independent utility evidence.
No new CI workflow or local test execution is required by this example.
