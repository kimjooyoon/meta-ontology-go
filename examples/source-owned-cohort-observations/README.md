# 원문이 선언한 예상 대상과 관측 데이터

`main.gooo`는 `Alpha`, `Beta`, `Gamma`를 호출해 예상 대상 세 개를 정한다.
`Assess`는 이 선언을 유지하면서 전달받은 관측 목록을 비교한다. 관측에 들어간
새 문자열은 데이터로 남으며, 같은 이름의 활동 구현을 만드는 요청으로 해석하지 않는다.

예상 대상마다 관측이 정확히 하나일 때 결합 수에 포함한다. 중복 관측과 예상 목록
밖의 관측은 미해결 수에 포함한다. 결과에는 전달받은 관측 ID 전체를 보존한다.
비율과 상태의 계산은 Gooo 본문에 있다.

| 관측 목록 | 예상 수 | 결합 수 | 미해결 수 | 비율 | 상태 |
| --- | ---: | ---: | ---: | ---: | --- |
| alpha, beta, gamma | 3 | 3 | 0 | 10000 | VERIFIED |
| alpha, beta, gamma, outside | 3 | 3 | 1 | 10000 | FAIL_CLOSED |
| alpha, beta | 3 | 2 | 0 | 6666 | FAIL_CLOSED |
| alpha, beta, outside | 3 | 2 | 1 | 6666 | FAIL_CLOSED |
| alpha, alpha, beta, gamma | 3 | 2 | 1 | 6666 | FAIL_CLOSED |
| 빈 목록 | 3 | 0 | 0 | 0 | FAIL_CLOSED |

표는 새 검사를 작성하기 위한 독립 기대값이다. 작성일(2026-10-17)에는 새 소스의
원래 CI 실행 결과가 아직 없다.
활동 ID의 전체 값은 소스의 `urn:cohort:*`이며, `outside`는 관측 데이터다.
예상 선언의 `Gamma(seed)`를 구현되지 않은 함수 호출로 바꾸면 별도의 소스 오류가 된다.

`AssessDeclared`는 같은 판정을 임의의 명시적 예상 목록에 적용한다. 기존 지표의
관측 생산자는 실행할 전략을 바꾸지 않고, 원문 레지스트리와 프로그램에서 복원한
예상 목록을 이 활동에 전달한다. 정상 경로의 기존 영수증은 그대로 보존한다.
새 관측 영수증은 그 영수증, 관측 원본 바이트, 이 Gooo 원문과 투영의 해시를 연결한다.
수신자는 기존 전략·프로그램을 독립 재구성한 뒤 원문의 판정을 다시 계산한다.

Gooo 판정은 기존 `gooo.metric.meta.concept-operation-binding-bps.v1`의 관측 값을
계산한다. `readiness_credit`는 항상 false다. 이 함수가 직접 준비도나 변경 권한을
부여하지 않으며, 준비도 반영은 기존 수신자의 검증을 거친다. 누락·중복·알 수 없는
관측이 있으면 해당 준비도 항목을 충족하지 않는다. 원본 프로그램이 이미 미해결이면 관측을 추가해도
새 경로로 승격할 수 없다.

새 원래 CI와 네이티브 결과를 확인한 뒤 이 연결의 수용 여부를 판단한다. 입력의 원본
바이트를 보존하는 것은 외부 관측 자체의 사실성을 인증하는 것과 구분한다.
