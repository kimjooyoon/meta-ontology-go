# 한 목록으로 세 가지 등록 조각 만들기

브랜치의 변경 범위를 JSON, Go, Markdown에 각각 적다 보면 같은 파일 목록을
세 번 수정하게 된다. 이 예제는 Gooo가 한 입력을 받아 세 표현으로 옮긴다.
에이전트는 입력 목록과 출력 조각을 검토하고, 각 파일의 해당 위치에 적용할 수 있다.

## 실행

이 폴더의 세 파일(`main.gooo`, `gooo.workspace.json`, `inputs.json`)을 함께 두고 실행한다.
Gooo CLI와 Go 1.27.2가 필요하다. 모델 호출은 0회다.

```sh
gooo package execute --json --inputs inputs.json gooo.workspace.json > execution.json
```

입력은 `meta/scopefragments:Project` 아래에 `branch`와 `paths`를 둔다.
제공된 예제에는 두 파일이 들어 있다. 결과는
`result.runtime.traces[0].deliveries[0].actual`에서 읽는다.

| 필드 | 결과 |
| --- | --- |
| `status` | `PROPOSAL` 또는 `OUTSIDE_PROFILE` |
| `governance` | `branch`와 `paths`를 가진 JSON 객체 |
| `golang` | `branchScopeAllowlist`의 한 항목을 대입하는 Go 문장 |
| `markdown` | 브랜치와 경로 목록을 담은 표의 두 셀 |

입력이 범위를 벗어나면 세 조각을 모두 빈 문자열로 돌려준다. 프로그램은 파일을
읽거나 쓰지 않는다. 기존 항목과의 중복, 실제 파일 존재 여부, Git 브랜치 규칙,
파일에 삽입할 위치와 반영 권한은 호출자가 다룬다.

## 원문이 정하는 범위

- 브랜치는 `agent/` 뒤에 이름이 있어야 한다.
- 경로는 1~256개이며, 사전순으로 정렬하고 중복을 제거해 전달한다.
- 브랜치와 각 경로는 1~256 UTF-8 바이트다. 허용 문자는 ASCII 영문자·숫자와
  `.`, `_`, `-`, `/`다. 빈 경로 요소, `.` 또는 `..` 요소는 거부한다.
- 입력 레코드의 기본 Text 한계와 전체 실행·전송 예산도 그대로 적용된다.

출력에는 기존 `max_utf8_bytes` 선언을 사용한다. 브랜치 길이 `B`, 경로 개수 `N`,
경로 최대 길이 `P`에 `B=P=N=256`을 대입해 아래 상한을 얻는다.

| 출력 | 바이트 상한 계산 | 원문의 선언 |
| --- | --- | ---: |
| JSON | `24 + B + N*(P+2) + (N-1)` | 66,583 |
| Go | `38 + B + N*(P+5)` | 67,110 |
| Markdown | `9 + B + N*(P+2) + 2*(N-1)` | 66,823 |

ASCII 범위를 사용하므로 이 세 표현에서 경로의 추가 이스케이프 길이가 생기지 않는다.
새 출력 크기는 원문에 고정되어 있고, 실행 입력이 이를 바꾸지 않는다.

## 확인한 범위

- Go의 JSON 인코더와 Go 구문 분석기를 사용하는 독립 기대값으로 15개 사례를 비교한다.
  보통 입력, 최대 크기 입력과 13개 거부 사례를 포함한다.
- 개발 컴파일러 `98fadef7f2c3f5b9f6eecd88dd5085674f116d9f`로 실제 109개 파일의
  기존 등록 행을 실행했다. JSON 값, Go 파일의 서식 적용 후 바이트, Markdown 셀이
  원래 저장소 내용과 일치했다.
- 256개 경로가 각각 256바이트인 입력도 실제 실행과 재생을 완료했다.
  세 출력의 길이가 위 선언과 각각 정확히 일치했다.

실행은 `--inputs`로 관측했다. 실행기의 기대값 비교 분모는 0이며 `OBSERVED`를 반환한다.
위 비교는 저장된 실제 출력을 별도 기대값과 대조한 결과다. 이 사례는 기존 문법을
조합하는 응용 프로그램이며, 언어의 새로운 문법 하나를 추가했다는 뜻은 아니다.

첫 초안은 세 출력에 1,024바이트를 고정해 큰 등록 행을 거부했다. 이미 구현된
[Text 필드 범위](../../docs/language/text-field-bounds.ko.md)를 적용해 해결했다.
목록 원소를 선언된 활동으로 변환하는 실험은
[목록 변환 예제](../collection-map/README.md)에서 이어진다. 입력과 출력 원소의
순서·타입·길이, 각 원소를 만든 활동과 읽은 입력의 기원을 함께 기록한다.

기존 CI의 소스 검사와 언어 사례 등록 경로를 사용한다. 이 예제를 사용하는 프로젝트는
위 실행 명령만으로 출력을 받을 수 있다.

이 변경의 등록 목록도 같은 Gooo 프로그램으로 실행해 세 조각을 얻었다.
호출자가 JSON 항목을 삽입하고 Go의 `init` 함수로 감싸 서식을 적용했으며,
문서 행에 변경 목적을 덧붙였다. 출력과 입력 목록을 비교한 뒤 반영한 작업이다.
